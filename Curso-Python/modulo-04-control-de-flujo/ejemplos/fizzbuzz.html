fizzbuzz.py — El clásico FizzBuzz

El ejercicio más famoso de programadores: del 1 al 100, imprimir "Fizz" si es múltiplo de 3, "Buzz" si es de 5, "FizzBuzz" si de ambos, y el número en caso contrario.

Cómo ejecutar

python fizzbuzz.py

Código fuente

⬇ Descargar .py 
"""FizzBuzz clásico — ejercicio de control de flujo."""


def fizzbuzz(n: int) -> str:
    if n % 15 == 0:
        return "FizzBuzz"
    if n % 3 == 0:
        return "Fizz"
    if n % 5 == 0:
        return "Buzz"
    return str(n)


if __name__ == "__main__":
    for i in range(1, 101):
        print(fizzbuzz(i))

Conceptos clave

  • Función pura: fizzbuzz(n) siempre devuelve lo mismo para la misma entrada — sin side effects.
  • Type hints: n: int y -> str documentan tipos esperados.
  • Early return: cada caso retorna inmediatamente; sin else.
  • Orden importa: % 15 primero porque "FizzBuzz" es más restrictivo. Si lo pusieras último, nunca se imprimiría (los múltiplos de 15 ya disparan el de 3).
  • if __name__ == "__main__": el bloque solo se ejecuta cuando se corre el archivo directamente, no al importarlo.

Por qué este ejercicio es famoso

Jeff Atwood publicó en 2007 que un alto porcentaje de candidatos a programador no podían resolver FizzBuzz en una entrevista. Desde entonces se volvió el filtro mínimo de cualquier proceso de selección técnica. Es trivial si entendés modular y condicionales, pero entrena el músculo de "leer el enunciado y traducirlo a código limpio".

Variaciones para practicar

  1. Imprimir con comprehension de una línea: [print(fizzbuzz(i)) for i in range(1, 101)].
  2. Hacer una versión con match/case (Python 3.10+).
  3. Generalizarlo: fizzbuzz(n, rules={3: "Fizz", 5: "Buzz", 7: "Bazz"}).
  4. Devolver lista en vez de imprimir; testearla con assert fizzbuzz(15) == "FizzBuzz".
  5. Comparar performance entre la versión con % y una basada en strings/loops.
