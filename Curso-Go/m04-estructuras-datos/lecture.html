Módulo 04 — Estructuras de Datos

Hasta acá manejaste valores sueltos: un int, un string, un bool. Pero el software real trabaja con colecciones: una lista de usuarios, un diccionario de precios, una ficha con varios campos. Go te da cuatro herramientas para esto, y entender la diferencia entre ellas (sobre todo array vs slice) es lo que separa al que copia código del que lo entiende. En este módulo dominás arrays, slices (la estrella), maps y structs.

Arrays: tamaño fijo, parte del tipo

Un array tiene una longitud fija que forma parte de su tipo. Un [3]int y un [4]int son tipos distintos: no podés asignar uno al otro.

var notas [3]int        // array de 3 enteros, todos en cero
notas[0] = 10
notas[1] = 7
fmt.Println(notas)      // [10 7 0]
fmt.Println(len(notas)) // 3 (la longitud es fija para siempre)

primos := [4]int{2, 3, 5, 7}  // declarar e inicializar de una
En la práctica vas a usar arrays directamente muy poco. Su tamaño rígido los hace incómodos: casi nunca sabés de antemano cuántos elementos vas a tener. Para eso existen los slices, que son lo que de verdad vas a usar el 95% del tiempo. El array sigue ahí debajo, pero raramente lo tocás a mano.

Slices: la estrella del módulo

💡 Un slice es una vista dinámica sobre un array. No guarda los datos: guarda un puntero al array subyacente, una longitud (len, cuántos elementos ves) y una capacidad (cap, cuántos entran antes de tener que agrandar). Vos lo tratás como una lista que crece sola; Go maneja el array de abajo.

Se crea con make o con un literal, y crece con append:

s := make([]int, 0)   // slice de int, longitud 0
s = append(s, 10)     // [10]
s = append(s, 20, 30) // [10 20 30] — append devuelve el slice nuevo
fmt.Println(s, len(s)) // [10 20 30] 3

// también con literal:
colores := []string{"rojo", "verde", "azul"}
📌 Siempre reasigná el resultado de append: s = append(s, x). Cuando el slice se queda sin capacidad, append crea un array más grande y devuelve un slice nuevo que apunta a él. Si escribís append(s, x) sin el s =, perdés el resultado.

Slicing: cortar un pedazo

Con s[inicio:fin] obtenés una sub-vista. El índice inicio se incluye; fin NO se incluye (igual que en Python):

nums := []int{0, 10, 20, 30, 40}
fmt.Println(nums[1:3])  // [10 20]  (índices 1 y 2; el 3 queda afuera)
fmt.Println(nums[:2])   // [0 10]   (desde el principio)
fmt.Println(nums[2:])   // [20 30 40] (hasta el final)
⚠️ Cuidado: el slicing comparte memoria. nums[1:3] NO copia los datos: es otra ventana sobre el mismo array. Si modificás un elemento a través de la sub-vista, también cambia en el slice original. Dos slices pueden apuntar al mismo array subyacente sin que se note.
base := []int{1, 2, 3, 4}
vista := base[0:2]   // [1 2] — comparte memoria con base
vista[0] = 99
fmt.Println(base)    // [99 2 3 4]  ← ¡también cambió base!

Maps: pares clave → valor

Un map es un diccionario: asocia claves con valores. Se crea con make y se escribe/lee con corchetes:

edades := make(map[string]int)  // claves string, valores int
edades["ana"] = 30
edades["luis"] = 25
fmt.Println(edades["ana"])  // 30
delete(edades, "luis")      // borra la clave "luis"

El idiom comma-ok: ¿la clave existe?

💡 Leer una clave que NO existe NO da error: devuelve el zero value del tipo del valor (0 para int, "" para string, false para bool). Por eso, para saber si una clave realmente está, usás la forma de dos valores: v, ok := m[clave]. El segundo valor (ok) es un bool que dice si la clave existía.
edades := map[string]int{"ana": 30}

v, ok := edades["ana"]
fmt.Println(v, ok)  // 30 true   → existe

v, ok = edades["pepe"]
fmt.Println(v, ok)  // 0 false   → NO existe (0 es el zero value, no un dato real)
⚠️ El error clásico: hacer if edades["pepe"] == 0 y creer que detectás "no existe". ¡No! Una persona con edad 0 daría lo mismo que una clave ausente. Para distinguir "está y vale 0" de "no está", siempre usá v, ok := m[clave].

Structs: agrupar campos con nombre

Un struct es un tipo que junta varios campos relacionados bajo un solo nombre. Es como modelar una "ficha":

type Persona struct {
    Nombre string
    Edad   int
}

p := Persona{Nombre: "Ana", Edad: 30}  // instanciar con campos nombrados
fmt.Println(p.Nombre)  // Ana
p.Edad = 31            // acceder y modificar un campo con punto
fmt.Println(p)         // {Ana 31}

Los structs pueden anidarse (un struct dentro de otro) y también existen los anónimos (sin declarar un tipo con nombre, útil para algo de un solo uso):

type Direccion struct {
    Ciudad string
    Pais   string
}
type Empleado struct {
    Nombre string
    Dir    Direccion   // struct anidado
}
e := Empleado{Nombre: "Luis", Dir: Direccion{Ciudad: "Córdoba", Pais: "AR"}}
fmt.Println(e.Dir.Ciudad)  // Córdoba

// struct anónimo (un solo uso, sin nombre de tipo):
config := struct {
    Debug bool
    Port  int
}{Debug: true, Port: 8080}
fmt.Println(config.Port)  // 8080

Los tres errores que más cuestan al empezar

Confundir array (fijo) con slice (dinámico). [3]int tiene siempre 3 elementos y no le podés hacer append útilmente. []int crece solo. Si dudás, casi siempre querés un slice.
Leer una clave de map inexistente y creer que "falló". Devuelve el zero value, no un error. Usá v, ok := m[clave] para saber de verdad si está.
Olvidar que dos slices pueden compartir memoria. Un s[1:3] o un slice copiado por asignación apunta al mismo array de abajo: modificás uno y mutás el otro. Si necesitás una copia real, usá copy(destino, origen).

Checkpoint — ¿lo tenés claro?

¿Cuál es la diferencia esencial entre un array y un slice?

El array tiene tamaño fijo que forma parte de su tipo ([3]int ≠ [4]int). El slice es una vista dinámica sobre un array: crece con append y guarda puntero + len + cap. En la práctica casi siempre usás slices.

¿Qué devuelve leer una clave que no existe en un map, y cómo detectás si la clave estaba?

Devuelve el zero value del tipo del valor (0, "", false…), NO un error. Para saber si la clave existía usás el idiom comma-ok: v, ok := m[clave], donde ok es true si la clave estaba.

¿Por qué vista := base[0:2]; vista[0] = 99 también cambia base?

Porque el slicing no copia los datos: vista es otra ventana sobre el mismo array subyacente que base. Modificar un elemento por una vista lo modifica en todas las que comparten ese array. Para una copia independiente usás copy.

Ejercicios

  1. Creá un slice vacío con make([]string, 0) y agregale 3 nombres con append. Imprimí el slice y su len.
  2. Partiendo de nums := []int{0, 10, 20, 30, 40}, imprimí nums[1:4], nums[:2] y nums[3:]. Predecí el resultado antes de correrlo.
  3. Creá un map[string]int de stock de productos. Usá el idiom comma-ok para imprimir "hay N" si una clave existe o "no tenemos ese producto" si no.
  4. Demostrá la memoria compartida: creá un slice base, sacá una vista := base[0:2], modificá vista[0] y mostrá que base también cambió.
  5. Definí un struct Persona con Nombre y Edad, creá un slice []Persona con 3 personas y recorrelo con for ... range imprimiendo cada nombre.

🧠 Autoevaluación

1. ¿Qué hace s = append(s, 5) en un slice?

append agrega elementos y devuelve el slice resultante; si no hay capacidad, crea un array más grande. Por eso siempre se reasigna: s = append(s, ...).

2. Tenés m := map[string]int{} y leés v := m["x"] con "x" inexistente. ¿Qué pasa?

Leer una clave ausente devuelve el zero value, NO un error. Para distinguir "no está" de "está y vale 0" se usa el idiom comma-ok: v, ok := m["x"].

3. base := []int{1,2,3}; v := base[0:2]; v[0] = 99. ¿Cuánto vale base después?

El slicing no copia: v es otra vista sobre el mismo array que base. Modificar v[0] también cambia base. Para una copia real se usa copy.
