Módulo 01 — Sintaxis & Tipos

En M00 corriste tu primer binario. Ahora vamos al corazón del lenguaje: cómo se declaran variables, qué tipos básicos existen, y la regla que más choca viniendo de Python o JavaScript — Go no convierte tipos por vos. Lo que en otros lenguajes pasa silencioso, acá te lo exige explícito. Esa "rigidez" es justamente lo que hace al código Go tan predecible.

Tres formas de declarar variables

Go te da tres maneras de crear una variable, y conviene conocer las tres porque vas a verlas en código real:

var x int = 5   // explícita: nombre, tipo y valor
var y = 5       // inferida: Go deduce que y es int por el valor
z := 5          // short: la más común DENTRO de funciones
💡 El operador := declara y asigna en un solo paso, infiriendo el tipo. Es la forma idiomática dentro de funciones. Pero ojo: := solo funciona dentro de una función. A nivel de paquete (fuera de toda función) tenés que usar var.

Podés declarar y asignar varias variables a la vez. Esto se usa muchísimo, sobre todo cuando una función devuelve dos valores:

a, b := 1, 2          // a=1, b=2
nombre, edad := "Ana", 30  // tipos distintos, sin problema
a, b = b, a           // swap clásico: ahora a=2, b=1 (sin variable temporal)
📌 Regla: var sirve en cualquier lado (paquete o función). := solo dentro de funciones. Si estás declarando una variable global del paquete, no te queda otra que var.

Zero values: nada queda "indefinido"

Esta es una de las decisiones de diseño más elegantes de Go. En JavaScript una variable sin asignar es undefined; en Go toda variable tiene un valor por defecto garantizado según su tipo. Nunca trabajás con basura de memoria.

TipoZero value
números (int, float64, byte...)0
string"" (cadena vacía)
boolfalse
punteros, slices, maps, funciones, interfacesnil
 
var contador int      // vale 0, no "undefined"
var activo bool       // vale false
var msg string        // vale "" (no nil — un string nunca es nil)
Que no haya undefined elimina toda una clase de bugs. En Go nunca te preguntás "¿esta variable está inicializada?": si la declaraste, tiene un valor usable desde el primer instante.

Estos son los tipos que vas a usar el 90% del tiempo:

💡 byte y rune son alias, no tipos nuevos. byte es exactamente uint8 y representa un byte crudo. rune es exactamente int32 y representa un punto de código Unicode — es decir, un carácter completo, aunque ocupe varios bytes. Por eso una ñ es una sola rune pero dos byte.

Constantes y iota

Una constante se declara con const y su valor se fija en tiempo de compilación — no se puede cambiar después:

const Pi = 3.14159
const MaxUsuarios int = 100

Cuando necesitás una serie de constantes relacionadas (un "enumerado"), Go te da iota: un contador que arranca en 0 y se incrementa automáticamente en cada línea del bloque const.

const (
    Lunes = iota   // 0
    Martes         // 1
    Miercoles      // 2
    Jueves         // 3
    Viernes        // 4
)

// Útil para flags o estados:
const (
    Pendiente = iota  // 0
    Activo            // 1
    Cerrado           // 2
)
No hace falta repetir = iota en cada línea: una vez que lo escribís en la primera, Go aplica el mismo patrón a las siguientes. iota se reinicia a 0 en cada nuevo bloque const (...).

Conversión de tipos: SIEMPRE explícita

Acá está la regla que más sorprende. En Python 1 + 2.5 funciona; en JavaScript también. En Go, no podés mezclar tipos numéricos distintos sin convertir a mano. No hay conversión implícita.

var i int = 10
var f float64 = 3.5

// suma := i + f   // ❌ ERROR de compilación: mismatched types int and float64

suma := float64(i) + f   // ✅ convertís i a float64 explícitamente → 13.5
entero := int(f)         // ✅ convertís f a int (trunca, no redondea) → 3
Pensalo como aduana: cada tipo es un país con su moneda. Para pasar un int al "país" float64 tenés que cambiar la moneda explícitamente con float64(i). Go no te deja cruzar la frontera con la moneda equivocada "asumiendo" el cambio — te obliga a declararlo, así nunca hay una conversión silenciosa que pierda precisión sin que te enteres.
📌 Sintaxis: la conversión se escribe tipoDestino(valor): int(f), float64(i), string(r), byte(n). Convertir float64 a int trunca (descarta los decimales), no redondea.

Strings: inmutables y UTF-8

En Go un string es una secuencia inmutable de bytes codificada en UTF-8. "Inmutable" significa que no podés cambiar un carácter en el lugar: para "modificar" un string creás uno nuevo.

s := "café"
fmt.Println(len(s))   // 5, NO 4 — len cuenta BYTES, y la 'é' ocupa 2

// s[0] = 'C'   // ❌ ERROR: los strings son inmutables
💡 len(s) cuenta bytes, no caracteres. Como Go usa UTF-8, los caracteres ASCII (a–z, 0–9) ocupan 1 byte, pero acentos y emojis ocupan 2 a 4. La é de "café" son 2 bytes, así que len("café") da 5. Para contar caracteres reales (runes) se usan otras herramientas que verás más adelante.

Errores típicos al empezar

Esperar conversión implícita. int + float64 no compila. Go exige float64(i) + f. Esto no es un capricho: te protege de perder precisión sin darte cuenta.
Usar := fuera de una función. A nivel de paquete := es error de sintaxis. Para una variable global usá var nombre = valor.
Dejar una variable sin usar. Igual que un import sin usar, una variable declarada y nunca leída es un error de compilación, no un warning. El programa no compila hasta que la uses (o la borres).

Ejemplo completo

Este programa junta todo: las tres formas de declarar, una constante con iota y una conversión explícita.

package main

import "fmt"

// A nivel de paquete: var (NO :=)
var version = "1.0"

const (
    Bronce = iota  // 0
    Plata          // 1
    Oro            // 2
)

func main() {
    // 1) explícita
    var edad int = 30
    // 2) inferida
    var nombre = "Ana"
    // 3) short (solo dentro de funciones)
    activo := true

    // asignación múltiple
    ancho, alto := 1920, 1080

    // conversión EXPLÍCITA: int → float64 para poder dividir con decimales
    ratio := float64(ancho) / float64(alto)

    fmt.Println("versión:", version)
    fmt.Println(nombre, edad, activo)
    fmt.Println("nivel Oro =", Oro)        // 2
    fmt.Printf("ratio = %.3f\n", ratio)    // 1.778
}

Checkpoint — ¿lo tenés claro?

¿Por qué len("café") devuelve 5 y no 4?

Porque len cuenta bytes, no caracteres, y los strings de Go son UTF-8. La é ocupa 2 bytes, así que c+a+f (1 byte cada uno) + é (2 bytes) = 5 bytes.

Tenés var i int = 10 y var f float64 = 2.0. ¿Por qué i + f no compila y cómo lo arreglás?

Go no convierte tipos implícitamente: int y float64 son tipos distintos y no se pueden sumar directamente. Lo arreglás convirtiendo a mano: float64(i) + f (o i + int(f) si querés el resultado en int).

¿Cuál es el zero value de un bool, un string y un int? ¿Y por qué importa?

bool → false, string → "", int → 0. Importa porque significa que en Go no existe undefined: toda variable declarada arranca con un valor válido y usable, eliminando bugs de "variable sin inicializar".

Ejercicios

  1. Declará la misma variable de las tres formas (var x int = 5, var y = 5, z := 5) e imprimí las tres. Después intentá poner := fuera de main() y mirá el error.
  2. Declará un int y un float64 sin asignarles valor e imprimílos. Confirmá que muestran sus zero values (0 y 0) sin error.
  3. Creá un bloque const con iota para los días de la semana (Lunes=0 … Domingo=6) e imprimí el valor de Miercoles.
  4. Tomá un int y un float64, sumálos (vas a tener que convertir uno) e imprimí el resultado. Después convertí un float64 como 9.99 a int y observá que trunca a 9.
  5. Asigná "piñón" a un string e imprimí su len. Explicá por qué el número no coincide con la cantidad de caracteres que ves.

🧠 Autoevaluación

1. ¿Dónde se puede usar el operador :=?

:= (short declaration) solo es válido dentro de funciones. A nivel de paquete tenés que declarar con var.

2. Tenés var i int = 3 y var f float64 = 1.5. ¿Qué pasa con i + f?

Go exige conversión explícita. i + f es un error de tipos; tenés que escribir float64(i) + f (o i + int(f)).

3. ¿Cuál es el zero value de un string en Go?

El zero value de un string es la cadena vacía "", nunca nil ni undefined. En Go toda variable declarada arranca con un valor válido.
