Módulo 00 — Introducción & Setup

Go (o "Golang") es un lenguaje creado en Google en 2009 por Rob Pike, Ken Thompson y Robert Griesemer — tres leyendas de la informática. Su objetivo: hacer software de servidor simple, rápido y concurrente, sin la complejidad que acumularon C++ y Java. En este módulo entendés por qué importa y dejás listo tu primer programa.

¿Qué es Go y por qué la nube lo eligió?

💡 Go es compilado y tipado estático, pero se siente casi tan simple como Python. Compila a un único binario sin dependencias (lo copiás y corre), arranca en milisegundos, y trae concurrencia de fábrica (goroutines). Por eso Docker, Kubernetes, Terraform y la CLI de GitHub están escritos en Go.

Las tres ideas que definen a Go:

  • Simplicidad radical: pocas palabras clave (25), un solo bucle, una sola forma de hacer cada cosa. El estilo no se discute: gofmt formatea por vos.
  • Velocidad: compila a código máquina nativo. Rápido como C, productivo como Python.
  • Concurrencia: lanzar miles de tareas en paralelo es trivial (lo vemos en M08).

Instalar Go

1. Descargá el instalador de go.dev/dl (Windows, Mac o Linux) y seguí los pasos.
2. Verificá en la terminal:
go version    # ej: go version go1.23 windows/amd64

Tu primer programa

Creá un archivo hola.go:

package main

import "fmt"

func main() {
    fmt.Println("¡Hola, Go!")
}

Corrélo:

go run hola.go      # compila y ejecuta al vuelo
go build hola.go    # genera un binario (hola.exe / hola) que podés distribuir
📌 Anatomía mínima: todo archivo Go pertenece a un package. El programa ejecutable arranca en el paquete main, en la función main(). Lo que usás de otros paquetes se trae con import.

Módulos: el manejo de dependencias

Un proyecto Go moderno es un módulo. Lo iniciás una vez:

go mod init ejemplo.com/miapp   # crea go.mod (como package.json o pyproject.toml)
go get github.com/algun/paquete  # agrega una dependencia
gofmt (o go fmt) reformatea tu código al estilo estándar de Go. En Go no se discute tabs vs espacios ni dónde van las llaves: hay una sola forma y la herramienta la impone. Esto elimina toneladas de debates de estilo en los equipos.

Tres cosas que sorprenden viniendo de Python/JS

No existe while. Go tiene un único bucle: for (que hace de while, for y forever). Lo vemos en M03.
Una variable o import sin usar es ERROR de compilación, no un warning. Go te obliga a tener el código limpio.
Tenés que declarar (o inferir) el tipo. Con := Go infiere el tipo, pero el tipo existe y es fijo. No podés meter un string donde esperabas un int.

Checkpoint — ¿lo tenés claro?

¿Por qué Go compila a un único binario es una ventaja?

Porque el deploy es copiar un solo archivo: no necesitás instalar un runtime ni dependencias en el servidor. Ideal para contenedores y la nube (por eso Docker/Kubernetes lo usan).

¿Qué hace go run vs go build?

go run compila y ejecuta de una (útil mientras desarrollás). go build genera el binario ejecutable que después distribuís o desplegás.

¿Para qué sirve gofmt?

Reformatea automáticamente tu código al estilo estándar único de Go. Elimina los debates de formato: hay una sola forma "correcta" y la herramienta la aplica.

Ejercicios

  1. Instalá Go y verificá la versión con go version.
  2. Escribí, compilá y ejecutá el "¡Hola, Go!" con go run.
  3. Generá el binario con go build y ejecutalo directamente.
  4. Probá dejar una variable sin usar y mirá el error de compilación (para que veas lo estricto que es).
  5. Iniciá un módulo con go mod init y mirá el archivo go.mod que crea.

🧠 Autoevaluación

1. ¿Qué hace especial a Go para la nube?

Un binario sin dependencias + arranque instantáneo + goroutines hacen a Go ideal para servidores y contenedores. Por eso Docker/Kubernetes lo usan.

2. ¿Dónde empieza a ejecutarse un programa Go?

El ejecutable arranca en func main() dentro de package main. Es la convención de Go.

3. En Go, ¿qué pasa con una variable declarada y no usada?

Go es estricto: variables (e imports) sin usar son errores de compilación. Te obliga a mantener el código limpio.
