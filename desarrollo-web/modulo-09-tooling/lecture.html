🧠 Autoevaluación rápida

Respondé sin mirar arriba. Cada pregunta te explica el porqué.

1. En el CI, ¿por qué conviene npm ci y no npm install?

npm ci es determinístico y más rápido: no toca el lockfile, lo obedece. Y falla ruidosamente si alguien se olvidó de commitear el package-lock.json, que es justo lo que querés que pase en CI. npm install sí puede reescribir el lock y subir versiones dentro del rango.

2. En package.json, ¿qué versiones acepta "^2.5.7"?

El ^ deja subir MINOR y PATCH pero nunca el MAJOR, porque un MAJOR nuevo rompe la API. El que se queda clavado en 2.5.x es ~2.5.7. Sin prefijo ("2.5.7") es versión exacta, y "*" es la más reciente — peligroso.

3. ¿Cuál de estos sí va commiteado al repo?

El lockfile es el que garantiza que todo el equipo (y el CI) instale las mismas versiones exactas: va commiteado sí o sí. node_modules/ se regenera con npm install y .env tiene secretos — los dos van al .gitignore, junto con dist/ y *.log.
