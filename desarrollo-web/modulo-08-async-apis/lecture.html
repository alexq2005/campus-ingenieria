🧠 Autoevaluación rápida

Respondé sin mirar arriba. Cada pregunta te explica el porqué.

1. ¿En qué orden imprime este código?

console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
console.log('4');
Primero corre todo lo sincrónico (1 y 4). Recién cuando el call stack queda vacío, el event loop vacía la microtask queue (las promises → 3) y después la macrotask queue (setTimeout → 2). Microtasks siempre antes que macrotasks, aunque el timeout sea 0.

2. El servidor responde 404. ¿fetch rechaza la promesa y cae en el catch?

fetch solo rechaza ante errores de red (DNS, offline, CORS). Un 404 es una respuesta válida del servidor, así que la promesa resuelve. El patrón correcto es if (!resp.ok) throw new Error('HTTP ' + resp.status); — es la trampa que sorprende a todos los juniors.

3. Disparás 3 requests en paralelo y querés el reporte de las tres aunque alguna falle. ¿Cuál usás?

allSettled espera a todas y nunca rechaza: devuelve un array de {status, value/reason}. all cortocircuita apenas una rechaza; race te da solo la primera que termina (sirve para timeouts); any ignora los rechazos y te da el primer éxito.
