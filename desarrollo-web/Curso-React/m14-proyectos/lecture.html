Módulo 14 — Proyecto Integrador

Acumulaste 14 módulos de teoría y ejemplos. Ahora construí algo real. Este proyecto va a tu portfolio y va a ser lo que muestres en entrevistas.

1. ¿Qué vamos a construir?

Un Dashboard de Productividad Personal con:

  • Auth (sign up, login, logout) con email + password.
  • Tareas (CRUD): crear, editar, marcar como hecha, eliminar, filtrar.
  • Categorías personalizadas con color.
  • Stats: gráfico de tareas hechas en los últimos 7 días.
  • Sync en tiempo real entre tabs/dispositivos.
  • Tema light/dark persistido.
  • Responsive mobile + desktop.
  • Deploy en Vercel con URL pública.

3. Plan en 5 fases (~2-3 semanas)

Fase 1 — Setup (Día 1-2)

  • Crear proyecto Next.js + TS + Tailwind.
  • Instalar shadcn/ui + componentes base (Button, Input, Card, Dialog).
  • Setup Neon Postgres + Drizzle.
  • Setup ESLint + Prettier + CI con GitHub Actions.
  • Setup Vercel: primer deploy del "Hello World".

Fase 2 — Auth + Schema (Día 3-5)

  • Integrar auth (Clerk es la opción más rápida).
  • Definir schema Drizzle: users, categories, tasks.
  • Migraciones.
  • Páginas: /sign-in, /sign-up, /dashboard (protegida).
  • Middleware de Next.js que redirige a sign-in si no hay sesión.

Fase 3 — CRUD de Tareas (Día 6-10)

  • Server Component que lista tareas del user actual.
  • Form para crear con Server Action.
  • Toggle "hecha" con optimistic update vía useOptimistic.
  • Editar inline + delete.
  • Filtros (todas / pendientes / hechas) con searchParams.
  • Categorías: CRUD + selector en el form de tarea.

Fase 4 — Stats + Real-time (Día 11-14)

  • Página /dashboard/stats con Recharts.
  • Server Component que calcula tareas hechas por día (últimos 7).
  • Real-time: usar Supabase Realtime O Pusher para sync entre tabs.
  • Mostrar indicador "alguien más está editando" si hay 2+ tabs activos.

Fase 5 — Polish + Deploy (Día 15-18)

  • Theme toggle (Zustand persistido).
  • Responsive: probar en mobile, fix issues.
  • Tests críticos: auth flow, crear tarea, marcar como hecha.
  • SEO: metadata por página, OG image.
  • Lighthouse: apuntar > 90 en todo.
  • README con screenshots, stack, demo link.

5. Snippets clave

Schema Drizzle

// db/schema.ts
import { pgTable, serial, text, boolean, timestamp, integer } from 'drizzle-orm/pg-core';

export const categories = pgTable('categories', {
  id: serial('id').primaryKey(),
  userId: text('user_id').notNull(),
  name: text('name').notNull(),
  color: text('color').notNull(),
  createdAt: timestamp('created_at').defaultNow(),
});

export const tasks = pgTable('tasks', {
  id: serial('id').primaryKey(),
  userId: text('user_id').notNull(),
  title: text('title').notNull(),
  done: boolean('done').default(false),
  categoryId: integer('category_id').references(() => categories.id),
  createdAt: timestamp('created_at').defaultNow(),
});

Server Action de crear tarea

// app/actions/tasks.ts
'use server';

import { auth } from '@clerk/nextjs';
import { db } from '@/lib/db';
import { tasks } from '@/db/schema';
import { revalidatePath } from 'next/cache';
import { z } from 'zod';

const schema = z.object({
  title: z.string().min(1).max(200),
  categoryId: z.number().optional(),
});

export async function createTask(formData: FormData) {
  const { userId } = auth();
  if (!userId) throw new Error('No auth');

  const parsed = schema.parse({
    title: formData.get('title'),
    categoryId: formData.get('categoryId')
      ? Number(formData.get('categoryId'))
      : undefined,
  });

  await db.insert(tasks).values({
    userId,
    title: parsed.title,
    categoryId: parsed.categoryId,
  });

  revalidatePath('/dashboard/tasks');
}

Server Component que lista tareas

// app/(dashboard)/tasks/page.tsx
import { auth } from '@clerk/nextjs';
import { db } from '@/lib/db';
import { tasks } from '@/db/schema';
import { eq } from 'drizzle-orm';
import TaskItem from '@/components/tasks/TaskItem';
import NewTaskForm from '@/components/tasks/NewTaskForm';

export default async function TasksPage() {
  const { userId } = auth();
  if (!userId) return null;

  const list = await db
    .select()
    .from(tasks)
    .where(eq(tasks.userId, userId))
    .orderBy(tasks.createdAt);

  return (
    <div>
      <h1>Mis Tareas</h1>
      <NewTaskForm />
      <ul>
        {list.map(t => <TaskItem key={t.id} task={t} />)}
      </ul>
    </div>
  );
}

6. Criterios de "terminado"

Tu capstone está DONE cuando:
  1. ✅ Tiene URL pública (Vercel) que cualquiera puede visitar.
  2. ✅ Auth real funciona (registrarse, salir, volver).
  3. ✅ CRUD completo de tareas y categorías.
  4. ✅ Algún feature "wow" (stats, real-time, drag-drop, undo).
  5. ✅ Responsive: usable en mobile sin scroll horizontal.
  6. ✅ Dark mode funcional y persistido.
  7. ✅ Lighthouse > 90 en Performance, SEO, A11y.
  8. ✅ Tests: al menos 5 tests críticos (auth, CRUD).
  9. ✅ README con screenshots + stack + demo link.
  10. ✅ Código en GitHub público.
  11. ✅ CI/CD: cada push corre tests y deploya si pasa.

9. Errores comunes en proyectos finales

Empezar grande y abandonar: querer hacer "el próximo Notion". Empezás emocionado, te trabás, abandonás. MVP primero, features después.
No deployar hasta el final: deployás el día 18 y todo se rompe. Deployá desde día 1 con "Hello World" y mantenelo verde siempre.
Sin git commits chicos: 1 commit "todo" al final. Imposible volver atrás. Hacé commits pequeños y descriptivos.
Sin README: el proyecto puede ser increíble pero si nadie sabe qué hace, no lo van a mirar.
Scope creep: "ya que estoy, agrego notificaciones push, comentarios, social login con Apple"... NUNCA terminás. Cerrá scope.
No pedir feedback: mostrar a alguien después de terminar es tarde. Mostrá MVP día 7, ajustá.

✅ Checkpoint final

1. ¿Por qué este proyecto y no otro?

Combina TODO lo aprendido: routing, auth, server/client components, forms, mutations con server actions, optimistic updates, estado global, charts, tests, deploy. Es lo que vas a hacer en tu primer trabajo.

2. ¿Qué es el "criterio de done"?

Una checklist explícita: deploy público + auth real + CRUD completo + responsive + tests + README + Lighthouse > 90. Sin criterios, el proyecto nunca está "terminado".

3. ¿Por qué deployar desde el día 1?

Para detectar problemas de deploy temprano (env vars, build, configs). Si esperás al final, todo falla a la vez y no sabés qué arreglar. Mantené el deploy verde siempre.

4. ¿Cómo evitar scope creep?

Definir MVP por escrito antes de empezar. Cualquier idea nueva va a un "v2 ideas". Terminás MVP, deployás, después agregás. Sin disciplina de scope, NUNCA terminás.

5. ¿Qué hacer si te trabás?

(1) Buscar en Stack Overflow / docs / GitHub issues. (2) Preguntar en Discord de Next.js / React / TanStack. (3) Postear pregunta concreta con MWE en Twitter. (4) Si llevás más de 2h trabado, pasar a otra tarea — volvés con cabeza fresca.

6. ¿Cómo medir que está listo para mostrar?

Test del "viernes a la noche": ¿podés mandarle el link a un amigo, que se registre y use la app sin que rompa nada? Si la respuesta es no, no está listo. Si es sí, deploy y comparte.
