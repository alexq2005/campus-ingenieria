Módulo 09 — React Router 7

Una "single page" no significa una sola URL. Con React Router, tu app puede tener múltiples páginas, navegación con back/forward, deeplinks — todo sin recargar el browser.

1. ¿Por qué necesitamos un router?

React por sí solo NO sabe nada de URLs. Si querés que /home muestre un componente, /perfil otro, y que el botón "atrás" del browser funcione, necesitás un router.

React Router es la librería estándar de facto. En 2026 vamos por la versión 7, que unificó Remix y React Router en un solo framework.

2. Instalación y setup

npm install react-router-dom
// src/main.jsx
import { BrowserRouter } from 'react-router-dom';
import App from './App';

ReactDOM.createRoot(document.getElementById('root')).render(
  <BrowserRouter>
    <App />
  </BrowserRouter>
);

BrowserRouter envuelve la app y gestiona la URL del browser usando History API.

3. Rutas básicas

import { Routes, Route, Link } from 'react-router-dom';

function App() {
  return (
    <>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/about">About</Link>
        <Link to="/products">Products</Link>
      </nav>

      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="/products" element={<Products />} />
        <Route path="*" element={<NotFound />} />
      </Routes>
    </>
  );
}
Cómo funciona: React Router lee la URL, compara con las rutas del <Routes>, renderiza el element de la que matchea. La ruta * es el "catch-all" (404).

4. Link vs <a>

TagComportamiento
<a href="/about">Recarga la página entera. Perdés estado React.
<Link to="/about">Navegación SPA — sin reload, mantiene estado.
SIEMPRE usar Link dentro de la app. <a> solo para enlaces externos.

5. Params de URL

// Define la ruta con :id
<Route path="/products/:id" element={<ProductDetail />} />

// En el componente, leés el param con useParams
import { useParams } from 'react-router-dom';

function ProductDetail() {
  const { id } = useParams();
  return <h1>Producto #{id}</h1>;
}

// URLs:
// /products/42      → id = "42"
// /products/banana  → id = "banana"

6. Query params (search params)

// URL: /search?q=react&page=2
import { useSearchParams } from 'react-router-dom';

function Search() {
  const [searchParams, setSearchParams] = useSearchParams();
  const q = searchParams.get('q');
  const page = searchParams.get('page') || '1';

  return (
    <>
      <p>Buscando "{q}" — página {page}</p>
      <button onClick={() => setSearchParams({ q, page: Number(page) + 1 })}>
        Siguiente
      </button>
    </>
  );
}

7. Navegación programática — useNavigate

import { useNavigate } from 'react-router-dom';

function LoginForm() {
  const navigate = useNavigate();

  async function handleSubmit(e) {
    e.preventDefault();
    const ok = await login();
    if (ok) {
      navigate('/dashboard');           // ir a dashboard
    }
  }

  return ...;
}

// Otras formas de navegar
navigate('/about');                      // ir a /about
navigate(-1);                            // back
navigate('/admin', { replace: true });   // sin agregar al history
navigate('/users/42', { state: { from: 'list' } });  // pasar state

8. Layouts y rutas anidadas

function App() {
  return (
    <Routes>
      <Route path="/" element={<PublicLayout />}>
        <Route index element={<Home />} />
        <Route path="about" element={<About />} />
      </Route>

      <Route path="/dashboard" element={<PrivateLayout />}>
        <Route index element={<Dashboard />} />
        <Route path="users" element={<Users />} />
        <Route path="users/:id" element={<UserDetail />} />
      </Route>
    </Routes>
  );
}

// Cada Layout debe renderizar <Outlet /> donde van las rutas hijas
import { Outlet } from 'react-router-dom';

function PublicLayout() {
  return (
    <>
      <Header />
      <main><Outlet /></main>
      <Footer />
    </>
  );
}
Las rutas anidadas son la mejor manera de compartir layout (header, sidebar) entre múltiples páginas. <Outlet /> es el "slot" donde React Router inserta la ruta hija matched.

9. Rutas protegidas (guarded)

function PrivateRoute({ children }) {
  const { isLoggedIn } = useAuth();
  if (!isLoggedIn) return <Navigate to="/login" replace />;
  return children;
}

// Uso
<Route path="/dashboard" element={
  <PrivateRoute><Dashboard /></PrivateRoute>
} />

10. NavLink con estado activo

import { NavLink } from 'react-router-dom';

<NavLink
  to="/about"
  className={({ isActive }) => isActive ? 'active' : ''}
>
  About
</NavLink>

NavLink es Link + auto-clase cuando la URL matchea. Útil para navs con indicador visual.

11. Loaders y actions (React Router 7 style)

Con la API de Data Routers, podés cargar datos ANTES de renderizar:

import { createBrowserRouter, RouterProvider, useLoaderData } from 'react-router-dom';

const router = createBrowserRouter([
  {
    path: '/users/:id',
    element: <UserDetail />,
    loader: async ({ params }) => {
      const res = await fetch(`/api/users/${params.id}`);
      return res.json();
    },
    errorElement: <ErrorPage />,
  },
]);

function UserDetail() {
  const user = useLoaderData();  // ya cargado antes de renderizar
  return <h1>{user.name}</h1>;
}

function App() {
  return <RouterProvider router={router} />;
}
Loaders eliminan el patrón "useEffect + fetch + loading". La URL se vuelve la fuente de verdad de qué datos cargar. Es el modelo que viene de Remix.

12. Pasar state entre rutas

// Navegar pasando state
navigate('/checkout', { state: { producto: { id: 42 } } });

// Leer state en la ruta destino
import { useLocation } from 'react-router-dom';

function Checkout() {
  const location = useLocation();
  const producto = location.state?.producto;
  return <p>Producto: {producto?.id}</p>;
}
El state no sobrevive a F5. Si necesitás persistencia, ponelo en search params o en estado global.

13. Errores típicos

Usar <a> en lugar de <Link>: la página se recarga, perdés todo el estado React.
Olvidar BrowserRouter: las rutas no renderizan, no hay error claro. Verificar que el root tenga <BrowserRouter>.
Routes sin orden de especificidad: rutas más específicas primero. /users/:id antes que /users. (React Router 7 lo maneja mejor pero igual sé explícito.)
Olvidar <Outlet /> en layouts: las rutas hijas no aparecen.
SPA en hosting estático sin fallback: si Vercel/Netlify no rutean a index.html para rutas inexistentes, F5 en /about da 404. Hay que configurar el host.

✅ Checkpoint

1. ¿Por qué Link y no <a>?

Porque <a> recarga la página entera, perdiendo el estado React. Link usa History API del browser para cambiar la URL sin reload — verdadera navegación SPA.

2. ¿Cómo leés parámetros dinámicos de URL?

Con el hook useParams(). Si la ruta es /users/:id y la URL es /users/42, useParams() devuelve { id: "42" }.

3. ¿Cómo navegás programáticamente?

Con useNavigate() que devuelve una función navigate. Llamala con la URL: navigate('/dashboard'). También acepta números (navigate(-1) = back) y options ({ replace: true }).

4. ¿Para qué sirve <Outlet />?

Es el "placeholder" en un layout donde React Router renderiza la ruta hija matched. Permite compartir UI (header, sidebar) entre múltiples rutas anidadas.

5. ¿Cómo proteger una ruta para que requiera login?

Crear un componente wrapper que verifica auth y, si no está logueado, devuelve <Navigate to="/login" replace />. Envolver la ruta protegida con ese wrapper.

6. ¿Qué problema resuelven los loaders de React Router 7?

Cargar datos basados en la URL ANTES de renderizar el componente. Elimina el patrón "useEffect + fetch + loading state". La URL se vuelve la fuente de verdad de qué cargar. Modelo inspirado en Remix.

1. Dentro de la app, ¿por qué usar <Link to="/about"> y no <a href="/about">?

Esa es toda la gracia de una SPA. Dejá el <a> solo para links externos, que sí tienen que salir del sitio.

2. En un layout con rutas anidadas, ¿para qué sirve <Outlet />?

Sin <Outlet /> el Header y el Footer se ven, pero las rutas hijas no aparecen — y no hay ningún error que te avise. Es de los bugs más frustrantes de debuggear.

3. ¿Qué resuelven los loaders de React Router 7 (createBrowserRouter)?

La URL pasa a ser la fuente de verdad de qué datos hay que traer. El componente los lee ya listos con useLoaderData(), y los errores caen en el errorElement. Es el modelo que React Router heredó de Remix.
