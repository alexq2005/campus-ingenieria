Módulo 01 — Setup + Primer Componente

Antes de escribir hooks y arquitectura, primero: crear un proyecto, renderizar algo, ver el código actualizarse en vivo. Esta es la base mecánica.

1. Crear un proyecto React con Vite

Vite es el bundler moderno por default en 2026 (reemplazó a Create React App, que está deprecated). Configuración cero, dev server ultra rápido, HMR (Hot Module Replacement) sub-100ms.

# Crear proyecto
npm create vite@latest mi-app -- --template react
# o con TypeScript (recomendado):
npm create vite@latest mi-app -- --template react-ts

cd mi-app
npm install
npm run dev

Abrí http://localhost:5173. Vas a ver la página default de Vite. Modificá src/App.jsx → el browser se actualiza solo.

2. Estructura inicial del proyecto

mi-app/
├── index.html              # entry HTML — único en toda la app
├── package.json            # deps + scripts
├── vite.config.js          # config de Vite
├── public/                 # assets estáticos (favicon, robots.txt)
└── src/
    ├── main.jsx            # ⭐ punto de entrada JS
    ├── App.jsx             # ⭐ componente raíz
    ├── App.css
    ├── index.css
    └── assets/
Solo hay UN index.html — el de la raíz. React monta TODA la app dentro de un <div id="root"></div>. Eso es lo que llamamos "SPA" (Single Page Application).

3. El flujo de arranque

Cuando abrís la app en el browser:

(1) El browser carga index.html que tiene <script type="module" src="/src/main.jsx">.
(2) Vite transforma main.jsx a JS válido (JSX → llamadas a React) y lo sirve.
(3) main.jsx ejecuta:
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App.jsx';
import './index.css';

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
(4) React busca <div id="root"> en el HTML y renderiza dentro tu componente <App />.
(5) A partir de ahí, todo lo que ves en la página viene de tus componentes React.

4. JSX — La sintaxis "HTML en JS"

JSX es una extensión de JavaScript que parece HTML. NO es HTML — es azúcar sintáctico sobre llamadas a React.createElement().
JSX: 
const elemento = <h1 className="titulo">Hola</h1>;
Lo que realmente se ejecuta (después de la transformación): 
const elemento = React.createElement(
  'h1',
  { className: 'titulo' },
  'Hola'
);
JSX es solo más cómodo de escribir y leer. Lo que React procesa son objetos JS, no HTML.

4.1 Reglas de JSX

ReglaEjemplo
Atributos en camelCaseclassName en lugar de class; onClick en lugar de onclick
Un solo elemento raíz por componenteSi necesitás varios, envolvé en <>...</> (Fragment)
Todos los tags deben cerrarse<img />, <br />, <input /> (self-closing)
Expresiones JS entre {}<p>Hola {nombre}</p>
Estilos inline son objetosstyle={{ color: 'red', fontSize: 16 }} (camelCase!)
Comentarios en JSX{/* esto es un comentario */}

4.2 Por qué className y no class

Porque class es palabra reservada en JavaScript (para definir clases). React eligió className para evitar el conflicto.

5. Tu primer componente

Un componente React es una función JavaScript que devuelve JSX. Eso es todo.

// src/components/Saludo.jsx
function Saludo() {
  return <h1>Hola, mundo</h1>;
}

export default Saludo;
Reglas inquebrantables:
  • El nombre debe empezar con MAYÚSCULA. saludo no funciona — React lo trataría como HTML tag desconocido.
  • Debe devolver JSX (o null, string, number, array de elementos).
  • Un archivo = un componente exportado por default es la convención.

6. Usar el componente

// src/App.jsx
import Saludo from './components/Saludo';

function App() {
  return (
    <main>
      <Saludo />
      <Saludo />
      <Saludo />
    </main>
  );
}

export default App;

Resultado en el browser: tres <h1>Hola, mundo</h1> uno debajo del otro. Cada <Saludo /> es una instancia del componente.

7. Expresiones JS dentro de JSX

Lo que está entre {} es JavaScript puro:

function Tarjeta() {
  const nombre = "Ana";
  const edad = 30;
  const esMayor = edad >= 18;

  return (
    <div>
      <p>Hola {nombre}</p>
      <p>Edad: {edad}</p>
      <p>Año aprox de nacimiento: {2026 - edad}</p>
      <p>¿Mayor? {esMayor ? 'Sí' : 'No'}</p>
      <p>Texto en mayúscula: {nombre.toUpperCase()}</p>
    </div>
  );
}
Dentro de {} va una expresión, NO un statement. {if (x) {...}} NO funciona. Para condicionales usás ternario: {condicion ? a : b} o short-circuit {condicion && a}.

8. Fragments — más de un elemento raíz

JSX requiere UN elemento raíz. Si necesitás devolver varios sin envolver en un <div> extra, usás Fragment:

// ❌ Error: dos elementos raíz
function Lista() {
  return (
    <li>Uno</li>
    <li>Dos</li>
  );
}

// ✅ Bien con Fragment shorthand
function Lista() {
  return (
    <>
      <li>Uno</li>
      <li>Dos</li>
    </>
  );
}

// ✅ Bien con Fragment explícito (si necesitás key)
function Lista() {
  return (
    <React.Fragment>
      <li>Uno</li>
      <li>Dos</li>
    </React.Fragment>
  );
}

9. StrictMode — qué es y por qué importa

En main.jsx ves <React.StrictMode> envolviendo todo. Es un modo de desarrollo (NO se ejecuta en producción) que:

  • Detecta side effects mal escritos llamando tu componente 2 veces.
  • Avisa sobre APIs deprecated.
  • Detecta uso inseguro de algunos hooks.
Si ves console.log ejecutándose 2 veces en dev y 1 vez en prod, NO es un bug — es StrictMode haciendo su trabajo. Dejalo activo siempre.

10. DevTools de React

Extensión obligatoria para Chrome / Firefox: React Developer Tools. Una vez instalada:

  • Aparece tab "⚛️ Components" en DevTools.
  • Inspeccionás el árbol de componentes con sus props y estado.
  • Tab "⚛️ Profiler" para medir renders.
Instalar y abrir ⚛️ Components es lo primero al debuggear React. Sin DevTools estás programando a ciegas.

11. Función vs Clase (referencia histórica)

Antes de 2018, los componentes se escribían como clases. Hoy ese estilo está deprecated en proyectos nuevos:

// ❌ Estilo viejo — solo si mantenés código legacy
class Saludo extends React.Component {
  render() {
    return <h1>Hola</h1>;
  }
}

// ✅ Estilo moderno
function Saludo() {
  return <h1>Hola</h1>;
}
Las clases todavía funcionan, pero en proyectos nuevos del 2026 NUNCA se usan. Los hooks (próximos módulos) son MUCHO más limpios.

12. Mini-proyecto: tarjeta de perfil

// src/components/TarjetaPerfil.jsx
function TarjetaPerfil() {
  const usuario = {
    nombre: "Ana Pérez",
    rol: "Frontend Developer",
    foto: "https://i.pravatar.cc/120?u=ana",
    skills: ["React", "TypeScript", "Tailwind"],
  };

  return (
    <div style={{
      border: '1px solid #ccc',
      borderRadius: 12,
      padding: 16,
      maxWidth: 300,
      textAlign: 'center'
    }}>
      <img
        src={usuario.foto}
        alt={usuario.nombre}
        style={{ borderRadius: '50%', width: 120 }}
      />
      <h2>{usuario.nombre}</h2>
      <p><em>{usuario.rol}</em></p>
      <p>Skills: {usuario.skills.join(', ')}</p>
      <p>Cantidad de skills: {usuario.skills.length}</p>
    </div>
  );
}

export default TarjetaPerfil;
Notá: los style reciben un OBJETO (no string), las propiedades son camelCase (borderRadius, no border-radius), {usuario.skills.length} es JS puro dentro del JSX. Esto es todo lo que vas a hacer una y otra vez.

13. Errores típicos del principiante

Nombre del componente en minúscula: function saludo() + <saludo /> = React lo trata como HTML tag desconocido y no renderiza.
Olvidar el return en una función componente: devuelve undefined → error "Nothing was returned from render".
Usar class en lugar de className: warning en consola, el className no se aplica.
Llaves vs paréntesis confundidos: return ( <div>... </div> ) usa paréntesis para multilínea. { } son para expresiones JS adentro.
Devolver múltiples elementos sin Fragment: error "Adjacent JSX elements must be wrapped". Usá <>...</>.
Modificar el archivo y no ver cambio: revisar terminal — Vite muestra errores ahí. Si la consola del browser muestra error rojo, es runtime; si la terminal muestra error, es de compilación.

✅ Checkpoint

1. ¿Qué es JSX y cómo se transforma?

JSX es azúcar sintáctico que parece HTML pero es JavaScript. El bundler (Vite) lo transforma en llamadas a React.createElement() que generan objetos JS. React procesa esos objetos, no HTML real.

2. ¿Por qué className y no class?

Porque class es palabra reservada en JavaScript (para definir clases). JSX está dentro de JS, así que reusar class generaría conflicto. React eligió className para evitarlo. Similar con htmlFor en lugar de for.

3. ¿Cuáles son las 2 reglas básicas de un componente función?

(1) El nombre debe empezar con mayúscula (Saludo, no saludo) para que React lo trate como componente. (2) Debe devolver JSX (o null/string/number/array).

4. ¿Qué pasa si tu componente devuelve dos elementos hermanos sin envolver?

Error de compilación: "Adjacent JSX elements must be wrapped in an enclosing tag". Solución: envolver en un <div> si tiene sentido visual, o en un Fragment <>...</> si NO querés agregar un nodo extra al DOM.

5. ¿Para qué sirve React.StrictMode?

Es un modo de DESARROLLO (no afecta producción) que detecta problemas: side effects mal escritos (llama tus componentes 2 veces para detectarlos), uso de APIs deprecated, hooks usados incorrectamente. Dejarlo siempre activo.

6. ¿Cómo se interpolan expresiones JS dentro de JSX?

Con llaves {}. Solo expresiones (cosas que devuelven un valor), no statements. {nombre}, {2 + 2}, {condicion ? a : b} sí; {if (x) {...}} NO.

Respondé sin mirar arriba. Cada pregunta te explica el porqué.

1. ¿Por qué en JSX se escribe className y no class?

El JSX vive adentro de JS, donde class ya sirve para definir clases. React eligió className para esquivar el choque — igual que htmlFor en lugar de for.

2. ¿Qué hace ReactDOM.createRoot(document.getElementById('root')).render(<App />)?

Hay un solo index.html en toda la app (eso es una SPA). Compilar el JSX lo hace Vite; createRoot solo se encarga de montar <App /> adentro de ese div.

3. Tu componente devuelve dos <li> hermanos y explota con "Adjacent JSX elements must be wrapped". ¿Cuál es la solución que NO agrega un nodo extra al DOM?

JSX exige un único elemento raíz. El <div> también soluciona el error pero ensucia el DOM con un nodo de más; el Fragment agrupa sin dejar rastro. Y con dos return, el segundo nunca se ejecuta.
