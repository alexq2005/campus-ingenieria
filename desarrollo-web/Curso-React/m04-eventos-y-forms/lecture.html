Módulo 04 — Eventos y Forms

Sin eventos, una app React es solo una pantalla bonita. Sin forms, no podés capturar nada del usuario. Esta lección hace tu app interactiva.

1. Manejar eventos

Los eventos en React son synthetic events: un wrapper sobre los nativos del DOM, cross-browser, con la misma API.

function Boton() {
  function handleClick() {
    alert('¡Click!');
  }

  return <button onClick={handleClick}>Apretame</button>;
}
Reglas:
  • Atributos en camelCase: onClick, onChange, onSubmit (no onclick).
  • Pasás una FUNCIÓN, no una llamada: onClick={handleClick}, NO onClick={handleClick()}.
  • Inline arrow funciona pero crea nueva función en cada render: onClick={() => setX(1)}.

2. Inline vs función separada

// Inline — ok para handlers simples
<button onClick={() => setCount(count + 1)}>+1</button>

// Función separada — preferida para lógica compleja
function handleClick() {
  setCount(count + 1);
  console.log('Clickeado');
  trackEvent('button_click');
}
<button onClick={handleClick}>+1</button>

3. Pasar argumentos al handler

function Lista() {
  function eliminar(id) {
    console.log('Eliminando', id);
  }

  return (
    <>
      {items.map(item => (
        // ⭐ Arrow function que recibe el id
        <button onClick={() => eliminar(item.id)}>Borrar</button>
      ))}
    </>
  );
}
NO escribas onClick={eliminar(item.id)} (sin arrow) — eso EJECUTA eliminar durante el render, no en el click.

4. El objeto event

function Input() {
  function handleChange(event) {
    console.log(event.target.value);   // el valor del input
    console.log(event.target.name);    // el name del input
    console.log(event.target.checked); // para checkboxes
    console.log(event.type);            // "change", "click", etc.
  }

  return <input onChange={handleChange} />;
}

5. preventDefault y stopPropagation

function Form() {
  function handleSubmit(e) {
    e.preventDefault();  // evita el reload de página default del form
    console.log('Submit con JS');
  }

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit">Enviar</button>
    </form>
  );
}

function Card({ onClick }) {
  function handleButton(e) {
    e.stopPropagation();  // evita que el click llegue al onClick del Card
    console.log('Botón clickeado, NO la card');
  }

  return (
    <div onClick={onClick}>
      <button onClick={handleButton}>X</button>
    </div>
  );
}

6. Inputs controlados (controlled)

Un input "controlado" tiene su valor en el estado de React. React es la fuente de verdad.

function FormControlado() {
  const [nombre, setNombre] = useState('');

  return (
    <>
      <input
        value={nombre}
        onChange={(e) => setNombre(e.target.value)}
      />
      <p>Hola, {nombre}</p>
    </>
  );
}
El patrón canónico de input controlado: value={estado} + onChange={e => setEstado(e.target.value)}. Lo vas a escribir 1000 veces en tu carrera.

7. Inputs uncontrolled (con ref)

Alternativa: dejar que el DOM maneje el valor, leerlo solo en submit:

import { useRef } from 'react';

function FormUncontrolled() {
  const inputRef = useRef(null);

  function handleSubmit(e) {
    e.preventDefault();
    console.log(inputRef.current.value);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input ref={inputRef} defaultValue="" />
      <button>Enviar</button>
    </form>
  );
}
Cuándo usarControladoUncontrolled
Validar en vivo✅❌
Auto-formato (mayúscula, máscara)✅❌
Disable submit hasta válido✅❌
Forms muy grandes (perf)🟡✅
File inputs❌ (forzado uncontrolled)✅
Default: controlado. Cambiá a uncontrolled (o usá React Hook Form) si el form es grande y los re-renders se notan.

8. Distintos tipos de inputs

function FormCompleto() {
  const [texto, setTexto] = useState('');
  const [edad, setEdad] = useState(0);
  const [acepta, setAcepta] = useState(false);
  const [pais, setPais] = useState('AR');
  const [color, setColor] = useState('#ff0000');

  return (
    <form>
      {/* Texto */}
      <input value={texto} onChange={(e) => setTexto(e.target.value)} />

      {/* Número */}
      <input
        type="number"
        value={edad}
        onChange={(e) => setEdad(Number(e.target.value))}
      />

      {/* Checkbox */}
      <input
        type="checkbox"
        checked={acepta}
        onChange={(e) => setAcepta(e.target.checked)}
      />

      {/* Select */}
      <select value={pais} onChange={(e) => setPais(e.target.value)}>
        <option value="AR">Argentina</option>
        <option value="UY">Uruguay</option>
      </select>

      {/* Color picker */}
      <input
        type="color"
        value={color}
        onChange={(e) => setColor(e.target.value)}
      />

      {/* Textarea */}
      <textarea value={texto} onChange={(e) => setTexto(e.target.value)} />
    </form>
  );
}
En React, <textarea> usa value (no children como HTML normal) y <select> usa value en el select (no selected en cada option).

9. Form con un solo objeto de estado

function FormUsuario() {
  const [form, setForm] = useState({
    nombre: '',
    email: '',
    edad: 0,
  });

  function actualizar(e) {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
  }

  function handleSubmit(e) {
    e.preventDefault();
    console.log('Enviando:', form);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="nombre" value={form.nombre} onChange={actualizar} />
      <input name="email" type="email" value={form.email} onChange={actualizar} />
      <input name="edad" type="number" value={form.edad} onChange={actualizar} />
      <button>Enviar</button>
    </form>
  );
}
Truco: usar name en el input + computed key [name] en el setState. Un solo handler para todos los inputs.

10. Validación básica

function FormLogin() {
  const [email, setEmail] = useState('');
  const [pwd, setPwd] = useState('');

  const emailValido = email.includes('@');
  const pwdValido = pwd.length >= 8;
  const formValido = emailValido && pwdValido;

  return (
    <form>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />
      {email && !emailValido && <p style={{color: 'red'}}>Email inválido</p>}

      <input
        type="password"
        value={pwd}
        onChange={(e) => setPwd(e.target.value)}
      />
      {pwd && !pwdValido && <p style={{color: 'red'}}>Mín 8 caracteres</p>}

      <button disabled={!formValido}>Login</button>
    </form>
  );
}
Notar: los errores se DERIVAN del estado, no se guardan aparte. Esto es estado derivado correcto — no duplicás info.

11. React Hook Form (preview)

Para forms grandes con validación compleja, la librería estándar es React Hook Form:

import { useForm } from 'react-hook-form';

function FormPro() {
  const { register, handleSubmit, formState: { errors } } = useForm();

  function onSubmit(data) {
    console.log(data);
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('email', { required: 'Email requerido' })} />
      {errors.email && <p>{errors.email.message}</p>}
      <button>Submit</button>
    </form>
  );
}
React Hook Form usa inputs uncontrolled internamente → re-renders mínimos. Para forms con > 5 campos o validación compleja, vale la pena. Lo profundizamos en M11.

12. useActionState — React 19

React 19 introdujo useActionState para forms con actions (server actions o async):

import { useActionState } from 'react';

async function loginAction(prevState, formData) {
  const email = formData.get('email');
  const result = await fetch('/api/login', {
    method: 'POST',
    body: JSON.stringify({ email })
  });
  return result.ok ? { ok: true } : { error: 'Falló' };
}

function FormLogin() {
  const [state, action, pending] = useActionState(loginAction, null);

  return (
    <form action={action}>
      <input name="email" type="email" />
      <button disabled={pending}>
        {pending ? 'Enviando...' : 'Login'}
      </button>
      {state?.error && <p>{state.error}</p>}
    </form>
  );
}
Funciona excelente combinado con Server Actions de Next.js 15. Lo profundizamos en M13.

13. Errores típicos

Ejecutar el handler en lugar de pasarlo: onClick={handleClick()} ejecuta inmediatamente al render. Debe ser onClick={handleClick}.
Input controlado sin onChange: <input value={x} /> sin onChange → input read-only. React te avisa por consola.
Olvidar preventDefault en form submit: la página se recarga, perdés estado.
Mutar el form state: form.email = 'x'; setForm(form) NO funciona. Usá setForm({...form, email: 'x'}).
Validar con regex en el render sin memoización: si la regex es cara, considerá useMemo. Para validaciones simples, no te preocupes.
Convertir Number en cada handler: e.target.value es siempre string. Para números: Number(e.target.value) o parseInt.

✅ Checkpoint

1. ¿Diferencia entre onClick={fn} y onClick={fn()}?

El primero PASA la función como handler — React la llama al click. El segundo EJECUTA fn() ahora mismo durante el render y le pasa el resultado al onClick (probablemente undefined). Casi siempre querés el primero.

2. ¿Qué es un input controlado?

Un input cuyo valor está en el estado React (value={estado}) y se actualiza vía onChange. React es la fuente de verdad. Permite validación en vivo, formato automático, disable de submit por validación.

3. ¿Cuándo usar uncontrolled o React Hook Form?

Cuando los re-renders del controlado se notan (forms grandes, > 10 inputs) o no necesitás validación en vivo (solo en submit). React Hook Form usa uncontrolled internamente con la mejor DX.

4. ¿Por qué e.preventDefault() en form submit?

Porque el comportamiento default del browser es recargar la página al submit del form. Eso destruye el estado React. preventDefault permite manejar el submit con JS.

5. ¿Qué hace este código? setForm(prev => ({ ...prev, [name]: value }))

Crea un NUEVO objeto que copia todas las props del estado previo Y sobrescribe la propiedad con clave [name] (computed key — el nombre del input). Es el patrón canónico para form con un solo handler para múltiples inputs.

6. ¿Qué es useActionState y cuándo usarlo?

Hook de React 19 para forms con async actions (especialmente Server Actions de Next.js). Devuelve [state, action, pending]. Maneja el estado del submit, errores y loading sin escribir useState manual.
