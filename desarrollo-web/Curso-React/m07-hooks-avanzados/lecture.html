Módulo 07 — Hooks Avanzados

useState y useEffect son el 80% del trabajo. Los otros hooks (useContext, useRef, useReducer, useMemo, useCallback, useId, use) cubren casos específicos pero importantes.

1. useContext — compartir datos sin props drilling

Context permite que datos viajen "por arriba" del árbol de componentes sin pasar props manualmente. Solución directa al problema de M02.
import { createContext, useContext, useState } from 'react';

// 1. Crear el context
const ThemeContext = createContext('light');

// 2. Provider en el padre
function App() {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Page />
    </ThemeContext.Provider>
  );
}

// 3. Consumir en cualquier descendiente (sin importar la profundidad)
function ThemeToggle() {
  const { theme, setTheme } = useContext(ThemeContext);
  return (
    <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>
      Toggle ({theme})
    </button>
  );
}
Context NO es para estado global de toda la app. Es para subárboles. Para estado global complejo, usá Zustand (M11). Context excesivo causa re-renders innecesarios.

2. useRef — referencias mutables

useRef guarda un valor que persiste entre renders PERO no causa re-render al cambiar. Su uso principal: acceder al DOM.

Caso 1: foco programático en input

function FormConFoco() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current?.focus();  // focusear al montar
  }, []);

  return <input ref={inputRef} />;
}

Caso 2: guardar valor sin re-render

function Cronometro() {
  const [count, setCount] = useState(0);
  const intervalRef = useRef(null);

  function start() {
    if (intervalRef.current) return;
    intervalRef.current = setInterval(() => {
      setCount(c => c + 1);
    }, 1000);
  }

  function stop() {
    clearInterval(intervalRef.current);
    intervalRef.current = null;
  }

  return (
    <>
      <p>{count}s</p>
      <button onClick={start}>Start</button>
      <button onClick={stop}>Stop</button>
    </>
  );
}
useRef vs useState:
  • useState: cambio dispara re-render. Usalo si el valor afecta lo que se VE.
  • useRef: cambio NO dispara re-render. Usalo para timers, DOM, contadores internos invisibles.

3. useReducer — estado complejo con lógica encapsulada

Si tu estado es un objeto con muchas formas de actualizarlo, useReducer es más limpio que múltiples useState + setters dispersos.
import { useReducer } from 'react';

const initialState = { count: 0, history: [] };

function reducer(state, action) {
  switch (action.type) {
    case 'INC':
      return { count: state.count + 1, history: [...state.history, state.count + 1] };
    case 'DEC':
      return { count: state.count - 1, history: [...state.history, state.count - 1] };
    case 'RESET':
      return initialState;
    default:
      throw new Error(`Acción desconocida: ${action.type}`);
  }
}

function Contador() {
  const [state, dispatch] = useReducer(reducer, initialState);

  return (
    <>
      <p>Count: {state.count}</p>
      <button onClick={() => dispatch({ type: 'INC' })}>+</button>
      <button onClick={() => dispatch({ type: 'DEC' })}>-</button>
      <button onClick={() => dispatch({ type: 'RESET' })}>Reset</button>
      <p>History: {state.history.join(', ')}</p>
    </>
  );
}
Cuándo useReducer vs useState:
  • 1-3 piezas independientes de estado → useState.
  • Estado con 4+ formas de update relacionadas → useReducer.
  • Lógica de transición compleja (state machine) → useReducer.
  • Familiar con Redux → useReducer se va a sentir natural.

4. useMemo — memoizar cálculos caros

useMemo guarda el resultado de un cálculo y solo lo recalcula cuando cambian las dependencias.
function ListaProductos({ productos, busqueda }) {
  // Filtrar es O(n) — si productos tiene 10000 items y se ejecuta en cada render, lag.
  const filtrados = useMemo(() => {
    return productos.filter(p => p.nombre.includes(busqueda));
  }, [productos, busqueda]);

  return <ul>{filtrados.map(p => <li key={p.id}>{p.nombre}</li>)}</ul>;
}
useMemo TIENE COSTO (memoria + checkeo de deps). Usalo solo cuando MEDISTE que hay problema. Memoizar todo "por las dudas" hace el código más complejo sin beneficio.

5. useCallback — memoizar funciones

useCallback es useMemo para funciones. Devuelve la MISMA referencia entre renders mientras no cambien las deps.
function Padre() {
  const [count, setCount] = useState(0);

  // ❌ Sin useCallback — nueva función en cada render
  const handleClick = () => console.log('click');

  // ✅ Con useCallback — misma función entre renders
  const handleClick = useCallback(() => {
    console.log('click');
  }, []);

  return <Hijo onClick={handleClick} count={count} />;
}

// Si Hijo está memoizado con React.memo, sin useCallback va a re-renderizar
// porque onClick es nueva referencia cada vez.
useCallback SOLO tiene sentido cuando la función va a un componente memoizado o a deps de otro hook. En otros casos es overhead sin beneficio.

6. useId — IDs únicos para accesibilidad

function CampoForm({ label }) {
  const id = useId();
  return (
    <>
      <label htmlFor={id}>{label}</label>
      <input id={id} />
    </>
  );
}
Genera IDs estables entre server y client (importante para SSR de Next.js). NO usar para keys de listas — es para IDs HTML de accesibilidad.

7. use() — el hook nuevo de React 19

use() permite leer Promises directamente en componentes (combinado con Suspense):

import { use, Suspense } from 'react';

function Posts({ postsPromise }) {
  const posts = use(postsPromise);  // ⭐ "espera" la promise
  return <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
}

function App() {
  const postsPromise = fetch('/api/posts').then(r => r.json());
  return (
    <Suspense fallback={<p>Cargando...</p>}>
      <Posts postsPromise={postsPromise} />
    </Suspense>
  );
}
use() también lee contexts condicionalmente (cosa que useContext no puede). Es la API del futuro — vas a verla más en React 19+.

8. useDeferredValue y useTransition — concurrent UI

Para mantener la UI responsive cuando hacés updates costosos:

function Buscador() {
  const [input, setInput] = useState('');
  const deferredInput = useDeferredValue(input);

  // input se actualiza en cada keypress (UI responsive)
  // deferredInput se atrasa si el filtrado es caro
  const resultados = useMemo(() => buscarLento(deferredInput), [deferredInput]);

  return (
    <>
      <input value={input} onChange={(e) => setInput(e.target.value)} />
      <Resultados items={resultados} />
    </>
  );
}
function App() {
  const [tab, setTab] = useState('home');
  const [isPending, startTransition] = useTransition();

  function cambiarTab(t) {
    startTransition(() => setTab(t));  // marca como "no urgente"
  }

  return (
    <>
      {isPending && <p>Cambiando...</p>}
      <Tabs onChange={cambiarTab} />
      <Content tab={tab} />
    </>
  );
}

9. Las 2 reglas de los hooks

  1. Solo llamar hooks en el TOP-LEVEL. NUNCA dentro de if, for, while, callbacks anidados. React identifica los hooks por su ORDEN de llamada — si cambia el orden, se rompe.
  2. Solo llamar hooks desde componentes React o desde otros custom hooks. NO desde funciones normales.
// ❌ MAL
function Componente({ condicion }) {
  if (condicion) {
    const [x, setX] = useState(0);  // ¡ROMPE!
  }
  return ...;
}

// ✅ BIEN — siempre llamarlo
function Componente({ condicion }) {
  const [x, setX] = useState(0);
  if (!condicion) return null;
  return ...;
}

11. Errores típicos

Llamar hooks condicionalmente: rompe la regla de los hooks. ESLint te grita.
Mutar .current esperando re-render: useRef NO re-renderiza. Si necesitás re-render, usá useState.
Memoizar todo "por performance": useMemo y useCallback tienen costo. Sin medir, agregás complejidad sin beneficio.
Context con value en objeto inline: <Ctx.Provider value={{ x }}> crea objeto nuevo en cada render → todo el subárbol re-renderiza. Memoizar o partir el context.
useReducer cuando no hace falta: para 2 estados simples, useState es más legible. Reducer brilla con 5+ acciones.

✅ Checkpoint

1. ¿Cuál es la diferencia entre useState y useRef?

Cambiar useState dispara re-render; cambiar useRef no. useState para datos que afectan la UI; useRef para DOM, timers, contadores invisibles, cualquier mutable que NO debe causar render.

2. ¿Cuándo elegir useReducer sobre useState?

Cuando el estado es un objeto con varias formas de actualización relacionadas, cuando querés encapsular la lógica de transición en una función pura (testeable), o cuando vienes de Redux y te resulta familiar.

3. ¿Para qué sirve useContext?

Para pasar datos a descendientes profundos sin props drilling. Util para tema, usuario logueado, idioma. Para estado global complejo, preferir Zustand u otro store dedicado.

4. ¿Cuándo usar useMemo y useCallback?

useMemo: cuando un cálculo es caro y dependencias cambian poco. useCallback: cuando la función va a un componente memoizado con React.memo o a deps de otro hook. SIN medición previa, evitarlos — agregan complejidad.

5. ¿Cuáles son las 2 reglas de los hooks?

(1) Llamar hooks solo en el top-level del componente, nunca en if/for/callbacks. (2) Solo llamar desde componentes React o custom hooks, nunca desde funciones normales.

6. ¿Qué hace useTransition?

Marca un update de estado como "no urgente". React puede interrumpirlo si llega un update urgente (input typing). Devuelve isPending para mostrar loading. Ideal para tabs, filtros caros, navegación.
