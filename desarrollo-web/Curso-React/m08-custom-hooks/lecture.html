Módulo 08 — Custom Hooks

El verdadero superpoder de React: extraer lógica reutilizable en funciones propias. Custom hooks son lo que diferencia a un junior de un mid-level.

1. ¿Qué es un custom hook?

Un custom hook es una función JavaScript cuyo nombre empieza con use y que internamente llama a otros hooks de React. Encapsula lógica que querés reutilizar entre componentes.
Las dos reglas:
  • El nombre debe empezar con use (useFoo, useAuth). Sin esa convención, ESLint no detecta que es hook y no aplica las reglas.
  • Puede usar cualquier hook adentro (useState, useEffect, otros customs).

2. Antes y después: extraer lógica repetida

Antes (lógica duplicada en 2 componentes)

function UserList() {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false;
    fetch('/api/users')
      .then(r => r.json())
      .then(d => !cancelled && setData(d))
      .catch(e => !cancelled && setError(e))
      .finally(() => !cancelled && setLoading(false));
    return () => { cancelled = true; };
  }, []);

  // ...render
}

function PostList() {
  // EL MISMO CÓDIGO DUPLICADO pero con /api/posts...
}

Después (extraído en custom hook)

// hooks/useFetch.js
import { useState, useEffect } from 'react';

export function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false;
    setLoading(true);
    fetch(url)
      .then(r => r.json())
      .then(d => !cancelled && setData(d))
      .catch(e => !cancelled && setError(e))
      .finally(() => !cancelled && setLoading(false));
    return () => { cancelled = true; };
  }, [url]);

  return { data, loading, error };
}

// Uso:
function UserList() {
  const { data: users, loading, error } = useFetch('/api/users');
  // ...
}

function PostList() {
  const { data: posts, loading, error } = useFetch('/api/posts');
  // ...
}
El hook NO comparte ESTADO entre los dos componentes — cada uso crea su propia instancia. Lo que comparte es la LÓGICA.

3. Custom hooks populares

useLocalStorage — persistir en localStorage

function useLocalStorage(key, defaultValue) {
  const [value, setValue] = useState(() => {
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : defaultValue;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}

// Uso
function Theme() {
  const [theme, setTheme] = useLocalStorage('theme', 'light');
  return <button onClick={() => setTheme(t => t === 'light' ? 'dark' : 'light')}>
    Theme: {theme}
  </button>;
}

useDebounce — esperar antes de actuar

function useDebounce(value, delay = 500) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(t);
  }, [value, delay]);

  return debounced;
}

// Uso: buscador que no llama API en cada tecla
function Buscador() {
  const [input, setInput] = useState('');
  const debouncedInput = useDebounce(input, 400);

  useEffect(() => {
    if (debouncedInput) {
      fetch(`/api/search?q=${debouncedInput}`);
    }
  }, [debouncedInput]);

  return <input value={input} onChange={(e) => setInput(e.target.value)} />;
}

useToggle — boolean simple

function useToggle(initial = false) {
  const [value, setValue] = useState(initial);
  const toggle = useCallback(() => setValue(v => !v), []);
  return [value, toggle];
}

// Uso
function Modal() {
  const [isOpen, toggleModal] = useToggle();
  return (
    <>
      <button onClick={toggleModal}>Abrir</button>
      {isOpen && <dialog open>Modal content</dialog>}
    </>
  );
}

useWindowSize — viewport reactivo

function useWindowSize() {
  const [size, setSize] = useState({
    width: window.innerWidth,
    height: window.innerHeight,
  });

  useEffect(() => {
    function handler() {
      setSize({ width: window.innerWidth, height: window.innerHeight });
    }
    window.addEventListener('resize', handler);
    return () => window.removeEventListener('resize', handler);
  }, []);

  return size;
}

usePrevious — recordar valor anterior

function usePrevious(value) {
  const ref = useRef();
  useEffect(() => {
    ref.current = value;
  }, [value]);
  return ref.current;
}

// Uso: detectar cambios de prop
function Counter({ count }) {
  const prev = usePrevious(count);
  return <p>Ahora: {count}, antes: {prev}</p>;
}

useOnlineStatus

function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);

  useEffect(() => {
    function on() { setIsOnline(true); }
    function off() { setIsOnline(false); }
    window.addEventListener('online', on);
    window.addEventListener('offline', off);
    return () => {
      window.removeEventListener('online', on);
      window.removeEventListener('offline', off);
    };
  }, []);

  return isOnline;
}

4. Custom hooks que componen otros custom hooks

function useAuth() {
  const [user, setUser] = useLocalStorage('user', null);

  const login = useCallback(async (email, pwd) => {
    const res = await fetch('/api/login', {
      method: 'POST',
      body: JSON.stringify({ email, pwd })
    });
    const u = await res.json();
    setUser(u);
  }, [setUser]);

  const logout = useCallback(() => setUser(null), [setUser]);

  return { user, login, logout, isLoggedIn: !!user };
}

// Uso
function Header() {
  const { user, logout } = useAuth();
  return user
    ? <p>Hola {user.name} <button onClick={logout}>Salir</button></p>
    : <p>No logueado</p>;
}

5. Convención de nombres y firma

PatrónDevuelve
useToggle, useLocalStorageArray [valor, setter] (como useState)
useFetch, useAuthObjeto { data, loading, error }
useDebounce, usePreviousValor único
useHover, useOnScreenTupla [ref, isActive]
Devolvé array si hay 2 cosas paralelas. Objeto si hay más de 2 o si querés nombres claros. No hay regla dura — consistencia dentro de tu proyecto es lo importante.

6. Cuándo NO crear custom hook

Custom hooks tienen costo cognitivo. NO crear si:
  • La "lógica" es 2-3 líneas usadas en 1 lugar.
  • Solo lo usa 1 componente.
  • El nombre cuesta encontrar — síntoma de que la abstracción no es buena.
  • La lógica es realmente del componente (form-specific, etc).
Espera a tener 2-3 usos REALES antes de extraer.

7. Tests de custom hooks

// useCounter.test.js
import { renderHook, act } from '@testing-library/react';
import { useCounter } from './useCounter';

test('increment funciona', () => {
  const { result } = renderHook(() => useCounter(0));

  expect(result.current.count).toBe(0);

  act(() => result.current.increment());

  expect(result.current.count).toBe(1);
});
Para testear hooks aislados, usá renderHook de Testing Library. Wraps el hook en un componente de prueba.

8. Errores típicos

Olvidar el prefijo use: function fetchData() que llama useEffect adentro. ESLint no lo va a chequear → bugs sutiles.
Pretender que custom hook comparte estado: cada componente que usa useCounter() tiene SU PROPIO contador. Si necesitás estado compartido, usá context o store global.
Hooks anidados condicionalmente: aplican las mismas reglas — siempre top-level.
Custom hook con efectos secundarios al "primer call": si tu hook hace fetch automáticamente con cada llamada y se usa en 5 componentes, son 5 fetches. Para data fetching real → TanStack Query (M10).
Devolver objeto nuevo cada vez sin memo: si retornás { data, loading }, cada render es nueva referencia. Si el padre lo pasa a un memo, no funciona. Para hooks complejos, considerá memoizar el return.

✅ Checkpoint

1. ¿Qué hace especial a un custom hook?

Es una función cuyo nombre empieza con use y que usa otros hooks adentro. Permite extraer lógica con estado/efectos para reutilizarla en múltiples componentes sin duplicación.

2. ¿Custom hooks comparten estado entre componentes que los usan?

NO. Cada llamada a useFoo() crea su propia instancia. Comparten la LÓGICA, no el ESTADO. Si necesitás estado compartido, usá context o estado global (Zustand).

3. ¿Por qué importa que el nombre empiece con use?

Es una convención que React/ESLint usan para reconocer que es hook y aplicar las reglas (no llamar condicionalmente, etc). Sin el prefijo, te perdés esa validación.

4. ¿Cuándo NO crear un custom hook?

Cuando la lógica es trivial (2-3 líneas), solo se usa 1 vez, o cuando el nombre cuesta encontrar (síntoma de mala abstracción). Esperá a tener 2-3 usos reales antes de extraer.

5. ¿Cómo testear un custom hook?

Con renderHook de @testing-library/react. Devuelve un objeto { result } con el valor actual. Usá act al disparar updates de estado.

6. ¿Es mejor que un custom hook devuelva array u objeto?

Array si tiene 2 cosas paralelas y querés renombrar fácil (const [x, setX] = useFoo()). Objeto si tiene 3+ propiedades o querés que el orden no importe. Lo importante es consistencia en tu proyecto.

Respondé sin mirar arriba. Cada pregunta te explica el porqué.

1. Dos componentes distintos llaman a useCounter(). ¿Qué comparten?

Un custom hook reutiliza lógica, no estado. Cada uso arranca su propio useState. Si de verdad necesitás estado compartido, va Context o un store global (Zustand, M11).

2. ¿Por qué el nombre tiene que empezar con use?

Si lo llamás fetchData() y adentro usás useEffect, el plugin de ESLint no detecta que es hook y deja de validar las reglas (nada de llamadas condicionales, siempre top-level). Bugs sutiles garantizados.

3. En useDebounce, ¿qué hace el return () => clearTimeout(t) del efecto?

El cleanup corre antes de cada re-ejecución del efecto. Como value cambia en cada tecla, el timeout viejo se descarta y solo el último llega a los 400ms: por eso el buscador no llama a la API en cada letra.
