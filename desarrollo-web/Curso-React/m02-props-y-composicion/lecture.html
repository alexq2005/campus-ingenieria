Módulo 02 — Props y Composición

Si los componentes son funciones, las props son sus parámetros. Esta lección es donde React empieza a tener sentido.

1. ¿Qué son las props?

Props (de "properties") son los datos que un componente padre le pasa a su hijo. Son el equivalente a argumentos de función.
// Componente que RECIBE props
function Saludo(props) {
  return <h1>Hola, {props.nombre}</h1>;
}

// Componente padre que PASA props
function App() {
  return (
    <>
      <Saludo nombre="Ana" />
      <Saludo nombre="Luis" />
      <Saludo nombre="Eva" />
    </>
  );
}

Las 3 instancias del mismo componente renderizan distinto según la prop que reciben.

2. Destructuring de props (sintaxis moderna)

En vez de escribir props.nombre, destructurás directamente:

// Versión clásica
function Saludo(props) {
  return <h1>Hola, {props.nombre}</h1>;
}

// ✅ Versión moderna (recomendada)
function Saludo({ nombre }) {
  return <h1>Hola, {nombre}</h1>;
}

// Múltiples props
function Tarjeta({ nombre, edad, ciudad }) {
  return (
    <div>
      <h2>{nombre}</h2>
      <p>{edad} años — {ciudad}</p>
    </div>
  );
}
El 99% del código React moderno usa destructuring. Acostumbrate desde el día 1.

3. Props pueden ser cualquier tipo

function Producto({
  nombre,           // string
  precio,           // number
  enStock,          // boolean
  tags,             // array
  vendedor,         // object
  onComprar,        // function (callback!)
  imagen,           // JSX
}) {
  return (
    <div>
      <h2>{nombre}</h2>
      <p>${precio.toFixed(2)}</p>
      {enStock ? <span>En stock</span> : <span>Agotado</span>}
      <p>Tags: {tags.join(', ')}</p>
      <p>Vendedor: {vendedor.nombre}</p>
      {imagen}
      <button onClick={onComprar}>Comprar</button>
    </div>
  );
}

// Uso
<Producto
  nombre="Auriculares"
  precio={49.99}
  enStock={true}
  tags={["audio", "bluetooth"]}
  vendedor={{ nombre: "TechCorp", rating: 4.8 }}
  onComprar={() => console.log('Comprando...')}
  imagen={<img src="/auri.jpg" />}
/>

4. Sintaxis: cuándo usar comillas vs llaves

Tipo de propCómo se pasa
String literalnombre="Ana" — comillas
Expresión JSedad={30} — llaves
Booleano trueactivo o activo={true}
Booleano falseactivo={false} (no se puede omitir)
Variablenombre={mi_variable} — llaves
Objetouser={{ id: 1, name: "Ana" }} — llaves dobles (las externas son JSX, las internas son object literal)

5. Children — el slot universal

children es una prop especial: lo que se pone entre las tags de apertura y cierre del componente.

function Card({ children }) {
  return (
    <div className="card">
      {children}
    </div>
  );
}

// Uso: lo que va entre <Card> y </Card> se pasa como prop children
function App() {
  return (
    <Card>
      <h2>Título</h2>
      <p>Cualquier JSX adentro</p>
      <button>Click</button>
    </Card>
  );
}
children es la pieza más poderosa de React para componentes "contenedor" (modals, cards, layouts). Permite que el componente sea AGNÓSTICO de lo que contiene.

6. Composición: la alternativa pro a herencia

React NO tiene herencia de componentes. Tiene composición: componentes que reciben otros componentes como children o como props.

function Layout({ header, sidebar, children }) {
  return (
    <div className="layout">
      <header>{header}</header>
      <aside>{sidebar}</aside>
      <main>{children}</main>
    </div>
  );
}

function App() {
  return (
    <Layout
      header={<h1>Mi App</h1>}
      sidebar={<Menu />}
    >
      <Dashboard />
    </Layout>
  );
}
Pasar JSX como props se llama "render props" o "slots". Es la solución más usada para componentes genéricos.

7. Props son inmutables (read-only)

Un componente NUNCA debe mutar sus props. Si necesitás cambiarlas, pedile al padre que las pase distintas (en M03 vemos cómo con estado).
// ❌ MAL — mutar props es bug garantizado
function Tarjeta({ usuario }) {
  usuario.nombre = "Cambio";  // ¡NUNCA!
  return <p>{usuario.nombre}</p>;
}

// ✅ BIEN — solo leer props, crear copias locales si querés transformar
function Tarjeta({ usuario }) {
  const nombreUpper = usuario.nombre.toUpperCase();  // copia local
  return <p>{nombreUpper}</p>;
}

8. Valores por defecto

function Boton({ texto = 'Click', color = 'azul', onClick }) {
  return <button style={{ background: color }} onClick={onClick}>{texto}</button>;
}

// Si no pasás texto/color, se usan los defaults
<Boton onClick={...} />                  // texto='Click', color='azul'
<Boton texto="Enviar" />                  // color='azul'
<Boton texto="Salir" color="rojo" />

9. Spread de props

Si tenés un objeto con todas las props, podés expandirlas con ...:

const propsUsuario = { nombre: "Ana", edad: 30, ciudad: "BA" };

// Equivalentes:
<Tarjeta nombre="Ana" edad={30} ciudad="BA" />
<Tarjeta {...propsUsuario} />
Spread de props es útil pero peligroso: si pasás props que el componente no espera, terminan en el DOM como atributos HTML inválidos (warning en consola). Usalo solo cuando sabés exactamente qué hay en el objeto.

10. Props drilling — el problema

Cuando una prop tiene que viajar a través de muchos componentes intermedios para llegar a un hijo lejano:

function App() {
  const usuario = { nombre: "Ana" };
  return <Page usuario={usuario} />;
}

function Page({ usuario }) {           // ← solo lo pasa
  return <Header usuario={usuario} />;
}

function Header({ usuario }) {         // ← solo lo pasa
  return <Nav usuario={usuario} />;
}

function Nav({ usuario }) {            // ← solo lo pasa
  return <UserMenu usuario={usuario} />;
}

function UserMenu({ usuario }) {       // ← acá SÍ se usa
  return <span>Hola, {usuario.nombre}</span>;
}

Esto es props drilling: cada componente intermedio tiene que declarar y pasar una prop que no usa. Es código frágil y verboso.

Soluciones (las vemos más adelante):
  • Composición (M02 mismo): hacer que el componente padre arme el JSX completo.
  • useContext (M07): estado compartido en un subárbol.
  • Estado global con Zustand (M11): cuando muchas partes lo necesitan.

11. Mini-ejemplo completo: lista de productos

// src/components/Producto.jsx
function Producto({ nombre, precio, descuento = 0 }) {
  const precioFinal = precio * (1 - descuento / 100);
  return (
    <article className="producto">
      <h3>{nombre}</h3>
      {descuento > 0 ? (
        <p>
          <s>${precio}</s> ${precioFinal.toFixed(2)}
          <span> (-{descuento}%)</span>
        </p>
      ) : (
        <p>${precio}</p>
      )}
    </article>
  );
}

// src/App.jsx
function App() {
  return (
    <main>
      <h1>Catálogo</h1>
      <Producto nombre="Mouse" precio={25} />
      <Producto nombre="Teclado" precio={80} descuento={15} />
      <Producto nombre="Monitor" precio={400} descuento={20} />
    </main>
  );
}
Un componente, 3 instancias, 3 outputs distintos. Esa es la magia: la lógica de render se escribe una vez; las diferencias vienen de las props.

13. Errores comunes con props

Mutar props: props.usuario.nombre = ... rompe React. Tratá props como read-only.
Pasar booleano sin llaves correctamente: enStock="false" es un STRING "false" (truthy!). Para falso usá enStock={false}.
Devolver objetos directamente al renderizar: {usuario} falla con "Objects are not valid as React child". Renderizá propiedades, no objetos completos.
Props drilling sin necesidad: si Layout no usa usuario, no debería declararlo. Reorganizá con composición o context.
Olvidar destructurar y usar props.props.x: ojo con el typo. function X(props) + props.x, o function X({ x }) + x.

✅ Checkpoint

1. ¿Qué son las props y cómo se pasan?

Son los datos que un componente padre pasa al hijo, equivalente a argumentos de función. Se pasan como atributos del componente: <Hijo nombre="Ana" edad={30} />. Strings usan comillas, expresiones JS usan llaves.

2. ¿Qué es children?

Una prop especial que contiene lo que va ENTRE las tags del componente. Permite construir componentes "contenedor" (Card, Modal, Layout) agnósticos de su contenido. Es la base de composición.

3. ¿Por qué NO mutar props?

Porque React asume que las props son inmutables — un componente debe poder re-renderizarse con las mismas props y obtener el mismo output. Mutar rompe esa garantía, causa bugs sutiles y previene optimizaciones (memoization).

4. ¿Qué es props drilling y cómo se resuelve?

Cuando una prop atraviesa varios componentes intermedios solo para llegar a un descendiente lejano. Soluciones: (1) composición — hacer que el padre arme JSX completo, (2) useContext para estado compartido en subárbol, (3) Zustand u otro store global para datos usados en muchos lugares.

5. ¿Diferencia entre nombre="Ana" y nombre={"Ana"}?

Ninguna funcional. La primera usa comillas (sintaxis abreviada para strings literales). La segunda usa llaves con expresión JS. Por convención: comillas para strings literales, llaves para expresiones, variables y otros tipos.

6. ¿Cómo pasarías un componente entero como prop?

Usando JSX entre llaves: <Layout sidebar={<Menu />} />. Si va dentro del cuerpo del componente, podés usar children: <Layout><Menu /></Layout>. Esto se llama "render props" o "slots".
