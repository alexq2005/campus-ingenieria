Respondé sin mirar arriba. Cada pregunta te explica el porqué.

1. En una lista que se reordena, ¿por qué key={item.id} es mejor que key={index}?

React usa la key para identificar cada item entre renders. Con key={index}, al reordenar la lista todos los índices cambian de dueño: React cree que cambió todo y aparecen bugs sutiles (inputs que pierden el foco, estado que se mezcla entre filas). Con IDs estables, detecta que es el mismo item movido de lugar.

2. Sin segundo argumento, ¿cuándo corre useEffect(() => { console.log('render'); });?

Son tres casos distintos: sin array → después de cada render; array vacío [] → solo al montar; array con deps [id] → cada vez que alguna dep cambia. Y la regla es explicitar siempre las dependencias — la regla de ESLint react-hooks/exhaustive-deps te avisa cuál te falta.

3. ¿Por qué este código no re-renderiza?

const [users, setUsers] = useState([]);
users.push(nuevo);
setUsers(users);
El estado en React es inmutable: nunca lo mutes. Hay que crear una copia nueva con setUsers([...users, nuevo]), o mejor setUsers(prev => [...prev, nuevo]), que usa el valor más fresco. Lo mismo para objetos: setUser({ ...user, edad: user.edad + 1 }).
