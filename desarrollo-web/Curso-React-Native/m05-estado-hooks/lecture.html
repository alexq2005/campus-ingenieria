Módulo 05 — Estado & Hooks

Si venís del Curso de React, este es el módulo más fácil de todo el track móvil. La razón es simple y vale la pena que la grabes a fuego: los hooks son exactamente los mismos. No hay versión "RN" de useState ni un useEffect especial para móvil. Es la misma librería react, importada igual, comportándose igual.

💡 El estado y los hooks en RN son los de React. useState, useEffect, useContext, useRef y tus custom hooks se importan desde 'react' (no desde 'react-native') y funcionan idéntico a la web. Lo único que cambia es qué pintás con ese estado: un <Text> en vez de un <p>. Lo nuevo de este módulo son tres hooks extra que RN suma para cosas que solo existen en móvil (tema del sistema, tamaño de pantalla, app en primer/segundo plano).

Recap de useState — con sabor móvil

El patrón es el de siempre: declarás un valor y la función para cambiarlo. Cuando llamás al setter, RN re-renderiza el componente con el valor nuevo. Acá un contador y un toggle, los dos casos clásicos:

import { useState } from 'react';
import { Text, View, Pressable, Switch, StyleSheet } from 'react-native';

export default function Pantalla() {
  const [cuenta, setCuenta] = useState(0);        // número
  const [activo, setActivo] = useState(false);    // booleano (toggle)

  return (
    <View style={styles.container}>
      <Text style={styles.numero}>{cuenta}</Text>

      <Pressable style={styles.boton} onPress={() => setCuenta(cuenta + 1)}>
        <Text style={styles.botonTexto}>Sumar</Text>
      </Pressable>

      <Switch value={activo} onValueChange={setActivo} />
      <Text>{activo ? 'Encendido' : 'Apagado'}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center', gap: 16 },
  numero: { fontSize: 64, fontWeight: 'bold' },
  boton: { backgroundColor: '#a78bfa', paddingVertical: 12, paddingHorizontal: 24, borderRadius: 10 },
  botonTexto: { color: 'white', fontWeight: 'bold' },
});
🔍 Mirá lo que ya reconocés: es el mismo useState del Curso de React M03. El <Switch> de RN es el primo nativo del <input type="checkbox">: en vez de onChange usa onValueChange, y te pasa el booleano directo (no un evento del que sacás e.target.checked).

useEffect — efectos secundarios

useEffect sirve para todo lo que no es "renderizar": cargar datos de una API, suscribirte a algo, arrancar un timer. Igual que en la web, el segundo argumento (el array de dependencias) controla cuándo corre el efecto.

DependenciasCuándo corre el efectoUso típico
[] (vacío)Una sola vez, al montarCargar datos iniciales
[valor]Al montar y cada vez que valor cambiaRe-buscar cuando cambia un filtro
sin arrayEn cada render (¡peligroso!)Casi nunca — suele ser un bug

Cargar datos al montar

El patrón más común: pedís datos cuando la pantalla aparece y los guardás en estado.

import { useState, useEffect } from 'react';
import { Text, View, ActivityIndicator } from 'react-native';

export default function Perfil() {
  const [usuario, setUsuario] = useState(null);

  useEffect(() => {
    fetch('https://api.example.com/usuario/1')
      .then((r) => r.json())
      .then((data) => setUsuario(data));
  }, []);   // ⬅️ array vacío: solo al montar

  if (!usuario) return <ActivityIndicator />;   // spinner mientras carga

  return (
    <View>
      <Text>Hola, {usuario.nombre}</Text>
    </View>
  );
}
<ActivityIndicator> es el spinner de carga nativo de RN. No necesitás CSS ni una librería: es el equivalente móvil a mostrar un "Cargando…" mientras la petición está en vuelo.

La función de cleanup — el detalle que más se olvida

Si tu efecto arranca algo que sigue vivo (un timer, una suscripción, un listener), tenés que apagarlo cuando el componente se desmonta. Para eso, useEffect puede retornar una función de cleanup:

useEffect(() => {
  // arranco un timer que tickea cada segundo
  const id = setInterval(() => {
    setSegundos((s) => s + 1);
  }, 1000);

  // 🧹 cleanup: RN llama esto al desmontar (o antes de re-correr el efecto)
  return () => clearInterval(id);
}, []);
📌 Regla de oro: si en un efecto escribís setInterval, setTimeout, .addEventListener o .subscribe(...), casi siempre necesitás un return () => ... que lo deshaga. Sin cleanup, el timer o la suscripción siguen corriendo aunque la pantalla ya no exista → memory leak.

Lo RN-específico: tres hooks que la web no tiene

Acá empieza lo nuevo. RN agrega hooks para cosas que solo tienen sentido en un celular. Se importan desde 'react-native'.

useColorScheme — ¿modo claro u oscuro?

Te dice si el celular está en modo claro u oscuro (la config del sistema). Devuelve 'light', 'dark' o null, y re-renderiza solo cuando el usuario cambia el tema:

import { useColorScheme, Text, View } from 'react-native';

export default function Tarjeta() {
  const tema = useColorScheme();        // 'light' | 'dark' | null
  const esOscuro = tema === 'dark';

  return (
    <View style={{ backgroundColor: esOscuro ? '#111' : '#fff', padding: 20 }}>
      <Text style={{ color: esOscuro ? '#fff' : '#111' }}>
        Modo {esOscuro ? 'oscuro 🌙' : 'claro ☀️'}
      </Text>
    </View>
  );
}

useWindowDimensions — tamaño y rotación

Te da el ancho y alto de la pantalla en tiempo real: cuando el usuario rota el celular, el componente se re-renderiza con los valores nuevos. Ideal para layouts adaptativos.

import { useWindowDimensions, Text, View } from 'react-native';

export default function Layout() {
  const { width, height } = useWindowDimensions();
  const esHorizontal = width > height;     // landscape vs portrait

  return (
    <View style={{ flexDirection: esHorizontal ? 'row' : 'column' }}>
      <Text>Ancho: {Math.round(width)} px</Text>
      <Text>{esHorizontal ? 'Horizontal' : 'Vertical'}</Text>
    </View>
  );
}
💡 Tip: usá useWindowDimensions() y no Dimensions.get('window'). El primero es un hook reactivo (se actualiza al rotar); el segundo te da un valor congelado en el momento de la llamada.

AppState — app en primer o segundo plano

Te avisa cuando el usuario sale de tu app (la manda al fondo) o vuelve a ella. Útil para pausar un video, revalidar datos al volver, o cortar conexiones cuando la app no está visible. No es un hook "de una", se usa con useEffect + listener (y por eso es el ejemplo perfecto de cleanup):

import { useState, useEffect } from 'react';
import { AppState, Text } from 'react-native';

export default function EstadoApp() {
  const [estado, setEstado] = useState(AppState.currentState);

  useEffect(() => {
    const sub = AppState.addEventListener('change', (nuevo) => {
      setEstado(nuevo);   // 'active' | 'background' | 'inactive'
    });
    return () => sub.remove();   // 🧹 cleanup: sacamos el listener
  }, []);

  return <Text>La app está: {estado}</Text>;
}

Levantar el estado (lifting state up)

Cuando dos componentes hermanos necesitan compartir un dato, el estado sube al padre común y baja como props. El hijo no guarda el estado: lo recibe, y avisa cambios llamando una función (callback) que el padre le pasó. Esto es idéntico a la web — solo cambian los componentes.

import { useState } from 'react';
import { View, Text, Pressable, StyleSheet } from 'react-native';

// 🔽 Hijo "tonto": no tiene estado, recibe el valor y un callback
function Boton({ etiqueta, onPress }) {
  return (
    <Pressable style={styles.boton} onPress={onPress}>
      <Text style={styles.txt}>{etiqueta}</Text>
    </Pressable>
  );
}

// 🔼 Padre: dueño del estado, lo reparte a los hijos
export default function Contador() {
  const [cuenta, setCuenta] = useState(0);

  return (
    <View style={styles.container}>
      <Text style={styles.numero}>{cuenta}</Text>
      <Boton etiqueta="−" onPress={() => setCuenta((c) => c - 1)} />
      <Boton etiqueta="+" onPress={() => setCuenta((c) => c + 1)} />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center', gap: 12 },
  numero: { fontSize: 56, fontWeight: 'bold' },
  boton: { backgroundColor: '#a78bfa', padding: 14, borderRadius: 10, minWidth: 60, alignItems: 'center' },
  txt: { color: 'white', fontSize: 20, fontWeight: 'bold' },
});
El estado vive en el padre, los datos bajan como props, los avisos suben como callbacks. Fijate que usamos setCuenta((c) => c + 1) (forma funcional) en vez de setCuenta(cuenta + 1): es la forma segura cuando el nuevo valor depende del anterior.

Custom hooks — extraer lógica reutilizable

Cuando un patrón de estado se repite (un toggle, un contador, leer una API), lo sacás a una función que empieza con use y adentro usa otros hooks. Eso es un custom hook: igual a la web, sin nada nuevo. Acá un useToggle que abstrae el clásico abrir/cerrar:

import { useState, useCallback } from 'react';
import { View, Text, Pressable, StyleSheet } from 'react-native';

// 🪝 Custom hook: encapsula la lógica de un booleano que se alterna
function useToggle(inicial = false) {
  const [valor, setValor] = useState(inicial);
  const alternar = useCallback(() => setValor((v) => !v), []);
  return [valor, alternar];
}

export default function Acordeon() {
  const [abierto, alternar] = useToggle(false);   // ⬅️ una línea, lógica reutilizable

  return (
    <View style={styles.box}>
      <Pressable onPress={alternar}>
        <Text style={styles.titulo}>{abierto ? '▼' : '▶'} Detalles</Text>
      </Pressable>
      {abierto && <Text>Contenido que aparece y desaparece.</Text>}
    </View>
  );
}

const styles = StyleSheet.create({
  box: { padding: 20, gap: 8 },
  titulo: { fontSize: 18, fontWeight: 'bold' },
});
📌 Regla de oro de los custom hooks: el nombre tiene que empezar con use (es lo que le permite a React aplicar las reglas de los hooks). Y solo abstraé tras ver el patrón 3 veces — no inventes un hook genérico por un solo uso.

Errores típicos con estado y hooks

Efectos sin cleanup. Arrancás un setInterval o un AppState.addEventListener y no retornás la función que lo deshace. El timer/listener sigue vivo cuando la pantalla ya no existe → memory leak y, peor, setState sobre un componente desmontado.
Mutar el estado en vez de crear una copia. lista.push(item); setLista(lista) NO funciona: React compara por referencia y la referencia no cambió, así que no re-renderiza. Lo correcto es crear un array nuevo: setLista([...lista, item]). Lo mismo con objetos: setUsuario({ ...usuario, nombre: 'Ana' }).
Demasiados useState que deberían ser uno. Si tenés useState para nombre, email y edad que siempre cambian juntos (un formulario), conviene un solo estado objeto: const [form, setForm] = useState({ nombre: '', email: '', edad: 0 }). Menos setters sueltos, más coherencia.

Checkpoint — ¿lo tenés claro?

¿De dónde se importa useState en React Native?

De 'react', igual que en la web — no de 'react-native'. Los hooks de estado son los mismos de React. De 'react-native' se importan los hooks extra de la plataforma (useColorScheme, useWindowDimensions) y los componentes (View, Text).

¿Para qué sirve la función que retorna un useEffect?

Es el cleanup: RN la ejecuta cuando el componente se desmonta (o antes de volver a correr el efecto). Sirve para deshacer lo que el efecto arrancó: clearInterval, clearTimeout, subscription.remove(). Sin ella, timers y suscripciones quedan vivos y generan memory leaks.

¿Por qué lista.push(x); setLista(lista) no re-renderiza?

Porque React detecta cambios comparando referencias, y push muta el mismo array — la referencia no cambia, así que React cree que nada cambió. Hay que pasar un array nuevo: setLista([...lista, x]).

Ejercicios

  1. Escribí un componente con useState que tenga un <Switch>: cuando está encendido muestra "ON 🟢" y cuando está apagado "OFF 🔴".
  2. Hacé un cronómetro: un useEffect con setInterval que sume 1 segundo cada vez. Acordate del return () => clearInterval(id) de cleanup.
  3. Usá useColorScheme para que una <View> cambie de fondo claro/oscuro según el tema del celular. Probalo cambiando el modo en la configuración del sistema.
  4. Con useWindowDimensions, mostrá el ancho de la pantalla y la palabra "Horizontal" o "Vertical" según la orientación. Rotá el celular y verificá que se actualiza.
  5. Extraé un custom hook useContador(inicial) que devuelva { cuenta, sumar, restar, reiniciar } y usalo en un componente. Confirmá que la lógica quedó fuera del componente.

🧠 Autoevaluación

1. En React Native, ¿desde dónde se importa useState?

useState, useEffect y demás vienen de 'react' y funcionan idéntico a la web. De 'react-native' salen los hooks extra de plataforma y los componentes.

2. ¿Qué pasa si un useEffect arranca un setInterval y no retorna una función de cleanup?

Sin return () => clearInterval(id), el timer queda vivo aunque la pantalla ya no exista. Es la causa clásica de memory leaks y de setState sobre componentes desmontados.

3. ¿Cuál de estos hooks es propio de React Native (no existe en la web)?

useColorScheme (junto a useWindowDimensions y AppState) es de 'react-native', para cosas que solo existen en móvil. useState y useContext son de React y se comparten con la web.
