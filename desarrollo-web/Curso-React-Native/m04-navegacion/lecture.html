Módulo 04 — Navegación

Hasta acá tus apps eran una sola pantalla. Pero una app real tiene varias: una lista de productos que abre el detalle, un menú con secciones, pestañas abajo. En este módulo aprendés a moverte entre pantallas con React Navigation, la librería estándar del ecosistema.

¿Por qué una librería de navegación?

En la web el navegador te da la navegación gratis: URLs, el botón de "atrás", el historial. En móvil no existe nada de eso — no hay barra de direcciones ni botón universal de retroceso. Alguien tiene que manejar qué pantalla se muestra, cómo se anima la transición, y qué pasa cuando el usuario quiere volver. Esa es la tarea de React Navigation.

React Navigation es el estándar de facto: lo usa la enorme mayoría de las apps RN y viene integrado con Expo. No tiene rival serio para la mayoría de los casos.

Instalación

Necesitás el paquete núcleo (native), un navegador concreto (acá el stack nativo) y las dependencias nativas que Expo gestiona por vos:

# 1. Núcleo de React Navigation
npm install @react-navigation/native

# 2. El navegador que vamos a usar: stack nativo
npm install @react-navigation/native-stack

# 3. Dependencias nativas (Expo elige la versión compatible)
npx expo install react-native-screens react-native-safe-area-context
💡 Usá npx expo install (no npm install) para las dependencias nativas. Expo conoce qué versión de cada paquete nativo es compatible con tu versión de Expo y la instala exacta. Con npm install podrías traer una versión que rompe el build nativo.

El contenedor raíz: <NavigationContainer>

Todo el sistema de navegación vive dentro de un único <NavigationContainer>. Es el componente que mantiene el estado de navegación (qué pantalla está activa, el historial) y lo comparte con todos los navegadores que pongas adentro.

📌 Un solo <NavigationContainer> por app, en la raíz. Lo envolvés una vez, arriba de todo. Adentro pueden anidar muchos navegadores, pero el contenedor es uno solo. Si usás Expo Router, el contenedor lo pone el framework por vos — pero conviene entender qué hace.

Stack Navigator — pantallas apiladas

El patrón más común. Imaginá una pila de cartas: cada pantalla nueva se apila encima de la anterior, y al volver, se saca la de arriba y reaparece la de abajo. Así funciona "entrar al detalle y volver".

🔍 Es como el historial del navegador. Navegás de Lista a Detalle: Detalle queda arriba, Lista debajo. Tocás "atrás": se descarta Detalle y volvés a Lista — exactamente donde estabas, con el scroll y todo intacto.

Se crea con createNativeStackNavigator(), que te da dos componentes: <Stack.Navigator> (el contenedor de la pila) y <Stack.Screen> (cada pantalla registrada):

import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';

const Stack = createNativeStackNavigator();

export default function App() {
  return (
    <NavigationContainer>
      <Stack.Navigator>
        <Stack.Screen name="Lista" component={ListaScreen} />
        <Stack.Screen
          name="Detalle"
          component={DetalleScreen}
          options={{ title: 'Detalle del ítem' }}
        />
      </Stack.Navigator>
    </NavigationContainer>
  );
}

Cosas a notar:

ElementoQué hace
name="Lista"El nombre con el que navegás a esa pantalla (es el "destino")
component={ListaScreen}El componente que se renderiza en esa pantalla
options={{ title }}Configura el header automático (título, botones, color)
El headerEl stack te dibuja la barra superior solo, con el botón "atrás" incluido
💡 El header es automático. Cuando navegás a una segunda pantalla, el stack agrega arriba una barra con el título y una flecha de "atrás" funcional. No tenés que dibujarla vos. La primera pantalla muestra su name como título salvo que lo cambies con options.

Cómo navegar: navigation.navigate y goBack

Cada componente que registrás como component de un <Stack.Screen> recibe automáticamente una prop navigation. Con ella te movés:

import { View, Text, Pressable, StyleSheet } from 'react-native';

function ListaScreen({ navigation }) {
  return (
    <View style={styles.container}>
      <Text style={styles.titulo}>Pantalla Lista</Text>
      <Pressable
        style={styles.boton}
        onPress={() => navigation.navigate('Detalle')}
      >
        <Text style={styles.botonTexto}>Ir al Detalle</Text>
      </Pressable>
    </View>
  );
}

function DetalleScreen({ navigation }) {
  return (
    <View style={styles.container}>
      <Text style={styles.titulo}>Pantalla Detalle</Text>
      <Pressable style={styles.boton} onPress={() => navigation.goBack()}>
        <Text style={styles.botonTexto}>Volver</Text>
      </Pressable>
    </View>
  );
}
MétodoQué hace
navigation.navigate('Detalle')Va a la pantalla llamada Detalle (la apila encima)
navigation.goBack()Vuelve a la pantalla anterior (saca la de arriba)
navigation.push('Detalle')Apila otra instancia de Detalle, aunque ya estés en una
Confundir push con navigate. navigate('Detalle') es inteligente: si ya estás en Detalle, no apila otra — se queda donde está (o solo actualiza los params). push('Detalle') siempre apila una nueva instancia encima. Para "ver el siguiente producto sin volver" querés push; para navegación normal querés navigate.

Pasar datos entre pantallas: params

Navegar está bueno, pero casi siempre querés llevarte datos: "abrí el detalle del producto 42". Eso se hace con un segundo argumento (un objeto) en navigate:

// En la Lista: navego y le paso el id
navigation.navigate('Detalle', { id: 42, nombre: 'Teclado mecánico' });

Y en la pantalla destino los leés desde la prop route, en route.params:

function DetalleScreen({ route, navigation }) {
  const { id, nombre } = route.params;   // ⬅️ acá llegan los datos

  return (
    <View style={styles.container}>
      <Text style={styles.titulo}>{nombre}</Text>
      <Text>ID del producto: {id}</Text>
      <Pressable style={styles.boton} onPress={() => navigation.goBack()}>
        <Text style={styles.botonTexto}>Volver</Text>
      </Pressable>
    </View>
  );
}
📌 Dos props clave en cada pantalla: navigation (para moverte) y route (para leer route.params, los datos que te mandaron). Las dos llegan solas, no las pasás vos.
Pasar funciones o estado complejo por params. Los params deberían ser datos serializables y livianos: un id, un texto, un número. Pasar una función ({ onSave: miFuncion }) o un objeto enorme genera warnings y rompe cosas como el guardado de estado. Si dos pantallas necesitan compartir lógica o estado grande, usá estado global (Context, Zustand, Redux) — no los params de navegación.

Ejemplo completo: Lista → Detalle

Juntemos todo en una app de dos pantallas. La lista muestra ítems; tocar uno abre el detalle pasándole su id y nombre:

import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { View, Text, Pressable, StyleSheet } from 'react-native';

const Stack = createNativeStackNavigator();

const PRODUCTOS = [
  { id: 1, nombre: 'Teclado mecánico' },
  { id: 2, nombre: 'Mouse inalámbrico' },
  { id: 3, nombre: 'Monitor 27"' },
];

function ListaScreen({ navigation }) {
  return (
    <View style={styles.container}>
      {PRODUCTOS.map((p) => (
        <Pressable
          key={p.id}
          style={styles.item}
          onPress={() => navigation.navigate('Detalle', { id: p.id, nombre: p.nombre })}
        >
          <Text style={styles.itemTexto}>{p.nombre}</Text>
        </Pressable>
      ))}
    </View>
  );
}

function DetalleScreen({ route, navigation }) {
  const { id, nombre } = route.params;
  return (
    <View style={styles.container}>
      <Text style={styles.titulo}>{nombre}</Text>
      <Text>Producto #{id}</Text>
      <Pressable style={styles.boton} onPress={() => navigation.goBack()}>
        <Text style={styles.botonTexto}>← Volver a la lista</Text>
      </Pressable>
    </View>
  );
}

export default function App() {
  return (
    <NavigationContainer>
      <Stack.Navigator>
        <Stack.Screen name="Lista" component={ListaScreen} options={{ title: 'Productos' }} />
        <Stack.Screen name="Detalle" component={DetalleScreen} />
      </Stack.Navigator>
    </NavigationContainer>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center', gap: 14, padding: 20 },
  titulo: { fontSize: 28, fontWeight: 'bold' },
  item: { backgroundColor: '#ede9fe', paddingVertical: 14, paddingHorizontal: 20, borderRadius: 10, width: '100%' },
  itemTexto: { fontSize: 16, color: '#5b21b6' },
  boton: { backgroundColor: '#a78bfa', paddingVertical: 12, paddingHorizontal: 24, borderRadius: 10, marginTop: 16 },
  botonTexto: { color: 'white', fontWeight: 'bold' },
});
🔍 Mirá lo que ya reconocés: el .map() sobre PRODUCTOS con su key, los componentes de función, las props… es React puro. Lo único nuevo es navigation/route y el registro de pantallas.

Otros navegadores: Tabs y Drawer

El stack es para "entrar y volver". Pero hay otros dos patrones de navegación muy comunes, y cada uno tiene su navegador:

NavegadorCómo se veCuándo usarlo
Stack
@react-navigation/native-stack		Pantallas apiladas con header y "atrás"Flujos jerárquicos: lista → detalle → editar
Bottom Tabs
@react-navigation/bottom-tabs		Barra de pestañas abajo (Inicio, Buscar, Perfil)3–5 secciones principales entre las que se salta seguido
Drawer
@react-navigation/drawer		Menú lateral que se desliza desde el bordeMuchas secciones secundarias / config; cuando no entran en tabs
La API es la misma para todos: cada uno te da un createXNavigator() que devuelve <X.Navigator> y <X.Screen>. Si entendiste el stack, entendiste los tres. Cambia el aspecto visual, no la forma de usarlo. (Tabs y Drawer requieren instalar su paquete; el drawer además pide react-native-gesture-handler y react-native-reanimated.)

Ejemplo de tabs (mismo molde que el stack):

import { createBottomTabNavigator } from '@react-navigation/bottom-tabs';

const Tab = createBottomTabNavigator();

function App() {
  return (
    <NavigationContainer>
      <Tab.Navigator>
        <Tab.Screen name="Inicio" component={InicioScreen} />
        <Tab.Screen name="Perfil" component={PerfilScreen} />
      </Tab.Navigator>
    </NavigationContainer>
  );
}

Anidar navegadores

Las apps reales combinan navegadores. El patrón clásico: tabs abajo, y dentro de cada tab, su propio stack para entrar al detalle sin perder la barra de pestañas.

💡 Anidar = poner un navegador como component de la pantalla de otro. Una <Tab.Screen> puede tener como componente, en vez de una pantalla simple, un Stack Navigator entero. Así, dentro de la tab "Inicio" navegás de Lista a Detalle (con su header y "atrás") mientras las pestañas de abajo siguen visibles. 
const Tab = createBottomTabNavigator();
const Stack = createNativeStackNavigator();

// Un stack: Lista → Detalle
function InicioStack() {
  return (
    <Stack.Navigator>
      <Stack.Screen name="Lista" component={ListaScreen} />
      <Stack.Screen name="Detalle" component={DetalleScreen} />
    </Stack.Navigator>
  );
}

export default function App() {
  return (
    <NavigationContainer>
      <Tab.Navigator>
        {/* La tab "Inicio" ES un stack entero */}
        <Tab.Screen name="Inicio" component={InicioStack} />
        <Tab.Screen name="Perfil" component={PerfilScreen} />
      </Tab.Navigator>
    </NavigationContainer>
  );
}

Errores típicos

Olvidar envolver con <NavigationContainer>. Sin él, tirás un error tipo "Couldn't find a navigation object" apenas usás navigation o un <Stack.Screen>. El contenedor va en la raíz, una sola vez.
Pasar funciones por params. navigate('X', { onDone: fn }) parece práctico pero está desaconsejado: rompe la serialización del estado de navegación. Para compartir lógica entre pantallas, usá estado global, no params.
Confundir push con navigate. navigate no apila si ya estás en esa pantalla; push siempre apila una nueva. Usar el equivocado te deja con pantallas duplicadas en el historial (o sin la nueva instancia que esperabas).
⚠️ Reiniciá el bundler tras instalar paquetes nativos. Después de instalar react-native-screens y compañía, cortá Expo (Ctrl+C) y volvé a correr npx expo start -c (el -c limpia la caché). Si no, podés ver errores raros de módulos nativos que "no existen".

Checkpoint — ¿lo tenés claro?

¿Para qué sirve <NavigationContainer> y cuántos necesitás?

Es el contenedor raíz que mantiene y comparte el estado de navegación (pantalla activa, historial). Necesitás uno solo, en la raíz de la app, envolviendo a todos los navegadores. Anidás navegadores adentro, pero el contenedor es único.

Estás en la Lista y querés abrir el Detalle del producto con id: 7. ¿Cómo navegás y cómo lo leés?

Navegás con navigation.navigate('Detalle', { id: 7 }). En DetalleScreen lo leés desde la prop route: const { id } = route.params;. Las props navigation y route llegan automáticamente a cada pantalla registrada en un <Stack.Screen>.

¿Cuándo usás un Tab Navigator y cuándo un Stack?

Stack para flujos jerárquicos donde entrás y volvés (lista → detalle), con header y botón "atrás" automáticos. Tabs para 3–5 secciones principales entre las que el usuario salta seguido (Inicio, Buscar, Perfil). Y se combinan: tabs abajo, con un stack adentro de cada una.

Ejercicios

  1. Instalá React Navigation (@react-navigation/native, @react-navigation/native-stack y las dependencias con npx expo install) y envolvé tu app con <NavigationContainer>.
  2. Armá el ejemplo Lista → Detalle de dos pantallas. Verificá que el header aparece solo y que el botón "atrás" funciona.
  3. En la Lista, pasá el nombre y un precio por params, y mostralos en el Detalle leyendo route.params.
  4. Agregá una tercera pantalla "Editar" a la que se llega desde el Detalle. Probá navigation.navigate('Editar') y volvé con goBack().
  5. Convertí la app a un Bottom Tab Navigator con dos pestañas ("Productos" y "Perfil"), y poné el flujo Lista → Detalle como un Stack dentro de la pestaña "Productos".

🧠 Autoevaluación

1. ¿Cuántos <NavigationContainer> debe tener una app y dónde va?

El <NavigationContainer> es único y va en la raíz. Mantiene el estado de navegación y lo comparte con todos los navegadores que anides adentro.

2. Navegaste con navigation.navigate('Detalle', { id: 7 }). ¿Cómo leés ese id en la pantalla Detalle?

Los datos pasados al navegar llegan en route.params. La prop route (igual que navigation) llega automáticamente a cada pantalla registrada.

3. Querés 4 secciones principales (Inicio, Buscar, Mensajes, Perfil) con una barra abajo para saltar entre ellas. ¿Qué navegador usás?

Las tabs (bottom tabs) son ideales para 3–5 secciones principales entre las que se salta seguido. El stack es para flujos de entrar/volver (lista → detalle).
