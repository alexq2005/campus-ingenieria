Módulo 07 — Datos & Persistencia

Una app que no habla con el mundo es un cascarón. En este módulo tu app empieza a traer datos de internet (igual que en la web, con fetch y async/await) y a recordar cosas entre sesiones con AsyncStorage — el equivalente móvil de localStorage, pero con una diferencia clave que vamos a martillar hasta el cansancio: es asíncrono.

Traer datos de una API: es lo mismo que en la web

💡 En React Native el fetch es idéntico al de la web. Misma función fetch(), mismo async/await, mismo response.json(). No hay API nueva que aprender. Lo único que cambia es dónde mostrás el resultado: en vez de un <div>, va en un <Text> o una <FlatList>.

El patrón que vas a repetir en CADA pantalla que carga datos se llama "los 3 estados": mientras cargás mostrás un spinner (loading), si algo se rompe mostrás un mensaje (error), y cuando llega todo bien mostrás el contenido (data). Se modela con useState + useEffect:

import { useState, useEffect } from 'react';
import { View, Text, ActivityIndicator, StyleSheet } from 'react-native';

export default function Perfil() {
  const [data, setData] = useState(null);      // ⬅️ los datos cuando lleguen
  const [cargando, setCargando] = useState(true); // ⬅️ true mientras esperamos
  const [error, setError] = useState(null);     // ⬅️ mensaje si algo falla

  useEffect(() => {
    async function traer() {
      try {
        const res = await fetch('https://api.github.com/users/expo');
        if (!res.ok) throw new Error('Respuesta ' + res.status);
        const json = await res.json();
        setData(json);
      } catch (e) {
        setError(e.message);
      } finally {
        setCargando(false);   // ⬅️ pase lo que pase, dejamos de cargar
      }
    }
    traer();
  }, []);   // ⬅️ [] = corre una sola vez, al montar

  if (cargando) return <ActivityIndicator size="large" />;
  if (error) return <Text style={styles.error}>Ups: {error}</Text>;

  return (
    <View style={styles.container}>
      <Text style={styles.titulo}>{data.name}</Text>
      <Text>{data.public_repos} repositorios públicos</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center', gap: 8 },
  titulo: { fontSize: 24, fontWeight: 'bold' },
  error: { color: 'crimson', textAlign: 'center', marginTop: 40 },
});
🔍 Mirá lo que ya reconocés: useState, useEffect con array de dependencias vacío, try/catch/finally, await fetch… es exactamente lo que hacías en el Curso de React. Lo único nuevo es <ActivityIndicator>, que es el spinner nativo.

El spinner: <ActivityIndicator>

<ActivityIndicator> es la ruedita giratoria nativa de carga. No necesitás librerías ni GIFs: ya viene en react-native. Acepta size="small" / "large" y color="#...". En iOS se ve como el spinner de Apple y en Android como el de Material — porque es nativo en cada plataforma. 
<ActivityIndicator size="large" color="#a78bfa" />
📌 Siempre manejá los 3 estados. Una pantalla que solo contempla el caso "todo salió bien" se va a ver congelada o en blanco cuando la red sea lenta o falle. loading + error + data no es opcional: es lo que separa una app amateur de una profesional.

AsyncStorage: el "localStorage del móvil"

En la web guardabas cosas en localStorage para que sobrevivan al recargar la página. En el móvil el equivalente es AsyncStorage: un almacén clave→valor que persiste entre sesiones, aunque el usuario cierre la app.

1. Instalalo (no viene incluido en RN):
npx expo install @react-native-async-storage/async-storage
2. Importalo y usalo — pero con await en TODO:
import AsyncStorage from '@react-native-async-storage/async-storage';

// Guardar un string
await AsyncStorage.setItem('nombre', 'Alex');

// Leer (devuelve el string, o null si no existe)
const nombre = await AsyncStorage.getItem('nombre');

// Borrar
await AsyncStorage.removeItem('nombre');
📌 La diferencia que lo cambia todo: en la web localStorage es sincrónico (localStorage.getItem('x') te devuelve el valor en la misma línea). AsyncStorage es asíncrono: cada operación devuelve una promesa, así que va con await (o .then()) y dentro de una función async. Olvidarte del await es el error #1 con AsyncStorage.

Guardar objetos: JSON.stringify / JSON.parse

Igual que localStorage, AsyncStorage solo guarda strings. Si querés guardar un objeto o un array, lo convertís a texto al guardar y lo reconstruís al leer:

const usuario = { nombre: 'Alex', edad: 28, favoritos: ['rn', 'expo'] };

// Guardar: objeto → string
await AsyncStorage.setItem('usuario', JSON.stringify(usuario));

// Leer: string → objeto (ojo: puede ser null si nunca se guardó)
const crudo = await AsyncStorage.getItem('usuario');
const recuperado = crudo != null ? JSON.parse(crudo) : null;

console.log(recuperado.favoritos[0]);  // 'rn'
Guardar un objeto sin stringify. setItem('u', usuario) termina guardando el string "[object Object]" — un valor inútil. Siempre JSON.stringify al guardar y JSON.parse al leer.

Caché offline básico: leer local primero, luego refrescar de la red

💡 La estrategia "stale-while-revalidate" en su forma más simple: al abrir la pantalla, mostrá al instante lo último que guardaste en AsyncStorage (aunque sea viejo), y en paralelo pedí los datos frescos a la red. Cuando lleguen, actualizás la pantalla y reguardás el caché. Resultado: la app se siente rápida y funciona aunque no haya señal. 
import { useState, useEffect } from 'react';
import { View, Text, ActivityIndicator, StyleSheet } from 'react-native';
import AsyncStorage from '@react-native-async-storage/async-storage';

const CLAVE = 'cache_perfil';
const URL = 'https://api.github.com/users/expo';

export default function Perfil() {
  const [data, setData] = useState(null);
  const [cargando, setCargando] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    async function init() {
      // 1. Mostrar el caché viejo al instante (si existe)
      try {
        const cache = await AsyncStorage.getItem(CLAVE);
        if (cache != null) {
          setData(JSON.parse(cache));
          setCargando(false);   // ⬅️ ya hay algo en pantalla
        }
      } catch (e) { /* caché corrupto: lo ignoramos y vamos a la red */ }

      // 2. Refrescar de la red en paralelo
      try {
        const res = await fetch(URL);
        if (!res.ok) throw new Error('Respuesta ' + res.status);
        const json = await res.json();
        setData(json);
        await AsyncStorage.setItem(CLAVE, JSON.stringify(json)); // reguardar
      } catch (e) {
        setError(e.message);   // si falla la red, igual quedó el caché viejo
      } finally {
        setCargando(false);
      }
    }
    init();
  }, []);

  if (cargando && data == null) return <ActivityIndicator size="large" />;

  return (
    <View style={styles.container}>
      {data && <Text style={styles.titulo}>{data.name}</Text>}
      {error && <Text style={styles.error}>Sin conexión — mostrando datos guardados</Text>}
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center', gap: 8 },
  titulo: { fontSize: 24, fontWeight: 'bold' },
  error: { color: '#b45309', fontSize: 12 },
});
💡 Fijate el detalle: solo mostramos el spinner cuando cargando && data == null. Si ya teníamos caché, NO bloqueamos la pantalla con el spinner: el usuario ve contenido de inmediato y el refresco ocurre en silencio.

Un custom hook: useAsyncStorage

Leer y escribir AsyncStorage en cada pantalla a mano es repetitivo. Como ya sabés de React, lo encapsulamos en un custom hook que expone el valor con estado y una función para actualizarlo:

import { useState, useEffect, useCallback } from 'react';
import AsyncStorage from '@react-native-async-storage/async-storage';

// Devuelve [valor, setValor, cargando] — como useState, pero persistido
export function useAsyncStorage(clave, valorInicial) {
  const [valor, setValor] = useState(valorInicial);
  const [cargando, setCargando] = useState(true);

  // Al montar: leer lo guardado
  useEffect(() => {
    (async () => {
      try {
        const crudo = await AsyncStorage.getItem(clave);
        if (crudo != null) setValor(JSON.parse(crudo));
      } catch (e) {
        console.warn('useAsyncStorage leer:', e);
      } finally {
        setCargando(false);
      }
    })();
  }, [clave]);

  // Guardar: actualiza estado Y persiste
  const guardar = useCallback(async (nuevo) => {
    try {
      setValor(nuevo);
      await AsyncStorage.setItem(clave, JSON.stringify(nuevo));
    } catch (e) {
      console.warn('useAsyncStorage guardar:', e);
    }
  }, [clave]);

  return [valor, guardar, cargando];
}

Y se usa casi igual que useState — pero el valor sobrevive al cierre de la app:

function Ajustes() {
  const [tema, setTema, cargando] = useAsyncStorage('tema', 'claro');

  if (cargando) return <ActivityIndicator />;

  return (
    <Pressable onPress={() => setTema(tema === 'claro' ? 'oscuro' : 'claro')}>
      <Text>Tema actual: {tema} (tocá para cambiar)</Text>
    </Pressable>
  );
}
🔍 La regla de los 3 usos: no abstraés un hook "por si acaso". Pero cuando ves que estás copiando el mismo bloque de getItem/setItem en tres pantallas, ahí sí: extraés useAsyncStorage y limpiás las tres.

Errores típicos con datos & persistencia

Tratar AsyncStorage como sincrónico. const v = AsyncStorage.getItem('x') NO te da el valor: te da una promesa. v va a ser un objeto Promise, no tu dato. Siempre await dentro de una función async.
No manejar loading ni error. Si solo escribís el caso feliz, la pantalla queda en blanco mientras carga y crashea (o se congela) cuando la red falla. Los 3 estados van siempre.
Guardar objetos sin JSON.stringify. AsyncStorage solo guarda strings; un objeto crudo se convierte en "[object Object]". stringify al guardar, parse al leer.
⚠️ getItem puede devolver null. Si la clave nunca se guardó, obtenés null. Hacer JSON.parse(null) da null (no rompe), pero leer una propiedad de eso sí. Chequeá != null antes de usar.
🚫 AsyncStorage NO es para secretos. No guardes contraseñas ni tokens sensibles ahí: no está cifrado. Para datos sensibles se usa expo-secure-store (lo vas a ver más adelante). AsyncStorage es para preferencias, caché y estado de la UI.

Checkpoint — ¿lo tenés claro?

¿En qué se diferencia AsyncStorage de localStorage?

En que AsyncStorage es asíncrono: cada operación devuelve una promesa y se usa con await dentro de una función async. localStorage de la web es sincrónico (te devuelve el valor en la misma línea). En lo demás son parecidos: ambos guardan pares clave→valor como strings y persisten entre sesiones.

¿Cómo guardás un objeto en AsyncStorage y lo recuperás?

Al guardar: await AsyncStorage.setItem('clave', JSON.stringify(objeto)). Al leer: const crudo = await AsyncStorage.getItem('clave') y luego const obj = crudo != null ? JSON.parse(crudo) : null. AsyncStorage solo guarda strings, por eso hay que serializar/deserializar.

¿Qué es el patrón de los 3 estados y por qué importa?

Son loading (mostrás un <ActivityIndicator> mientras esperás), error (mostrás un mensaje si el fetch falla) y data (mostrás el contenido cuando llega). Importa porque sin él la pantalla queda en blanco con redes lentas y crashea cuando la API falla — es la diferencia entre una app robusta y una frágil.

🧠 Autoevaluación

1. ¿Cuál es la diferencia clave entre AsyncStorage y el localStorage de la web?

AsyncStorage es asíncrono — getItem/setItem devuelven promesas. Por eso van con await dentro de funciones async, a diferencia del localStorage sincrónico de la web.

2. Querés guardar el objeto { nombre: 'Alex' } en AsyncStorage. ¿Qué hacés?

AsyncStorage solo guarda strings. Hay que serializar con JSON.stringify al guardar y reconstruir con JSON.parse al leer. Guardar el objeto crudo termina como "[object Object]".

3. ¿Qué describe el patrón "de los 3 estados" al cargar datos de una API?

Son los tres estados de una carga: mostrás <ActivityIndicator> mientras esperás, un mensaje si falla, y el contenido cuando llega. Cubrir los tres es lo que hace una pantalla robusta.
