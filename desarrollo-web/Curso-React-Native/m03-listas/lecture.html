Módulo 03 — Listas Performantes

Casi toda app móvil es, en el fondo, una lista: chats, contactos, feed de un social, productos de una tienda, notificaciones. Mostrar 10 elementos es trivial. Mostrar 10.000 sin que la app se trabe es donde se separan los principiantes de quienes entienden cómo funciona el renderizado en móvil. Este módulo es sobre eso.

El problema: .map() + ScrollView

Viniendo de React, tu instinto es resolver una lista con .map(). Y para que se pueda scrollear, la metés dentro de un <ScrollView>. Funciona... hasta que la lista crece:

import { ScrollView, View, Text } from 'react-native';

export default function Feed({ posts }) {   // posts = 5000 items
  return (
    <ScrollView>
      {posts.map((post) => (
        <View key={post.id}>
          <Text>{post.titulo}</Text>
        </View>
      ))}
    </ScrollView>
  );
}
⚠️ Esto monta los 5000 elementos de golpe. Aunque solo veas 8 en pantalla, RN crea las 5000 vistas nativas, reserva memoria para todas y las mantiene vivas. Resultado: arranque lentísimo, scroll a tirones y, en celulares de gama baja, la app directamente se cierra por falta de memoria.
💡 El <ScrollView> renderiza TODO su contenido de una sola vez. Es perfecto para contenido finito y conocido (un formulario largo, una pantalla "Acerca de"). Es la herramienta equivocada para listas de datos que pueden ser largas o vienen de una API.

La solución: <FlatList>

💡 <FlatList> usa virtualización: solo renderiza los elementos que están (o están por estar) en pantalla. A medida que scrolleás, monta los que entran y desmonta los que salen, reciclando vistas. Así muestra 100.000 ítems consumiendo la memoria de los ~10 visibles.

En vez de hacer el .map() vos, le pasás los datos y una función que dice cómo dibujar un ítem. FlatList decide cuándo dibujarlo:

import { FlatList, View, Text } from 'react-native';

export default function Feed({ posts }) {
  return (
    <FlatList
      data={posts}
      keyExtractor={(item) => item.id}
      renderItem={({ item }) => (
        <View>
          <Text>{item.titulo}</Text>
        </View>
      )}
    />
  );
}

Las tres props que SIEMPRE vas a usar

PropQué recibePara qué
dataUn arrayLa fuente de datos a recorrer
renderItemFunción ({ item }) => JSXCómo dibujar un solo elemento
keyExtractorFunción (item) => stringDar a cada ítem una key única y estable
Fijate en renderItem: recibe un objeto y vos desestructurás { item } de adentro. Un error clásico es escribir renderItem={(item) => ...} (sin llaves) y después preguntarse por qué item.titulo es undefined — porque ahí item es el objeto completo, no el elemento. El objeto también trae index y separators si los necesitás: ({ item, index }).
📌 keyExtractor no es opcional en la práctica. Es lo que le permite a FlatList saber qué ítem es cuál cuando la lista cambia (se agrega, borra o reordena algo). Devolvé siempre un identificador único y estable del dato (un id de base de datos, no el índice).

Props que mejoran cualquier lista real

Una lista de producción rara vez es solo ítems pelados. Estas tres props cubren el 90% de los casos:

PropQué hace
ItemSeparatorComponentComponente dibujado entre ítems (una línea divisoria). No aparece antes del primero ni después del último.
ListEmptyComponentQué mostrar cuando data está vacío (un mensaje "No hay nada todavía"). Sin esto, la lista vacía es una pantalla en blanco.
ListHeaderComponent / ListFooterComponentContenido fijo arriba (un título, una barra de búsqueda) o abajo (un spinner de "cargando más"). Scrollean con la lista.
🔍 Pensalo como un sándwich: ListHeaderComponent es la tapa de arriba, renderItem repetido es el relleno, ItemSeparatorComponent son las rebanadas que separan cada capa, y ListFooterComponent es la tapa de abajo. Todo se scrollea junto, como una sola pieza.

Interacciones: scroll infinito y pull-to-refresh

Scroll infinito — onEndReached

Cuando el usuario se acerca al final, cargás más datos (la "página" siguiente de la API). Dos props trabajan juntas:

PropQué hace
onEndReachedFunción que se dispara cuando el scroll llega cerca del final.

Pull-to-refresh — refreshing + onRefresh

El gesto de "tirar hacia abajo desde arriba para recargar". FlatList lo trae integrado con dos props:

PropQué hace
onRefreshFunción que corre cuando el usuario tira hacia abajo. Acá recargás los datos.
refreshingBooleano. Mientras sea true, se muestra el spinner de carga. Lo controlás vos con estado.
 
import { useState } from 'react';
import { FlatList } from 'react-native';

export default function Feed() {
  const [posts, setPosts] = useState([]);
  const [refrescando, setRefrescando] = useState(false);

  async function recargar() {
    setRefrescando(true);
    const data = await traerPosts();   // tu fetch a la API
    setPosts(data);
    setRefrescando(false);
  }

  return (
    <FlatList
      data={posts}
      keyExtractor={(item) => item.id}
      renderItem={({ item }) => <Post post={item} />}
      refreshing={refrescando}
      onRefresh={recargar}
    />
  );
}
💡 Tip: notá el patrón setRefrescando(true) antes del await y setRefrescando(false) después. Si te olvidás del segundo, el spinner gira para siempre. Por eso conviene envolver el fetch en un try/finally y apagar el spinner en el finally.

<SectionList> — listas con secciones

Cuando los datos vienen agrupados (contactos por inicial, mensajes por fecha, tareas por categoría), querés encabezados de sección que se peguen arriba mientras scrolleás. Para eso existe <SectionList>, primo de FlatList.

La diferencia clave está en la forma de los datos: en vez de data (un array plano), recibe sections (un array de grupos, cada uno con su title y su propio array data):

import { SectionList, View, Text } from 'react-native';

const secciones = [
  { title: 'A', data: ['Ana', 'Alberto'] },
  { title: 'B', data: ['Bruno', 'Bianca'] },
];

export default function Agenda() {
  return (
    <SectionList
      sections={secciones}
      keyExtractor={(item, index) => item + index}
      renderItem={({ item }) => <Text>{item}</Text>}
      renderSectionHeader={({ section }) => (
        <View>
          <Text>{section.title}</Text>
        </View>
      )}
    />
  );
}
Lo nuevo respecto de FlatList: la prop sections (no data) y renderSectionHeader, que dibuja el encabezado de cada grupo recibiendo { section }. El resto (renderItem, keyExtractor) funciona igual.

Errores típicos con listas

Olvidar keyExtractor. Sin él (y sin un campo key en el ítem), RN tira un warning y el reciclado de vistas se vuelve impredecible: ítems que parpadean, estado que se mezcla entre filas.
Usar el index como key cuando la data cambia. Si insertás, borrás o reordenás elementos, las keys por índice se "corren" y React asocia mal el estado de cada fila (un check tildado salta a otro ítem). Usá un id estable del dato, no la posición.
Anidar un <FlatList> dentro de un <ScrollView> en la misma dirección. Los dos compiten por el gesto de scroll vertical, la virtualización se rompe (RN renderiza todo igual) y vas a ver el warning "VirtualizedLists should never be nested inside plain ScrollViews with the same orientation". Si necesitás contenido fijo arriba de la lista, usá ListHeaderComponent, no un ScrollView por fuera.

Ejemplo completo: lista de contactos

Juntemos lo importante en un ejemplo realista: una lista de contactos con separador entre filas y un mensaje cuando está vacía.

import { FlatList, View, Text, StyleSheet } from 'react-native';

const contactos = [
  { id: '1', nombre: 'Ana Gómez', tel: '11-2345-6789' },
  { id: '2', nombre: 'Bruno Díaz', tel: '11-9876-5432' },
  { id: '3', nombre: 'Carla Ruiz', tel: '11-5555-1234' },
];

export default function Agenda() {
  return (
    <FlatList
      data={contactos}
      keyExtractor={(item) => item.id}
      renderItem={({ item }) => (
        <View style={styles.fila}>
          <Text style={styles.nombre}>{item.nombre}</Text>
          <Text style={styles.tel}>{item.tel}</Text>
        </View>
      )}
      ItemSeparatorComponent={() => <View style={styles.separador} />}
      ListEmptyComponent={() => (
        <Text style={styles.vacio}>Todavía no tenés contactos.</Text>
      )}
    />
  );
}

const styles = StyleSheet.create({
  fila: { paddingVertical: 14, paddingHorizontal: 16 },
  nombre: { fontSize: 16, fontWeight: 'bold' },
  tel: { fontSize: 14, color: '#666' },
  separador: { height: 1, backgroundColor: '#e0e0e0' },
  vacio: { textAlign: 'center', marginTop: 40, color: '#999' },
});
📌 Probá el caso vacío: cambiá data={contactos} por data={[]} y vas a ver el ListEmptyComponent en acción. Manejar la lista vacía desde el día uno te evita la temida "pantalla en blanco" que confunde al usuario.

Checkpoint — ¿lo tenés claro?

¿Por qué .map() dentro de un ScrollView traba la app con listas largas?

Porque el ScrollView renderiza todos los elementos de una vez, aunque solo se vean unos pocos. Con miles de ítems eso monta miles de vistas nativas y reserva memoria para todas. FlatList en cambio virtualiza: solo renderiza lo visible y recicla las vistas a medida que scrolleás.

¿Cuáles son las tres props imprescindibles de FlatList y qué hace cada una?

data (el array de origen), renderItem (función ({ item }) => JSX que dibuja un elemento) y keyExtractor (función que devuelve una key única y estable por ítem, necesaria para el reciclado correcto).

¿Qué dos props usás para implementar pull-to-refresh y qué rol cumple cada una?

onRefresh es la función que recarga los datos cuando el usuario tira hacia abajo. refreshing es un booleano controlado por estado: mientras sea true se ve el spinner; lo ponés en true antes de recargar y en false al terminar (idealmente en un finally).

Ejercicios

  1. Armá una FlatList con un array de 10 objetos (por ejemplo, tus películas favoritas con id y titulo). Mostrá cada título en un <Text> y usá keyExtractor con el id.
  2. Agregá un ItemSeparatorComponent que dibuje una línea fina entre cada ítem y un ListHeaderComponent con un título "Mis películas".
  3. Vaciá el array (data={[]}) y agregá un ListEmptyComponent que muestre "No hay películas todavía". Confirmá que aparece.
  4. Implementá pull-to-refresh: un estado refrescando, una función onRefresh que espere 1 segundo (con setTimeout o un await) y vuelva a poner refrescando en false. Tirá hacia abajo y mirá el spinner.
  5. Convertí tu lista de películas en una SectionList agrupada por género (Acción, Drama, Comedia). Usá renderSectionHeader para mostrar el nombre del género arriba de cada grupo.

🧠 Autoevaluación

1. ¿Por qué FlatList rinde mejor que .map() + ScrollView con listas largas?

El ScrollView monta todos los elementos de golpe. FlatList solo dibuja lo que está (o está por estar) en pantalla y recicla vistas, manteniendo el consumo de memoria bajo aunque la lista tenga miles de ítems.

2. ¿Qué problema causa usar el index como key cuando la lista cambia?

Las keys por índice no son estables: si la data se reordena o se borra un elemento, el índice de cada ítem cambia y React mezcla el estado entre filas. Hay que usar un id estable del dato.

3. ¿Qué prop usás para mostrar un mensaje cuando la lista no tiene datos?

ListEmptyComponent se renderiza cuando data está vacío. Sin él, una lista vacía deja una pantalla en blanco que confunde al usuario.
