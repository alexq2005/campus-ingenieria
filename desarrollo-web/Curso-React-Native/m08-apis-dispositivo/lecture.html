Módulo 08 — APIs del Dispositivo

Hasta acá tu app vivía dentro de la pantalla. En este módulo se le abre la puerta al hardware: saber dónde está el usuario, sacar una foto, elegir una imagen de la galería, vibrar el celular o mandar una notificación. Es exactamente lo que una página web no puede hacer (o puede a medias), y es el motivo principal por el que las empresas hacen apps móviles.

El superpoder del móvil: el hardware

💡 La gran ventaja del móvil sobre la web es el acceso directo al hardware del dispositivo: GPS, cámara, micrófono, sensores, vibración, notificaciones que llegan aunque la app esté cerrada. Una web vive presa dentro del navegador y de su sandbox de seguridad; una app nativa tiene una línea directa con el sistema operativo. En RN + Expo, acceder a ese hardware sigue siempre el mismo patrón.

El patrón universal: instalar → pedir permiso → usar

No importa si querés el GPS, la cámara o las notificaciones: el flujo es idéntico en los tres pasos.

1. Instalá el módulo de Expo que envuelve esa pieza de hardware. Cada API vive en su propio paquete (expo-location, expo-camera, etc.).
npx expo install expo-location
Usamos npx expo install (no npm install a secas). La diferencia importa: Expo elige la versión del paquete compatible con tu versión de SDK, evitando el clásico "instalé la última y me rompió todo".
2. Pedí permiso al usuario antes de tocar el hardware. El sistema operativo muestra un cartel ("¿Permitís que la app use tu ubicación?") y el usuario decide. Vos esperás esa respuesta.
3. Usá la API — pero solo si el permiso fue concedido. Si lo negó, mostrás un mensaje amable y no llamás a la función del hardware.
📌 La regla de oro: siempre pedí permiso antes de usar el hardware, y siempre manejá el caso "denegado". El acceso al GPS, la cámara o las notificaciones está protegido por el sistema operativo: sin permiso, la API no funciona.
⚠️ El permiso no es para siempre y no es tuyo: el usuario puede negarlo, y puede revocarlo más tarde desde Ajustes del celular. Tu código no puede asumir que "ya lo pidió una vez". Verificá el estado del permiso cada vez que vas a usar el hardware.

expo-location — ¿dónde está el usuario?

El módulo expo-location te da el GPS. Dos funciones que vas a usar siempre:

FunciónQué hace
requestForegroundPermissionsAsync()Pide permiso de ubicación mientras la app está abierta. Devuelve { status }.
getCurrentPositionAsync()Lee la posición actual: latitud, longitud, precisión, etc.
 
import * as Location from 'expo-location';

async function obtenerUbicacion() {
  // 1. Pedir permiso
  const { status } = await Location.requestForegroundPermissionsAsync();

  // 2. Manejar el "denegado"
  if (status !== 'granted') {
    alert('Necesitamos tu permiso de ubicación para esto.');
    return;
  }

  // 3. Usar la API (solo si hay permiso)
  const pos = await Location.getCurrentPositionAsync({});
  console.log(pos.coords.latitude, pos.coords.longitude);
}
🔍 Fijate en la forma: es el mismo patrón de los tres pasos. Cambiá Location por Camera o Notifications y la estructura es idéntica: pedir permiso, chequear status !== 'granted', recién entonces usar el hardware.

expo-camera y expo-image-picker — fotos

Para sacar una foto en vivo o elegir una imagen ya guardada en el celular hay dos módulos distintos:

MóduloPara qué
expo-cameraAbrir la cámara en vivo dentro de tu app y sacar la foto vos mismo.
expo-image-pickerAbrir la galería del sistema para que el usuario elija una foto (o saque una rápida).

Para muchas apps, expo-image-picker es lo más práctico: el sistema operativo ya te resuelve toda la interfaz de selección.

import * as ImagePicker from 'expo-image-picker';

async function elegirFoto() {
  // 1+2. Pedir permiso de galería y manejar el "denegado"
  const { status } = await ImagePicker.requestMediaLibraryPermissionsAsync();
  if (status !== 'granted') {
    alert('Necesitamos acceso a tus fotos.');
    return;
  }

  // 3. Usar la API: abrir la galería
  const resultado = await ImagePicker.launchImageLibraryAsync({
    mediaTypes: ImagePicker.MediaTypeOptions.Images,
    quality: 1,
  });

  if (!resultado.canceled) {
    console.log(resultado.assets[0].uri);   // la ruta de la foto elegida
  }
}
launchImageLibraryAsync abre la galería; launchCameraAsync abre la cámara directamente. Ambas devuelven un objeto con canceled (por si el usuario cierra sin elegir) y assets con el uri de la imagen, que después podés mostrar en un <Image source={{ uri }} />.

expo-notifications — avisar al usuario

💡 Hay dos tipos de notificaciones: locales (las programa tu propia app desde el celular — un recordatorio, una alarma) y push (las envía un servidor remoto a través de los servicios de Apple/Google, y llegan aunque la app esté cerrada). El permiso y la idea general son los mismos; cambia quién dispara el aviso.

Para una notificación local, el patrón se repite: pedir permiso, programar el aviso.

import * as Notifications from 'expo-notifications';

async function recordarmeEn5seg() {
  // 1+2. Permiso
  const { status } = await Notifications.requestPermissionsAsync();
  if (status !== 'granted') {
    alert('Activá las notificaciones para recibir recordatorios.');
    return;
  }

  // 3. Programar la notificación local
  await Notifications.scheduleNotificationAsync({
    content: { title: '¡Hora de tomar agua! 💧', body: 'Pasaron 5 segundos.' },
    trigger: { seconds: 5 },
  });
}
⚠️ Las notificaciones push reales necesitan más: un build de la app (no funcionan del todo en Expo Go), credenciales de Apple/Google y un servidor que las envíe. Las locales, en cambio, las podés probar enseguida. Empezá por las locales para entender el flujo.

expo-haptics es de los pocos que normalmente no requieren permiso explícito, pero la mayoría del resto sí. Ante la duda, asumí que hace falta pedir permiso.

Ejemplo completo: botón "¿Dónde estoy?"

Juntemos todo en un componente real. Un botón que pide permiso de ubicación y, si se lo conceden, muestra la latitud y la longitud en pantalla.

import { useState } from 'react';
import { Text, View, Pressable, StyleSheet } from 'react-native';
import * as Location from 'expo-location';

export default function DondeEstoy() {
  const [coords, setCoords] = useState(null);
  const [mensaje, setMensaje] = useState('');

  async function buscarUbicacion() {
    setMensaje('Buscando…');

    // 1. Pedir permiso
    const { status } = await Location.requestForegroundPermissionsAsync();

    // 2. Manejar el caso "denegado"
    if (status !== 'granted') {
      setMensaje('Permiso denegado. No puedo ver tu ubicación.');
      return;
    }

    // 3. Usar la API
    const pos = await Location.getCurrentPositionAsync({});
    setCoords(pos.coords);
    setMensaje('');
  }

  return (
    <View style={styles.container}>
      <Pressable style={styles.boton} onPress={buscarUbicacion}>
        <Text style={styles.botonTexto}>¿Dónde estoy?</Text>
      </Pressable>

      {mensaje !== '' && <Text>{mensaje}</Text>}

      {coords && (
        <Text style={styles.coords}>
          Lat: {coords.latitude.toFixed(5)}{'\n'}
          Long: {coords.longitude.toFixed(5)}
        </Text>
      )}
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center', gap: 16 },
  boton: { backgroundColor: '#a78bfa', paddingVertical: 12, paddingHorizontal: 24, borderRadius: 10 },
  botonTexto: { color: 'white', fontWeight: 'bold' },
  coords: { fontSize: 18, textAlign: 'center' },
});
Reconocé lo que ya sabés: useState, un Pressable con onPress, renderizado condicional con &&. Lo único nuevo es el patrón asíncrono de los tres pasos (instalar ya está hecho; pedir permiso; usar). El resto es React de siempre.

Errores típicos

Usar la API sin pedir permiso. Llamar a getCurrentPositionAsync() sin haber pedido permiso antes hace que falle o devuelva un error. El hardware está bloqueado hasta que el usuario acepta.
Asumir que el permiso está dado. Que el usuario lo haya concedido la semana pasada no garantiza nada: pudo revocarlo desde Ajustes. Verificá el status cada vez antes de usar el hardware.
No manejar la denegación. Si el usuario dice "no" y tu código sigue como si nada, la app crashea o se queda colgada. Siempre tené una rama para status !== 'granted' con un mensaje claro.

Checkpoint — ¿lo tenés claro?

¿Cuál es el patrón universal para usar cualquier API de hardware en Expo?

Tres pasos, siempre los mismos: (1) instalar el módulo de Expo con npx expo install, (2) pedir permiso al usuario con la función request…PermissionsAsync(), y (3) usar la API solo si el status es 'granted'.

¿Qué pasa si el usuario niega el permiso y tu código no lo maneja?

La llamada al hardware falla o la app puede crashear/colgarse. Por eso siempre hay que tener una rama para status !== 'granted' que muestre un mensaje amable y no intente usar la API.

¿Cuál es la diferencia entre una notificación local y una push?

La local la programa tu propia app desde el celular (un recordatorio, una alarma) con scheduleNotificationAsync. La push la envía un servidor remoto vía Apple/Google y llega aunque la app esté cerrada, pero necesita un build real, credenciales y un servidor.

Ejercicios

  1. Instalá expo-location con npx expo install y escribí el componente "¿Dónde estoy?" del ejemplo. Probalo en tu celular.
  2. Negá el permiso a propósito (rechazá el cartel) y verificá que tu app muestra el mensaje de "permiso denegado" en vez de crashear.
  3. Instalá expo-image-picker y agregá un botón que abra la galería; mostrá la foto elegida en un <Image> usando el uri del resultado.
  4. Instalá expo-notifications y programá una notificación local que llegue a los 5 segundos de tocar un botón. Pedí el permiso primero.
  5. Sumá expo-haptics y hacé que el botón de ubicación vibre con notificationAsync al obtener las coordenadas con éxito.

🧠 Autoevaluación

1. ¿Cuál es el patrón universal para usar una API de hardware en Expo?

Siempre los mismos tres pasos: npx expo install, request…PermissionsAsync(), y recién usar el hardware si el status es 'granted'.

2. El usuario niega el permiso de ubicación. ¿Qué debería hacer tu código?

Hay que manejar la denegación: chequear el status, avisar al usuario y NO llamar al hardware. Insistir en bucle o ignorar la negativa rompe la app.

3. ¿Qué función programa una notificación local desde el propio celular?

scheduleNotificationAsync programa una notificación local (recordatorio/alarma) desde la propia app. Las push, en cambio, vienen de un servidor remoto.
