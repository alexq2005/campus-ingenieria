Módulo 06 — Formularios & Teclado

Casi toda app real le pide datos al usuario: un login, un buscador, un comentario, un número de tarjeta. En el móvil eso significa dos cosas que en la web casi ni pensás: el campo de texto y el teclado virtual que aparece tapando media pantalla. En este módulo vas a dominar <TextInput>, vas a manejar el teclado para que no te tape el campo, y vas a armar un formulario de login controlado con validación.

<TextInput>: el input del móvil

💡 <TextInput> es el equivalente al <input> de la web, pero con una diferencia que confunde a todo el que viene del navegador: en RN usás value + onChangeText, no onChange. Y onChangeText te entrega directamente el string escrito, no un evento del que tenés que sacar e.target.value.

La forma correcta de usarlo es controlado: el valor vive en un useState, y cada tecla que el usuario aprieta actualiza ese estado.

import { useState } from 'react';
import { TextInput, View, StyleSheet } from 'react-native';

export default function App() {
  const [nombre, setNombre] = useState('');   // ⬅️ la fuente de verdad

  return (
    <View style={styles.container}>
      <TextInput
        style={styles.input}
        value={nombre}                  // lo que se muestra
        onChangeText={setNombre}        // ⬅️ recibe el string directo, NO un evento
        placeholder="Tu nombre"
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', padding: 20 },
  input: { borderWidth: 1, borderColor: '#cbd5e1', borderRadius: 8, padding: 12, fontSize: 16 },
});
🔍 Mirá lo que ya reconocés: es exactamente el patrón de input controlado del Curso de React: el estado manda, el campo refleja. Lo único que cambia es el nombre del prop: onChange → onChangeText, y que ya no hay e.target.value — recibís el texto pelado.

Props clave de <TextInput>

El <TextInput> tiene props que afectan directamente qué teclado aparece y cómo se comporta. Usarlas bien es la diferencia entre una app prolija y una molesta:

PropPara qué sirveEjemplo de valor
placeholderTexto gris de ayuda cuando está vacío"Tu email"
keyboardTypeQué teclado mostrar'numeric', 'email-address', 'phone-pad'
secureTextEntryOculta el texto (contraseñas)true
autoCapitalizeCapitalización automática'none', 'words', 'sentences'
autoCorrectCorrector automático on/offfalse
multilinePermite varias líneas (textarea)true
maxLengthLímite de caracteres{50}
returnKeyTypeTexto/ícono de la tecla de acción'done', 'go', 'search'
📌 El teclado correcto importa. Si el campo es un email, poné keyboardType="email-address" y autoCapitalize="none": así el usuario tiene la @ a mano y el teléfono no le pone mayúscula a su correo. Si es un número de teléfono, keyboardType="phone-pad". Un teclado bien elegido se siente "profesional" sin que nadie sepa por qué. 
// Campo de email afinado
<TextInput
  value={email}
  onChangeText={setEmail}
  placeholder="tucorreo@ejemplo.com"
  keyboardType="email-address"
  autoCapitalize="none"      // los emails no llevan mayúscula inicial
  autoCorrect={false}        // que no te "corrija" el correo
/>

// Campo de contraseña
<TextInput
  value={pass}
  onChangeText={setPass}
  placeholder="Contraseña"
  secureTextEntry={true}     // ⬅️ muestra ••••• en vez del texto
  autoCapitalize="none"
/>

El problema del teclado que tapa el campo

En el móvil, cuando tocás un input, sube un teclado que ocupa media pantalla. Si el campo estaba abajo, queda tapado y el usuario no ve lo que escribe. Es de los detalles que más delatan a una app hecha sin cuidado.

💡 <KeyboardAvoidingView> es un contenedor que empuja su contenido hacia arriba cuando aparece el teclado, para que el campo enfocado quede siempre visible. Envolvés tu formulario con él y listo. 
import { KeyboardAvoidingView, TextInput, Platform, StyleSheet } from 'react-native';

<KeyboardAvoidingView
  style={styles.container}
  behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
>
  <TextInput style={styles.input} placeholder="Escribí acá" />
</KeyboardAvoidingView>
iOS y Android se comportan distinto. El prop behavior define cómo evita el teclado:
  • 'padding' — agrega espacio abajo. Funciona muy bien en iOS.
  • 'height' — achica la altura del contenedor. Suele ir mejor en Android.
Por eso el patrón habitual es elegirlo con Platform.OS, como en el ejemplo. En muchos casos Android ya maneja el teclado solo (por la config windowSoftInputMode), así que probá en ambos y ajustá.

Cerrar el teclado

Una vez abierto, el teclado se queda. Si el usuario terminó de escribir y toca en cualquier lado, esperaría que se cierre — pero por defecto no pasa. Hay que cerrarlo nosotros.

Opción 1 — manualmente: llamás a Keyboard.dismiss() cuando quieras (por ejemplo, al apretar "Entrar" o al terminar de validar).
import { Keyboard } from 'react-native';

// dentro de un handler:
Keyboard.dismiss();   // ⬅️ baja el teclado
Opción 2 — cerrar al tocar afuera: envolvés toda la pantalla en un <Pressable> (o <TouchableWithoutFeedback>) que al tocarse llama a Keyboard.dismiss().
import { Pressable, Keyboard, TextInput, StyleSheet } from 'react-native';

<Pressable style={styles.fondo} onPress={Keyboard.dismiss}>
  <TextInput style={styles.input} placeholder="Tocá afuera para cerrar el teclado" />
</Pressable>
✅ Combo recomendado: envolvé el formulario con <KeyboardAvoidingView> para que el teclado no tape el campo, y poné un <Pressable onPress={Keyboard.dismiss}> alrededor para cerrarlo al tocar afuera. Con esas dos piezas tu formulario ya se siente nativo.

Validación básica

Validar un formulario en RN es puro React: tenés el valor en estado, calculás si es válido, y mostrás un mensaje de error o deshabilitás el botón según corresponda. No hace falta ninguna librería para lo simple.

const [email, setEmail] = useState('');
const [error, setError] = useState('');

function validar() {
  if (!email.includes('@')) {
    setError('Ingresá un email válido');   // ⬅️ guardamos el mensaje en estado
    return false;
  }
  setError('');     // sin error
  return true;
}

// en el render, mostramos el error solo si existe:
{error !== '' && <Text style={styles.error}>{error}</Text>}
📌 Deshabilitá el botón si el formulario es inválido. Calculás un booleano (const formularioOk = email.includes('@') && pass.length >= 6) y se lo pasás al <Pressable disabled={!formularioOk}>. Así el usuario no puede enviar datos basura y vos no validás "después".

Ejemplo completo: formulario de login

Juntamos todo: dos campos controlados (email + contraseña), teclados afinados, secureTextEntry para la clave, KeyboardAvoidingView para que no tape, cierre del teclado al tocar afuera, validación con mensaje de error y botón deshabilitado mientras sea inválido.

import { useState } from 'react';
import {
  KeyboardAvoidingView, Pressable, Keyboard,
  TextInput, Text, View, Platform, StyleSheet,
} from 'react-native';

export default function Login() {
  const [email, setEmail] = useState('');
  const [pass, setPass] = useState('');
  const [error, setError] = useState('');

  // booleano de validez: email con @ y clave de 6+
  const formularioOk = email.includes('@') && pass.length >= 6;

  function entrar() {
    if (!formularioOk) {
      setError('Revisá el email y que la clave tenga 6+ caracteres');
      return;
    }
    setError('');
    Keyboard.dismiss();             // ⬅️ bajamos el teclado al enviar
    console.log('Login:', email);   // acá iría la llamada real
  }

  return (
    <Pressable style={{ flex: 1 }} onPress={Keyboard.dismiss}>
      <KeyboardAvoidingView
        style={styles.container}
        behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
      >
        <Text style={styles.titulo}>Ingresar</Text>

        <TextInput
          style={styles.input}
          value={email}
          onChangeText={setEmail}
          placeholder="Email"
          keyboardType="email-address"
          autoCapitalize="none"
          autoCorrect={false}
        />

        <TextInput
          style={styles.input}
          value={pass}
          onChangeText={setPass}
          placeholder="Contraseña"
          secureTextEntry={true}
          autoCapitalize="none"
        />

        {error !== '' && <Text style={styles.error}>{error}</Text>}

        <Pressable
          style={[styles.boton, !formularioOk && styles.botonOff]}
          onPress={entrar}
          disabled={!formularioOk}    // ⬅️ desactivado si es inválido
        >
          <Text style={styles.botonTexto}>Entrar</Text>
        </Pressable>
      </KeyboardAvoidingView>
    </Pressable>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', padding: 24, gap: 14 },
  titulo: { fontSize: 28, fontWeight: 'bold', marginBottom: 8 },
  input: { borderWidth: 1, borderColor: '#cbd5e1', borderRadius: 8, padding: 12, fontSize: 16 },
  error: { color: '#dc2626', fontSize: 14 },
  boton: { backgroundColor: '#a78bfa', padding: 14, borderRadius: 10, alignItems: 'center' },
  botonOff: { backgroundColor: '#cbd5e1' },   // gris cuando está deshabilitado
  botonTexto: { color: 'white', fontWeight: 'bold', fontSize: 16 },
});

Errores típicos

Usar onChange en vez de onChangeText. Si copiás un <TextInput onChange={(e) => setX(e.target.value)} /> de la web, el campo "no escribe" o tira error: en RN no hay e.target.value. Usá onChangeText={setX}, que te da el string directo.
El teclado tapa el campo. Poner los inputs abajo sin <KeyboardAvoidingView>: el teclado sube y el usuario no ve qué escribe. Envolvé el formulario y ajustá behavior según la plataforma.
No manejar el foco ni cerrar el teclado. El teclado abierto que no se cierra al tocar afuera, o que se queda tras enviar el formulario, se siente roto. Acordate de Keyboard.dismiss() y del <Pressable> envolvente.
⚠️ Input controlado = el value manda. Si ponés value={email} pero te olvidás del onChangeText, el campo queda congelado (el usuario teclea y no pasa nada), porque siempre vuelve a mostrar el estado, que nunca cambia. Van siempre juntos.

Checkpoint — ¿lo tenés claro?

¿Por qué onChangeText y no onChange?

Porque en React Native <TextInput> no usa eventos del DOM: no existe e.target.value. onChangeText te entrega directamente el string que el usuario escribió, así que podés hacer onChangeText={setNombre} sin desempaquetar ningún evento. Es más simple, pero distinto a la web.

¿Para qué sirve <KeyboardAvoidingView> y por qué behavior cambia según la plataforma?

Empuja el contenido hacia arriba cuando aparece el teclado, para que el campo enfocado no quede tapado. iOS y Android manejan el teclado de forma distinta: 'padding' (agrega espacio) suele ir mejor en iOS y 'height' (achica el contenedor) en Android. Por eso se elige con Platform.OS.

¿Cómo cierro el teclado cuando el usuario toca fuera del campo?

Envolviendo la pantalla en un <Pressable> (o <TouchableWithoutFeedback>) cuyo onPress llame a Keyboard.dismiss(). También podés llamar a Keyboard.dismiss() manualmente desde cualquier handler, por ejemplo al enviar el formulario.

Ejercicios

  1. Creá una pantalla con un <TextInput> controlado para el nombre y mostrá debajo un <Text> con "Hola, {nombre}" que se actualice mientras escribís.
  2. Agregá un campo de email con keyboardType="email-address" y autoCapitalize="none". Probalo en el celular y observá que aparece el teclado con @.
  3. Sumá un campo de contraseña con secureTextEntry y un maxLength de 20. Verificá que el texto se oculta.
  4. Envolvé el formulario con <KeyboardAvoidingView> y un <Pressable onPress={Keyboard.dismiss}>. Confirmá que el teclado no tapa el último campo y que se cierra al tocar afuera.
  5. Armá el formulario de login completo: validá que el email tenga @ y la clave 6+ caracteres, mostrá un mensaje de error y deshabilitá el botón "Entrar" mientras sea inválido.

🧠 Autoevaluación

1. ¿Cómo se obtiene el texto que el usuario escribe en un <TextInput>?

En RN no hay eventos del DOM: onChangeText te pasa el string ya listo, por eso podés hacer onChangeText={setX}.

2. ¿Para qué sirve <KeyboardAvoidingView>?

Mueve su contenido hacia arriba cuando sube el teclado; el behavior ('padding'/'height') se elige según iOS o Android.

3. ¿Qué prop usás para que un campo de contraseña oculte el texto?

secureTextEntry muestra puntos en lugar del texto. type="password" es de la web (HTML), no existe en <TextInput>.
