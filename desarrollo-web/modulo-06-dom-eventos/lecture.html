🧠 Autoevaluación rápida

Respondé sin mirar arriba. Cada pregunta te explica el porqué.

1. ¿En qué orden atraviesa el DOM un evento?

Primero baja desde window hasta el elemento (capture), llega al target, y después sube de vuelta (bubble). addEventListener escucha en bubble por defecto; para la bajada pasás { capture: true }.

2. Tenés una lista con 1000 ítems. ¿Por qué conviene event delegation?

Un listener en vez de mil: menos memoria y cero re-bindeo cuando la lista cambia. El patrón es e.target.closest('li') y salir temprano con if (!li) return; si el clic cayó fuera.

3. ¿Para qué sirve debounce en el evento input de un buscador?

debounce reinicia un setTimeout con cada tecla: la función real corre solo cuando pasan N ms sin escribir. Lo de la opción 3 es otra cosa: addEventListener(..., { once: true }).
