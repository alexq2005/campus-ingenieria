Módulo 08 — Archivos e I/O

Abrir y cerrar archivos

Forma manual (no recomendada)

f = open("datos.txt", "r")
contenido = f.read()
f.close()              # ⚠️ si hay excepción antes, no se cierra

Forma correcta — with

with open("datos.txt", "r", encoding="utf-8") as f:
    contenido = f.read()
# se cierra automáticamente, incluso si hay excepción
Siempre especificar encoding="utf-8" — en Windows el default es cp1252, que falla con caracteres no-ASCII.

Modos de apertura

ModoSignificado
rLectura (default) — falla si no existe
wEscritura — trunca el archivo
aAppend — agrega al final
xExclusivo — falla si ya existe
r+Lectura y escritura
bBinario (combinar: rb, wb)
tTexto (default)

Leer

with open("datos.txt", encoding="utf-8") as f:
    todo = f.read()                  # todo como string

with open("datos.txt", encoding="utf-8") as f:
    primera_linea = f.readline()     # una sola línea
    segunda_linea = f.readline()

with open("datos.txt", encoding="utf-8") as f:
    lineas = f.readlines()           # lista de líneas

with open("datos.txt", encoding="utf-8") as f:
    for linea in f:                  # iteración línea por línea (recomendado para archivos grandes)
        print(linea.rstrip())

Escribir

with open("salida.txt", "w", encoding="utf-8") as f:
    f.write("Primera línea\n")
    f.write("Segunda línea\n")
    f.writelines(["a\n", "b\n", "c\n"])

# Append
with open("log.txt", "a", encoding="utf-8") as f:
    f.write(f"{datetime.now()}: evento\n")

Archivos binarios

with open("imagen.jpg", "rb") as f:
    bytes_data = f.read()

with open("copia.jpg", "wb") as f:
    f.write(bytes_data)

Pathlib (forma moderna)

pathlib reemplaza a os.path con una API orientada a objetos:

from pathlib import Path

p = Path("datos") / "archivos" / "input.txt"
p.exists()              # True/False
p.is_file()
p.is_dir()
p.suffix                # '.txt'
p.stem                  # 'input'
p.name                  # 'input.txt'
p.parent                # Path('datos/archivos')
p.absolute()
p.read_text(encoding="utf-8")
p.write_text("contenido", encoding="utf-8")
p.read_bytes()
p.write_bytes(b"...")

# Crear directorios
Path("logs").mkdir(exist_ok=True)
Path("a/b/c").mkdir(parents=True, exist_ok=True)

# Listar
for archivo in Path(".").iterdir():
    print(archivo)

for archivo in Path(".").glob("*.py"):
    print(archivo)

for archivo in Path(".").rglob("*.py"):    # recursivo
    print(archivo)

# Eliminar
Path("temp.txt").unlink(missing_ok=True)   # archivo
Path("vacio").rmdir()                       # directorio vacío

JSON

import json

datos = {"nombre": "Ana", "edad": 30, "tags": ["a", "b"]}

# Escribir
with open("usuario.json", "w", encoding="utf-8") as f:
    json.dump(datos, f, indent=2, ensure_ascii=False)

# Leer
with open("usuario.json", encoding="utf-8") as f:
    leido = json.load(f)

# String <-> dict
texto = json.dumps(datos, indent=2)
de_texto = json.loads(texto)

Tipos compatibles JSON

dict, list, tuple, str, int, float, bool, None. Tipos custom requieren default= en dump.

CSV

import csv

# Leer
with open("personas.csv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f)
    for fila in reader:
        print(fila)

# Leer como dict (con header)
with open("personas.csv", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f)
    for fila in reader:
        print(fila["nombre"], fila["edad"])

# Escribir
with open("salida.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["nombre", "edad"])
    writer.writerows([("Ana", 30), ("Luis", 25)])

# Escribir con dict
with open("salida.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["nombre", "edad"])
    writer.writeheader()
    writer.writerow({"nombre": "Ana", "edad": 30})
newline="" es importante en Windows para evitar líneas en blanco extras.

Errores típicos con archivos

Usar el archivo fuera del with. Al salir del bloque el handle ya está cerrado: cualquier lectura posterior revienta. El with tiene que envolver todo el uso, no solo el open. 
# ❌ mal
with open("datos.txt", encoding="utf-8") as f:
    pass
for linea in f:                    # ValueError: I/O operation on closed file
    print(linea)

# ✅ bien
with open("datos.txt", encoding="utf-8") as f:
    for linea in f:
        print(linea.rstrip())
Leer dos veces el mismo handle. Un archivo abierto tiene un cursor. Después de un read() quedó al final, así que la segunda lectura devuelve vacío — y no lanza ningún error, que es lo peor de todo. 
# ❌ mal
with open("datos.txt", encoding="utf-8") as f:
    contenido = f.read()
    lineas = f.readlines()    # [] — el cursor ya está en el final

# ✅ bien — volvé al principio, o leé una sola vez y trabajá en memoria
with open("datos.txt", encoding="utf-8") as f:
    contenido = f.read()
    f.seek(0)
    lineas = f.readlines()
Confundir dump con dumps (y load con loads). Las versiones con s trabajan con strings; las que no, con un archivo abierto. Pasarle una ruta a json.dump falla con AttributeError: 'str' object has no attribute 'write'. 
# ❌ mal
json.dump(datos, "usuario.json")          # espera un file object, no una ruta
config = json.loads(open("cfg.json"))     # loads espera un string, no un archivo

# ✅ bien
with open("usuario.json", "w", encoding="utf-8") as f:
    json.dump(datos, f, indent=2, ensure_ascii=False)

with open("cfg.json", encoding="utf-8") as f:
    config = json.load(f)
Armar rutas concatenando strings. Se rompe al cambiar de sistema operativo, duplica barras y no expande ~ (para open() la virgulilla es un carácter común: solo el shell la traduce). pathlib resuelve las tres cosas. 
# ❌ mal
ruta = "datos" + "/" + "archivos" + "/input.txt"
config = open("~/config.json")     # FileNotFoundError: '~/config.json'

# ✅ bien
from pathlib import Path
ruta = Path("datos") / "archivos" / "input.txt"
config = (Path.home() / "config.json").read_text(encoding="utf-8")

Checkpoint — ¿lo tenés claro?

¿Por qué iterar con for linea in f: es mejor que f.readlines() en un archivo de varios GB?

Porque readlines() arma una lista con todas las líneas en memoria antes de que puedas tocar la primera: un archivo de 4 GB necesita 4 GB de RAM (más overhead) y probablemente te tire MemoryError. Iterando el archivo directamente, Python lee de a un buffer y descarta cada línea cuando terminás con ella: memoria constante sin importar el tamaño.

Si en tu máquina funciona igual sin ponerlo, ¿por qué pasar encoding="utf-8" explícito?

Porque sin el parámetro Python usa el encoding por defecto del sistema, y ese default cambia de máquina en máquina: en Windows suele ser cp1252, en Linux/macOS UTF-8. El mismo script te anda perfecto y en la compu del de al lado explota con UnicodeDecodeError ante la primera "ñ" o el primer emoji. Ponerlo explícito hace que el comportamiento sea el mismo en todos lados.

Guardás una tupla en un JSON y al leerla vuelve como lista. ¿Por qué?

Porque JSON es un formato de intercambio entre lenguajes y su vocabulario es chico: objetos, arrays, strings, números, booleanos y null. No existe el concepto de tupla, así que json.dump la serializa como array y json.load la trae de vuelta como list, que es lo más parecido en Python. Lo mismo pasa con set, datetime o tus clases propias: si necesitás conservarlos, tenés que convertirlos vos (con default= al escribir y reconstruirlos al leer).

🧠 Autoevaluación rápida

Respondé sin mirar arriba. Cada pregunta te explica el porqué.

1. Abrís con modo "w" un archivo que ya tenía contenido. ¿Qué pasa?

w trunca siempre. Si querés agregar sin borrar usá a (append); el modo que sí falla cuando el archivo ya existe es x.

2. Con p = Path("datos") / "archivos" / "input.txt", ¿qué devuelve p.stem?

stem es el nombre sin extensión. p.name da 'input.txt' y p.suffix da '.txt'.

3. ¿Para qué se pasa newline="" al abrir un CSV en Windows?

Sin newline="" el salto de línea se traduce dos veces en Windows y el CSV queda con una fila vacía entre cada registro. El encoding se pide aparte con encoding="utf-8".
