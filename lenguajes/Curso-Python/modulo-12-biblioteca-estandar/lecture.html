re — expresiones regulares

import re

# Match
re.match(r"\d+", "123abc")          # match al inicio
re.search(r"\d+", "abc123")         # match en cualquier posición
re.findall(r"\d+", "a1 b22 c333")   # ['1', '22', '333']

# Captura de grupos
m = re.search(r"(\w+)@(\w+)", "ana@example.com")
m.group(0)   # 'ana@example'
m.group(1)   # 'ana'
m.group(2)   # 'example'

# Sustitución
re.sub(r"\s+", "_", "hola   mundo")   # 'hola_mundo'

# Compilar para reutilizar
patron = re.compile(r"\d{4}-\d{2}-\d{2}")
patron.findall("2024-03-15 y 2025-01-01")

Errores típicos con la stdlib

Escribir regex sin r"...". El string se interpreta dos veces: primero Python resuelve los escapes y después la regex intenta interpretar lo que quedó. "\d" zafa de casualidad (con SyntaxWarning), pero "\b" se convierte en un backspace real y tu patrón deja de matchear sin avisarte. 
# ❌ mal
re.findall("\d+", texto)            # SyntaxWarning: invalid escape sequence '\d'
re.search("\bcasa\b", "una casa")   # None — "\b" es el carácter backspace

# ✅ bien — raw string siempre
re.findall(r"\d+", texto)
re.search(r"\bcasa\b", "una casa")  # <re.Match object...>
Mezclar datetimes naive y aware. datetime.now() no lleva zona horaria; datetime.now(timezone.utc) sí. Restarlos o compararlos es TypeError, y guardar naive en la DB te deja sin saber a qué huso pertenece cada registro. 
# ❌ mal
inicio = datetime.now()                # naive
fin = datetime.now(timezone.utc)       # aware
fin - inicio
# TypeError: can't subtract offset-naive and offset-aware datetimes

# ✅ bien — elegí uno y usá el mismo en todo el programa
inicio = datetime.now(timezone.utc)
fin = datetime.now(timezone.utc)
duracion = fin - inicio
Consultar un defaultdict como si fuera un dict. Acceder a una clave que no existe la crea con el valor por defecto. Un chequeo inocente te infla el diccionario con entradas vacías que después aparecen en el reporte. 
# ❌ mal
grupos = defaultdict(list)
if grupos["frutas"]:      # ¡acaba de crear grupos["frutas"] = []!
    procesar(grupos["frutas"])
len(grupos)               # 1, aunque nunca agregaste nada

# ✅ bien — para consultar sin crear, usá in o get
if "frutas" in grupos:
    procesar(grupos["frutas"])
len(grupos)               # 0
Loguear la excepción con log.error(e). Guardás el mensaje pero perdés el traceback: en el log queda "division by zero" y cero pistas de en qué archivo y en qué línea pasó. Dentro de un except, log.exception agrega la pila completa. 
# ❌ mal
try:
    procesar()
except Exception as e:
    log.error(e)          # "division by zero" y nada más

# ✅ bien
try:
    procesar()
except Exception:
    log.exception("falló procesar()")   # mensaje + traceback completo

Checkpoint — ¿lo tenés claro?

¿Por qué conviene guardar los timestamps en UTC y convertir a hora local recién al mostrarlos?

Porque UTC es un eje de tiempo continuo y sin ambigüedades, y la hora local no: con el horario de verano hay una hora que ocurre dos veces por año (¿el registro de las 02:30 es antes o después del cambio?) y otra que no existe nunca. Además, si tus usuarios están en husos distintos, ordenar por una columna de hora local mezcla eventos que pasaron en otro orden. Guardando en UTC, restar dos fechas siempre da la duración real, y la conversión a "hora del que mira la pantalla" queda como un problema de presentación, que es donde corresponde.

Si al final los dos escriben texto, ¿qué te da logging que print no?

Tres cosas que en producción son la diferencia entre debuggear y adivinar. Niveles: subís a DEBUG el día que hay un problema y bajás a WARNING el resto del tiempo, sin tocar una sola línea de código. Destinos: el mismo mensaje puede ir a consola, a un archivo con rotación y a un servicio remoto, decidido en la configuración y no en cada llamada. Contexto automático: timestamp, nivel, nombre del módulo y, con log.exception, el traceback entero. Un print desnudo es una línea sin fecha ni origen en un stdout que nadie está mirando.

Si un dict común ya hace el trabajo, ¿por qué existen Counter y defaultdict?

Para sacarte de encima el ritual de "si la clave no existe, inicializala": ese if clave not in d: d[clave] = 0 que se repite en todos lados es ruido donde se esconden bugs. defaultdict mueve esa decisión a un solo lugar (la fábrica que le pasás al construirlo) y Counter ya viene con la operación entera resuelta, más extras como most_common() y poder sumar y restar contadores. El código termina expresando la intención ("contar", "agrupar") en vez del mecanismo, y de paso el bucle corre en C en vez de en Python.

🧠 Autoevaluación rápida

Respondé sin mirar arriba. Cada pregunta te explica el porqué.

1. ¿Qué diferencia hay entre re.match(r"\d+", "abc123") y re.search(r"\d+", "abc123")?

match exige que el patrón empiece en el carácter 0, así que con "abc123" devuelve None. Si querés todas las coincidencias, usá findall.

2. Necesitás generar un token para recuperar contraseñas. ¿Qué módulo usás?

random no es criptográficamente seguro: conociendo la semilla se predice la secuencia. Para tokens, contraseñas y comparaciones constant-time va secrets.

3. ¿Por qué la lección marca shell=True en subprocess.run como peligroso?

Con shell=True el string lo interpreta el shell: un ; o un && metido en la entrada del usuario ejecuta lo que quiera. Pasá el comando como lista de argumentos, tal como ["ls", "-la"].
