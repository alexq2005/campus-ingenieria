Operadores lógicos

OperadorSignificado
andY lógico
orO lógico

Short-circuit evaluation

  • and devuelve el primer falsy o el último valor
  • or devuelve el primer truthy o el último valor
True and "hola"    # 'hola'
False and "hola"   # False
None or "default"  # 'default' (patrón común para defaults)
0 or 42            # 42

Operador walrus := (Python 3.8+)

Asigna y devuelve en una expresión:

# Sin walrus
linea = input()
while linea != "fin":
    print(linea)
    linea = input()

# Con walrus
while (linea := input()) != "fin":
    print(linea)

Operadores de identidad y pertenencia

a = [1, 2, 3]
b = [1, 2, 3]
c = a

a == b     # True (mismo contenido)
a is b     # False (objetos distintos)
a is c     # True (misma referencia)
a is None  # patrón estándar para chequeo None

3 in a         # True
4 in a         # False
"o" in "hola"  # True
Regla: usá is solo con None, True, False. Para igualdad de valor, ==.

Precedencia (de mayor a menor)

  1. () — paréntesis
  2. ** — exponenciación
  3. +x, -x, ~x — unarios
  4. *, /, //, %
  5. +, -
  6. <<, >>
  7. &
  8. ^
  9. |
  10. ==, !=, <, >, <=, >=, is, in
  11. not
  12. and
  13. or
Regla: cuando dudes, usá paréntesis. La claridad vale más que la brevedad.

Errores típicos con operadores

1. Escribir x == 1 or 2 — se lee como castellano, pero Python lo agrupa como (x == 1) or 2, y 2 es truthy: la condición da siempre verdadero. 
x = 7
if x == 1 or 2:        # ❌ entra igual, siempre
    print("entré")

if x == 1 or x == 2:   # ✅ dos comparaciones completas
    ...
if x in (1, 2):        # ✅ más corto y más claro
2. Usar is para comparar números o strings — a veces "funciona" por un detalle de implementación (CPython cachea los enteros chicos) y de golpe deja de funcionar. 
a = 256; b = 256
a is b        # True... pero por casualidad

a = 257; b = 257
a is b        # ❌ False — mismo valor, objetos distintos

a == b        # ✅ True: para valores, siempre ==
3. Asumir que % y // se comportan como en C o JavaScript — en Python el resto toma el signo del divisor y la división entera redondea hacia abajo, no hacia cero. 
-7 % 3        # 2 en Python (en C/JS daría -1)
-7 // 3       # -3 (no -2)

abs(-7) % 3   # ✅ 1, si lo que querías era el resto del valor absoluto
4. Olvidar que ** tiene más precedencia que el menos unario. 
-2 ** 2       # ❌ -4 → se agrupa como -(2 ** 2)
(-2) ** 2     # ✅ 4
Ante la duda, paréntesis: leer una expresión no debería obligar a nadie a recordar la tabla de precedencia.

Checkpoint — ¿lo tenés claro?

¿Por qué 18 <= edad < 65 hace lo que uno espera en Python y en muchos otros lenguajes no?

Porque Python encadena las comparaciones: internamente lo traduce a 18 <= edad and edad < 65, evaluando edad una sola vez. En C o JavaScript la expresión se resuelve de izquierda a derecha: 18 <= edad produce un booleano, y ese booleano se compara contra 65 — un resultado casi siempre inútil, y encima silencioso, porque no da error.

¿Qué diferencia hay entre = y :=, y por qué eso permite usar el walrus dentro de un while?

= es una sentencia: asigna y no vale nada, por eso no podés meterla dentro de una condición. := es una expresión: asigna y además devuelve el valor asignado, así que se puede usar en cualquier lugar donde se espere un valor. Eso es lo que habilita while (linea := input()) != "fin", leyendo y comparando en el mismo lugar en vez de duplicar la línea de lectura antes y adentro del bucle.

¿Cuál es la diferencia entre & y and?

and es lógico: trabaja sobre la verdad del valor completo y hace short-circuit, o sea que si el primer operando es falsy ni evalúa el segundo. & es bit a bit: opera sobre la representación binaria y evalúa siempre los dos lados. Se nota en el resultado: 1 and 2 devuelve 2, mientras que 1 & 2 devuelve 0. Usá and para condiciones, y & solamente cuando estés manipulando bits o flags (o trabajando con sets, donde & significa intersección).

1. ¿Qué devuelve la expresión 0 or 42?

Los operadores lógicos hacen short-circuit y devuelven un valor, no un bool: or devuelve el primer truthy (o el último valor). Como 0 es falsy, sigue y devuelve 42. Por eso None or "default" es el patrón clásico de valor por defecto.

2. Con a = [1, 2, 3] y b = [1, 2, 3], ¿qué devuelve a is b?

is compara identidad (si son el mismo objeto en memoria), no contenido. Son dos listas distintas: a == b da True pero a is b da False. Reservá is para None, True y False.

3. ¿Qué devuelve 4 / 2 en Python 3?

/ es división real y siempre devuelve float, aunque la división sea exacta. Si querés el entero, usá //: 4 // 2 da 2.
