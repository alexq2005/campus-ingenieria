Módulo 04 — Structs & Enums

Hasta ahora trabajaste con tipos sueltos: números, booleanos, strings. Pero un programa real modela cosas: un punto en el plano, un usuario, una forma geométrica, un estado. Rust te da dos herramientas para construir tus propios tipos: structs (agrupar datos relacionados) y enums (elegir entre variantes). Y como cierre, conocés Option: el enum que hace que null simplemente no exista.

Structs: agrupar datos relacionados

💡 Un struct es un tipo hecho por vos. En vez de pasar por separado x e y, los juntás en un tipo Punto con nombre. El compilador ahora entiende "un punto", no "dos f64 sueltos que ojalá vayan juntos".

Se define con struct y un bloque de campos con nombre y tipo:

struct Punto {
    x: f64,
    y: f64,
}

fn main() {
    // Instanciar: nombrás cada campo
    let p = Punto { x: 3.0, y: 4.0 };

    // Acceder a los campos con punto
    println!("x = {}, y = {}", p.x, p.y);
}
📌 Para mutar campos, el binding entero debe ser mut. No podés marcar un solo campo como mutable: o todo el struct es mutable (let mut p = ...) o nada. Recién ahí podés hacer p.x = 10.0;.

Tuple structs: campos sin nombre

A veces el nombre del campo no aporta nada — pensá en un color RGB, donde "los tres números" ya se entienden por posición. Para eso existen los tuple structs: tienen tipo pero sus campos son posicionales, como una tupla.

struct Color(u8, u8, u8);

fn main() {
    let rojo = Color(255, 0, 0);

    // Se accede por índice, como una tupla
    println!("R={} G={} B={}", rojo.0, rojo.1, rojo.2);
}
¿Struct normal o tuple struct? Usá campos con nombre cuando el significado importa (x, y, nombre). Usá tuple struct cuando la posición ya es obvia y nombrar sería redundante (un wrapper, un color, una coordenada). En la duda, nombrá los campos.

Métodos: darle comportamiento al struct

Un struct guarda datos; los métodos le dan comportamiento. Se definen en un bloque impl (de implementation) asociado al tipo. El primer parámetro suele ser &self: una referencia a la instancia sobre la que se llama el método.

struct Punto {
    x: f64,
    y: f64,
}

impl Punto {
    // Método: toma &self (la instancia, prestada)
    fn distancia_al_origen(&self) -> f64 {
        (self.x * self.x + self.y * self.y).sqrt()
    }
}

fn main() {
    let p = Punto { x: 3.0, y: 4.0 };
    println!("Distancia: {}", p.distancia_al_origen()); // 5
}
🔗 &self es "este de acá". Cuando escribís p.distancia_al_origen(), Rust pasa p como self automáticamente. El & significa que el método solo lee la instancia prestada, sin tomar posesión (borrowing, M03). Si necesitara modificarla, usaría &mut self.

Métodos asociados: los constructores

No todos los métodos toman self. Los que no reciben self son métodos asociados (parecidos a los métodos estáticos de otros lenguajes). El uso clásico es un constructor que arma y devuelve una instancia con Self (mayúscula = "el tipo de este bloque impl"):

impl Punto {
    // Constructor: no toma self, devuelve Self
    fn nuevo(x: f64, y: f64) -> Self {
        Punto { x, y }   // si el parámetro se llama igual que el campo, va corto
    }
}

fn main() {
    // Se llama con :: sobre el tipo, no con punto sobre una instancia
    let p = Punto::nuevo(3.0, 4.0);
    println!("{}", p.distancia_al_origen());
}
✅ Regla simple: si el método necesita una instancia para trabajar → &self, se llama con p.metodo(). Si fabrica o no depende de una instancia → método asociado, se llama con Tipo::metodo(). Por convención el constructor se llama new (acá nuevo).

Enums: elegir entre variantes

Un struct dice "esto tiene todos estos campos". Un enum dice "esto es una de estas opciones". Lo poderoso en Rust: cada variante puede llevar sus propios datos, y cada una puede llevar datos distintos.

enum Forma {
    Circulo(f64),            // lleva un radio
    Rectangulo(f64, f64),    // lleva ancho y alto
    Punto,                   // no lleva nada
}

fn main() {
    let formas = [
        Forma::Circulo(2.0),
        Forma::Rectangulo(3.0, 4.0),
        Forma::Punto,
    ];
}
💡 Esto es lo que hace especiales a los enums de Rust. En C un enum es solo una lista de nombres. En Rust una variante puede cargar datos (como un struct), y distintas variantes cargan datos distintos. Forma es o un círculo con su radio, o un rectángulo con sus dos lados, o nada — nunca dos a la vez.

match: usar el enum

Para hacer algo distinto según la variante, usás match. Acá lo vemos en su forma básica para sacarle los datos a cada variante — lo exprimimos a fondo en el M05 (Pattern Matching).

fn area(f: &Forma) -> f64 {
    match f {
        Forma::Circulo(r) => 3.14159 * r * r,
        Forma::Rectangulo(ancho, alto) => ancho * alto,
        Forma::Punto => 0.0,
    }
}
📌 match debe ser exhaustivo. Si olvidás una variante, no compila. El compilador te obliga a contemplar todos los casos posibles — adiós a los switch que se olvidan un caso y revientan en runtime.

Option: el enum que reemplaza al null

Acá llegamos a una de las ideas más queridas de Rust. En la mayoría de los lenguajes existe null / nil / None, y olvidarse de manejarlo es la fuente de bugs número uno ("el error de los mil millones de dólares", según su propio inventor). Rust no tiene null.

En su lugar, la ausencia de un valor se modela con el enum Option<T>, que viene en la librería estándar y tiene dos variantes:

enum Option<T> {
    Some(T),   // hay un valor de tipo T adentro
    None,      // no hay valor
}
💡 Si algo puede faltar, su tipo lo dice. Una función que devuelve Option<i32> está declarando en su firma: "a veces hay un número, a veces no". No te podés olvidar de manejar el None, porque el tipo no es i32 directo — para sacar el número de adentro tenés que abrir el Option con match (u otros métodos). 
// Busca el primer número par. Puede no haber ninguno → Option
fn primer_par(nums: &[i32]) -> Option<i32> {
    for &n in nums {
        if n % 2 == 0 {
            return Some(n);   // lo encontramos
        }
    }
    None                      // no había ninguno par
}

fn main() {
    let datos = [1, 3, 4, 7];
    match primer_par(&datos) {
        Some(n) => println!("Primer par: {}", n),
        None => println!("No hay pares"),
    }
}
✅ El tipo te guía. Mientras programás, ver Option<T> en una firma es una señal clara: "manejá la ausencia acá". El compilador no te deja seguir hasta que cubrís el caso None. El bug que en otros lenguajes explota en producción, en Rust ni compila.

#[derive(Debug)]: imprimir tus tipos

Si intentás imprimir un struct propio con println!("{}", p), no compila: Rust no sabe cómo mostrar tu tipo. La solución rápida para depurar es derivar Debug y usar el marcador {:?}:

#[derive(Debug)]
struct Punto {
    x: f64,
    y: f64,
}

fn main() {
    let p = Punto { x: 3.0, y: 4.0 };
    println!("{:?}", p);    // Punto { x: 3.0, y: 4.0 }
    println!("{:#?}", p);   // versión "pretty", en varias líneas
}
{} vs {:?}. {} (Display) es la salida "linda" para el usuario final y la tenés que escribir vos. {:?} (Debug) es la salida para vos, el programador, y la generás gratis con #[derive(Debug)]. Para depurar, casi siempre alcanza con Debug.

Errores típicos al empezar

Querer un campo "vacío" o "null". No existe. Si un campo puede no tener valor, su tipo es Option<T>: por ejemplo apodo: Option<String>. Ausencia = None, presencia = Some(valor).
Olvidar manejar el caso None. No te va a pasar: el compilador no te deja usar el valor de adentro sin antes abrir el Option. Eso es exactamente lo que previene la clase de bugs del null.
Querer imprimir un struct sin derivar Debug. println!("{:?}", p) falla si el tipo no tiene #[derive(Debug)] encima. Agregalo y listo.
⚠️ Option no es lo mismo que null disfrazado. La diferencia es que el tipo te obliga a tratar el caso vacío. Con null el lenguaje confía en que no te olvides; con Option el compilador lo verifica por vos.

Todo junto: struct + impl + enum + Option

#[derive(Debug)]
struct Circulo {
    radio: f64,
}

impl Circulo {
    fn nuevo(radio: f64) -> Self {
        Circulo { radio }
    }
    fn area(&self) -> f64 {
        3.14159 * self.radio * self.radio
    }
}

// Busca un círculo "grande"; puede no haber → Option
fn buscar_grande(circulos: &[Circulo]) -> Option<&Circulo> {
    for c in circulos {
        if c.radio > 10.0 {
            return Some(c);
        }
    }
    None
}

fn main() {
    let c = Circulo::nuevo(5.0);
    println!("{:?} → área {}", c, c.area());

    let lista = [Circulo::nuevo(2.0), Circulo::nuevo(15.0)];
    match buscar_grande(&lista) {
        Some(grande) => println!("Hay uno grande: {:?}", grande),
        None => println!("Ninguno supera radio 10"),
    }
}

Checkpoint — ¿lo tenés claro?

¿Qué diferencia hay entre un struct y un enum?

Un struct agrupa datos que van todos juntos (un punto tiene x y y). Un enum representa una de varias variantes (una Forma es círculo o rectángulo o punto, nunca dos a la vez). En Rust cada variante del enum puede llevar sus propios datos.

¿Por qué Option<T> es mejor que null?

Porque el tipo declara explícitamente que el valor puede faltar, y el compilador te obliga a manejar el caso None antes de usar el valor. Con null, olvidarse de chequear compila igual y explota en runtime; con Option ese bug ni compila.

¿Cuándo un método lleva &self y cuándo no?

Lleva &self cuando opera sobre una instancia existente (se llama p.metodo()). Si no toma self, es un método asociado — típicamente un constructor que devuelve Self — y se llama con Tipo::metodo().

  3. Definí un enum Semaforo con variantes Rojo, Amarillo, Verde y una función que con match devuelva los segundos de cada luz.
  4. Escribí una función dividir(a: f64, b: f64) -> Option<f64> que devuelva None si b es 0 y Some(a / b) si no. Usala con match.
  5. Definí un struct Usuario con un campo opcional apodo: Option<String>. Imprimí "Hola, <apodo>" si hay apodo, o "Hola, anónimo" con match si es None.

🧠 Autoevaluación

1. ¿Qué hace especial a un enum de Rust frente al de C?

En Rust una variante puede cargar datos como un struct, y cada variante puede cargar datos distintos. Forma::Circulo(f64) y Forma::Rectangulo(f64, f64) conviven en el mismo enum.

2. ¿Cómo modela Rust la ausencia de un valor, ya que no existe null?

Rust no tiene null. La ausencia se representa con Option<T>, y el compilador te obliga a manejar el caso None antes de usar el valor.

3. ¿Qué necesitás para imprimir un struct propio con println!("{:?}", p)?

{:?} usa el trait Debug, que se genera gratis con #[derive(Debug)]. Sin eso, Rust no sabe cómo mostrar tu tipo y no compila.
