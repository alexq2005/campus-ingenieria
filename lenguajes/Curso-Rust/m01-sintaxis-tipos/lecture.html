Módulo 01 — Sintaxis & Tipos

Ya tenés Rust instalado y corriste tu primer cargo run. Ahora vamos al ladrillo de cualquier programa: las variables y los tipos. Rust tiene dos decisiones de diseño que lo distinguen de lo que conocés: las variables son inmutables por defecto y el tipado es estático y fuerte (sin conversiones implícitas). Entender esto temprano te ahorra la mitad de las peleas con el compilador.

let: variables inmutables por defecto

💡 En Rust, "variable" no implica "cambia". Cuando escribís let x = 5;, estás creando un binding inmutable: el nombre x queda atado al valor 5 y no podés reasignarlo. Esto es al revés de Python o JavaScript, donde toda variable es mutable salvo que digas lo contrario. Rust invierte el default porque lo inmutable es más fácil de razonar y más seguro en concurrencia. 
fn main() {
    let x = 5;
    println!("x vale {x}");
    x = 6; // ❌ ERROR: cannot assign twice to immutable variable
}

El compilador no te deja compilar eso. Y el mensaje es clarísimo: te dice que x es inmutable y te sugiere agregar mut.

let mut: cuando sí querés mutar

Si necesitás cambiar el valor, declarás la variable con mut (de mutable):

fn main() {
    let mut x = 5;
    println!("antes: {x}");
    x = 6; // ✅ ahora sí: x es mutable
    println!("después: {x}");
}
📌 Regla: usá let por defecto y agregá mut solo cuando realmente vayas a reasignar. Esto le comunica a quien lea tu código (y al compilador) qué cosas pueden cambiar y cuáles no. El linter cargo clippy incluso te avisa si declarás mut y nunca mutás.

Shadowing: redeclarar con let

Hay una tercera vía que no es ni reasignar ni mut: el shadowing. Consiste en declarar otra vez una variable con el mismo nombre usando let. La nueva "tapa" (shadow) a la anterior.

fn main() {
    let x = 5;
    let x = x + 1;      // nueva x = 6 (usa la x vieja)
    let x = x * 2;      // nueva x = 12
    println!("x = {x}"); // x = 12
}
Shadowing ≠ mutación. Cada let crea una variable nueva. Por eso el shadowing puede incluso cambiar el tipo, algo que mut nunca permite: una variable mut conserva su tipo de por vida. 
fn main() {
    let espacios = "   ";          // &str (texto)
    let espacios = espacios.len(); // ahora es usize (un número)
    println!("hay {espacios} espacios");
}

const: constantes verdaderas

Una const es un valor que no cambia nunca y se conoce en tiempo de compilación. Se diferencia de let en tres cosas:

Aspectoletconst
MutabilidadInmutable (o mut)Siempre inmutable
Anotación de tipoOpcional (inferida)Obligatoria
Convención de nombresnake_caseMAYUSCULAS_CON_GUION
Dónde se puede declararDentro de funcionesTambién en scope global
 
const MAX_PUNTOS: u32 = 100_000;

fn main() {
    println!("máximo: {MAX_PUNTOS}");
}
El guion bajo en números es legible. 100_000 es lo mismo que 100000; Rust ignora los _ en literales numéricos. Usalos para agrupar miles y leer mejor.

Tipos escalares

Un tipo escalar representa un solo valor. Rust tiene cuatro familias:

FamiliaEjemplosQué guarda
Enterosi32, u32, i64, usizeNúmeros enteros (con o sin signo)
Flotantesf64, f32Números con decimales
Booleanosbooltrue / false
CaracterescharUn carácter Unicode (4 bytes)
💡 La i y la u dicen si hay signo. i32 es un entero con signo (puede ser negativo), u32 es sin signo (solo ≥ 0). El número es la cantidad de bits: i32 va de -2.147.483.648 a 2.147.483.647. El tipo usize tiene el tamaño de un puntero de tu máquina (32 o 64 bits) y es el que usás para indexar colecciones. 
fn main() {
    let entero: i32 = -42;
    let positivo: u32 = 42;
    let grande: i64 = 9_000_000_000;
    let decimal: f64 = 3.14159;
    let activo: bool = true;
    let letra: char = 'R';
    let emoji: char = '🦀'; // char es Unicode: cabe el cangrejo

    println!("{entero} {positivo} {grande} {decimal} {activo} {letra} {emoji}");
}
Defaults útiles: si no anotás el tipo, Rust asume i32 para enteros y f64 para flotantes. Son las opciones más rápidas/seguras en la mayoría de las CPUs modernas.

Tipos compuestos: tuplas y arrays

Los tipos compuestos agrupan varios valores en uno solo. Rust tiene dos primitivos.

Tuplas

Una tupla agrupa valores que pueden ser de distinto tipo. Tiene tamaño fijo. Accedés a sus elementos con .0, .1, etc., o desestructurando.

fn main() {
    let punto: (i32, f64, char) = (10, 2.5, 'P');

    // Acceso por índice con punto:
    let x = punto.0;
    let y = punto.1;
    println!("x = {x}, y = {y}");

    // Desestructuración (destructuring):
    let (a, b, c) = punto;
    println!("{a} {b} {c}");
}

Arrays

Un array es una colección de elementos del mismo tipo y tamaño fijo. Su tipo se escribe [T; N]: el tipo de los elementos y la cantidad.

fn main() {
    let dias: [&str; 3] = ["lun", "mar", "mie"];
    let ceros = [0; 5]; // [0, 0, 0, 0, 0] — repetir valor

    println!("primer día: {}", dias[0]);
    println!("hay {} ceros", ceros.len());
}
Indexar fuera de rango no es un agujero de seguridad. Si hacés dias[9], Rust no lee memoria basura como C: el programa hace panic y se detiene de forma controlada. Más adelante (M03) vas a conocer Vec<T>, la versión de tamaño variable.

Inferencia de tipos (pero estática)

Rust es de tipado estático: cada valor tiene un tipo conocido en compilación. Pero eso no significa que tengas que escribir el tipo en todos lados — el compilador lo infiere del contexto.

fn main() {
    let x = 5;          // Rust infiere i32
    let x: i32 = 5;     // lo mismo, pero explícito
    let pi = 3.14;      // Rust infiere f64
    let nombre = "Ana"; // Rust infiere &str
}
🔍 Pensalo como un detective. Vos no le decís a Rust "esto es un entero" en cada línea; él lo deduce mirando cómo usás el valor. Pero una vez que decidió el tipo, es inamovible: no podés meter un texto donde dedujo un número. La libertad de no anotar no es la libertad de cambiar de tipo en runtime (eso es Python, no Rust).
¿Cuándo anotar a mano? Cuando Rust no puede inferir solo (ej: let n: u64 = "42".parse().unwrap(); necesita saber a qué número parsear) o cuando querés ser explícito por claridad.

Funciones: sentencias vs expresiones

Las funciones se declaran con fn. Los parámetros siempre llevan tipo anotado, y el tipo de retorno va después de la flecha ->.

fn suma(a: i32, b: i32) -> i32 {
    a + b // sin punto y coma: ESTO es lo que retorna
}

fn main() {
    let resultado = suma(3, 4);
    println!("3 + 4 = {resultado}");
}
💡 La distinción clave de Rust: sentencia vs expresión. Una sentencia hace algo pero no devuelve valor (y termina en ;). Una expresión evalúa a un valor. En una función, la última expresión sin ; es el valor de retorno. Si le ponés ;, la convertís en sentencia y la función retornaría () (la "tupla vacía", el equivalente a "nada"). 
fn doble(x: i32) -> i32 {
    x * 2   // ✅ expresión: retorna x*2
}

fn roto(x: i32) -> i32 {
    x * 2;  // ❌ con ; es sentencia: la función devuelve () pero promete i32
}

También podés ser explícito con return (útil para salir temprano), pero el estilo idiomático en Rust es dejar la última expresión sin ;.

fn clasificar(n: i32) -> &'static str {
    if n < 0 {
        return "negativo"; // salida temprana con return
    }
    if n == 0 { "cero" } else { "positivo" } // if también es expresión
}
Hasta el if es una expresión. Fijate que arriba un if/else devuelve un valor directamente. Eso permite escribir let estado = if n > 0 { "ok" } else { "mal" }; sin variables intermedias.

Conversión explícita con as

Rust nunca convierte tipos numéricos por su cuenta. Si tenés un i32 y una función espera un f64, no compila hasta que vos hagas la conversión explícita con la palabra clave as.

fn main() {
    let entero: i32 = 10;
    let flotante: f64 = entero as f64; // conversión explícita

    let pi: f64 = 3.99;
    let truncado: i32 = pi as i32; // 3 (corta los decimales, no redondea)

    println!("{flotante} y {truncado}");
}
📌 Sin conversiones implícitas, a propósito. En C, mezclar int y float en una operación dispara conversiones automáticas que esconden bugs sutiles (pérdida de precisión, desbordamientos silenciosos). Rust te obliga a escribir as para que vos decidas y la conversión sea visible en el código.
⚠️ as puede perder datos sin avisar. Convertir 300 as u8 da 44 (porque u8 solo llega a 255 y "da la vuelta"), y 3.99 as i32 trunca a 3. as es la herramienta cruda; para conversiones seguras que avisan de overflow existen TryFrom/try_into() (más adelante).

Errores típicos al empezar

Olvidar mut e intentar reasignar. let x = 5; x = 6; no compila. Si vas a cambiar el valor, declará let mut x = 5;. Si solo querés un nuevo valor con el mismo nombre, usá shadowing (let x = 6;).
Esperar conversión implícita de tipos. let r: f64 = 5; falla: 5 es i32, no f64. Escribí 5.0 o 5 as f64. Rust nunca convierte solo.
Poner ; donde querías devolver una expresión. Una función que termina en x * 2; devuelve (), no el número. Sacá el ; de la última línea para que sea el valor de retorno.

Checkpoint — ¿lo tenés claro?

¿En qué se diferencia el shadowing de declarar la variable con mut?

El shadowing crea una variable nueva con let y el mismo nombre, así que puede incluso cambiar de tipo. Una variable mut se reasigna pero conserva su tipo original de por vida.

Una función declara -> i32 y su última línea es x + 1;. ¿Compila?

No. Con el ; esa línea es una sentencia y la función devuelve (), pero prometió devolver i32. Hay que quitar el punto y coma: x + 1.

¿Por qué let total: f64 = 3 + 2; no compila?

Porque 3 y 2 se infieren como i32 y su suma es i32, pero anotaste f64. Rust no convierte implícitamente: usá 3.0 + 2.0 o (3 + 2) as f64.

Ejercicios

  1. Declará let x = 5;, intentá x = 10; y leé el error. Después arreglalo con mut.
  2. Usá shadowing para tomar un &str como "hola" y reemplazarlo por su largo (.len()), cambiando de tipo en el camino.
  3. Definí una const VELOCIDAD_LUZ: u32 = 299_792_458; y mostrala con println!.
  4. Escribí una función fn area(base: f64, altura: f64) -> f64 que retorne el área de un triángulo por expresión (última línea sin ;).
  5. Tomá un f64 como 9.99, convertilo a i32 con as y mostrá el resultado. Explicá por qué da 9 y no 10.

🧠 Autoevaluación

1. ¿Qué diferencia al shadowing de mut?

El shadowing redeclara con let (variable nueva, puede cambiar de tipo). Una variable mut se reasigna pero mantiene su tipo.

2. Una función declara -> i32 y su última línea es resultado; (con punto y coma). ¿Qué pasa?

La última expresión sin ; es el valor de retorno. Con ; se vuelve sentencia y la función devuelve (), que no coincide con i32.

3. ¿Cómo convertís un i32 a f64 en Rust?

Rust no convierte tipos implícitamente. Tenés que escribir la conversión a mano con as, lo que la hace visible en el código.
