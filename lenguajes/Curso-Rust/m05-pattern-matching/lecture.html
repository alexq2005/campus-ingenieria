Módulo 05 — Pattern Matching

En M04 conociste los enums, Option y Result. Ahora viene la herramienta que los hace brillar: el pattern matching. Es la forma idiomática de "abrir" un valor, ver qué hay adentro y reaccionar a cada caso. Si venís de otros lenguajes, pensalo como un switch con superpoderes — pero mucho más seguro, porque el compilador no te deja olvidarte de ningún caso.

match: el switch con superpoderes

La expresión match compara un valor contra una serie de patrones y ejecuta el código del primero que coincide. Cada rama se llama brazo y tiene la forma patrón => expresión.

fn describir(n: i32) -> &'static str {
    match n {
        0 => "cero",
        1 => "uno",
        _ => "otro",   // el comodín: "el resto"
    }
}
El brazo usa => (flecha gorda), no ->. La flecha fina -> aparece en las firmas de funciones para indicar el tipo que devuelven. La flecha gorda => separa el patrón de su expresión dentro del match. Son dos cosas distintas — no las mezcles.

Como match es una expresión, devuelve un valor: podés asignar el resultado directamente a una variable. Todos los brazos deben devolver el mismo tipo.

let texto = match n {
    0 => "cero",
    _ => "no cero",
};

Exhaustividad: la red de seguridad

💡 El compilador te obliga a cubrir TODOS los casos. Un match en Rust es exhaustivo: si dejás un caso sin manejar, no compila. Esto parece molesto al principio, pero es una red de seguridad enorme: si mañana agregás una variante nueva a un enum, el compilador te marca cada match que no la contempla. Bugs de "me olvidé un caso" atrapados gratis, antes de ejecutar.

Por eso el comodín _ es tan útil: cubre "todo lo demás" en un solo brazo. Pero usalo con cuidado — si ponés _ de más, perdés la red de seguridad para las variantes que agregues después.

Desestructurar: sacar los datos de adentro

La verdadera potencia llega cuando el valor contiene datos. El patrón no solo compara: además extrae los datos a variables nuevas. Esto se llama desestructurar.

Enums con datos

enum Evento {
    Click { x: i32, y: i32 },
    Tecla(char),
    Cerrar,
}

fn manejar(e: Evento) {
    match e {
        Evento::Click { x, y } => println!("click en {}, {}", x, y),
        Evento::Tecla(c)       => println!("tecla: {}", c),
        Evento::Cerrar         => println!("adiós"),
    }
}

Option: Some(x) o None

let valor: Option<i32> = Some(7);

match valor {
    Some(x) => println!("hay un {}", x),
    None    => println!("no hay nada"),
}

Result: Ok(v) o Err(e)

let r: Result<i32, String> = "42".parse().map_err(|e: std::num::ParseIntError| e.to_string());

match r {
    Ok(v)  => println!("número: {}", v),
    Err(e) => println!("falló: {}", e),
}

Tuplas y structs

let punto = (0, 5);
match punto {
    (0, 0) => println!("origen"),
    (0, y) => println!("sobre el eje Y, en {}", y),
    (x, 0) => println!("sobre el eje X, en {}", x),
    (x, y) => println!("en {}, {}", x, y),
}

struct Punto { x: i32, y: i32 }
let p = Punto { x: 3, y: 4 };
let Punto { x, y } = p;   // desestructurar directo con let
println!("{} {}", x, y);

if let: cuando solo te importa un patrón

A veces no querés cubrir todos los casos: solo te interesa uno. Escribir un match con un brazo y un _ => {} vacío es verboso. Para eso está if let, que es azúcar sintáctico para "si el valor coincide con este patrón, hacé esto".

let config: Option<i32> = Some(100);

if let Some(x) = config {
    println!("configurado en {}", x);
} else {
    println!("usando default");
}

while let: repetir mientras coincida

El primo de if let para bucles: ejecuta el cuerpo mientras el patrón siga coincidiendo. Muy común al ir vaciando una colección.

let mut pila = vec![1, 2, 3];

while let Some(tope) = pila.pop() {
    println!("saqué {}", tope);
}
// imprime 3, 2, 1 y para cuando pop() devuelve None

Patrones avanzados

Guards: un if dentro del brazo

Una guard es una condición extra (if ...) que se evalúa después de que el patrón coincide. El brazo solo se elige si el patrón coincide y la guard es verdadera.

let n = 4;
match n {
    x if x < 0 => println!("negativo"),
    0          => println!("cero"),
    x if x % 2 == 0 => println!("par positivo"),
    _          => println!("impar positivo"),
}

Rangos: 1..=5

let nota = 8;
match nota {
    0..=3  => println!("insuficiente"),
    4..=6  => println!("aprobado"),
    7..=10 => println!("muy bien"),
    _      => println!("nota inválida"),
}

Binding con @

El operador @ te deja capturar el valor que coincidió con un patrón al mismo tiempo que lo testeás. Útil cuando el patrón es un rango pero igual querés el número concreto.

let edad = 17;
match edad {
    n @ 0..=12  => println!("niño de {} años", n),
    n @ 13..=17 => println!("adolescente de {} años", n),
    n           => println!("adulto de {} años", n),
}
🔍 Pensalo así: el rango 13..=17 es la pregunta ("¿está en este rango?") y n @ es la cámara que saca la foto del valor exacto mientras pasa el control. Sin @ sabrías que coincidió, pero no tendrías el número a mano dentro del brazo.

Ejemplo completo

Un enum, un Option y un if let, todo junto:

enum Semaforo {
    Rojo,
    Amarillo,
    Verde,
}

fn accion(s: &Semaforo) -> &'static str {
    match s {
        Semaforo::Rojo     => "frená",
        Semaforo::Amarillo => "atención",
        Semaforo::Verde    => "avanzá",
    }
}

fn main() {
    let luz = Semaforo::Verde;
    println!("{}", accion(&luz));

    let entrada: Option<i32> = "25".parse().ok();
    match entrada {
        Some(v) if v >= 18 => println!("mayor de edad: {}", v),
        Some(v)            => println!("menor: {}", v),
        None               => println!("entrada inválida"),
    }

    // if let cuando solo me importa el caso Some
    if let Some(v) = entrada {
        println!("el valor era {}", v);
    }
}
📌 Regla práctica: usá match cuando te importan varios casos (o querés la exhaustividad). Usá if let cuando solo te importa uno y el resto no hace nada. Elegir bien hace el código más legible.

Errores comunes

Olvidar un caso (o el _). El match no compila si no es exhaustivo. Esto es bueno: el error te avisa antes de ejecutar. No lo "arregles" tapando todo con _ sin pensar — a veces lo correcto es manejar cada variante.
Confundir => con ->. Dentro del brazo va la flecha gorda =>. La flecha fina -> es solo para el tipo de retorno de una función.
Usar match para un solo caso. Si solo te interesa Some(x) y el resto no hace nada, un match con _ => {} es ruido. if let Some(x) = ... es más limpio.
Poner _ demasiado pronto. Si ponés el comodín antes que un patrón más específico, ese patrón nunca se alcanza. Los brazos se evalúan de arriba hacia abajo: del más específico al más general.
El orden importa. Rust elige el primer brazo que coincide. Si _ está al principio, atrapa todo y los demás brazos quedan muertos (el compilador incluso te avisa con un warning de "unreachable pattern").

Checkpoint — ¿lo tenés claro?

¿Qué significa que un match sea exhaustivo y por qué es útil?

Significa que debe cubrir todos los casos posibles del valor, o no compila. Es útil porque si agregás una variante nueva a un enum, el compilador te obliga a manejarla en cada match — atrapa el bug de "me olvidé un caso" en compilación, no en producción.

¿Cuándo conviene if let en vez de match?

Cuando solo te interesa un patrón y el resto no hace nada. Por ejemplo if let Some(x) = opcion { ... } es más limpio que un match con un brazo útil y un _ => {} vacío.

¿Para qué sirve el binding con @?

Para capturar el valor que coincidió a la vez que lo testeás contra un patrón. Por ejemplo n @ 13..=17 verifica que esté en el rango y además guarda el número exacto en n para usarlo dentro del brazo.
