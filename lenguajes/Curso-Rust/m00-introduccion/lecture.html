Módulo 00 — Introducción & Setup

Rust es un lenguaje de programación de sistemas que nació en Mozilla y hoy es uno de los más queridos del mundo. Su promesa es casi contradictoria: la velocidad de C con la seguridad de memoria garantizada — sin recolector de basura. En este módulo entendés por qué eso importa y dejás el entorno listo.

El problema que Rust resuelve

💡 Todo lenguaje elige en un dilema… menos Rust. Los lenguajes con garbage collector (Python, Java, Go) son seguros pero pausan el programa para limpiar memoria. Los de control manual (C, C++) son rapidísimos pero te dejan cometer errores de memoria catastróficos (use-after-free, null pointers, data races). Rust te da ambas: velocidad de C y seguridad garantizada en compilación, mediante un sistema llamado ownership.

La idea central: en vez de un GC que limpia en runtime, el compilador rastrea quién es "dueño" de cada dato y cuándo se libera. Si tu código podría tener un bug de memoria, no compila. El error se atrapa antes de ejecutar, no en producción.

Instalar Rust

1. Instalá con rustup (el instalador oficial) desde rustup.rs. Trae el compilador (rustc), el gestor de proyectos (cargo) y las herramientas.
2. Verificá en la terminal:
rustc --version    # ej: rustc 1.80.0
cargo --version    # ej: cargo 1.80.0

Tu primer programa

La forma idiomática es crear un proyecto con cargo:

cargo new hola
cd hola
cargo run        # compila y ejecuta

Cargo genera src/main.rs con esto:

fn main() {
    println!("¡Hola, Rust!");
}
📌 Detalles que vas a notar: fn declara funciones, main es el punto de entrada, y println! termina en ! porque es una macro, no una función normal (lo verás más adelante). Cada sentencia termina en ;.

Cargo: el toolchain todo-en-uno

Cargo es el corazón del día a día en Rust. Un solo comando para todo:

ComandoQué hace
cargo newCrea un proyecto nuevo

cargo buildSolo compila (--release para optimizado)
cargo testCorre los tests
cargo fmtFormatea el código (estilo estándar)
cargo clippyLinter: sugiere mejoras idiomáticas

Tres cosas que sorprenden al principio

Las variables son inmutables por defecto. let x = 5; no se puede cambiar. Para mutar hace falta let mut x = 5;. Es a propósito: lo inmutable es más seguro.
No existe null. Donde otros lenguajes usan null/None y explotan, Rust usa Option, que te obliga a manejar el caso "no hay valor" (M04).
Vas a pelearte con el borrow checker. Es normal y temporal: el compilador rechaza código inseguro y te explica por qué. No está roto — te está enseñando a pensar la memoria.
El compilador de Rust es tu profesor: sus mensajes de error son famosos por lo claros — te dicen qué está mal, por qué, y muchas veces cómo arreglarlo. Leelos, no los esquives.

Checkpoint — ¿lo tenés claro?

¿Cómo logra Rust seguridad de memoria sin garbage collector?

Con el sistema de ownership: el compilador rastrea quién es dueño de cada dato y cuándo se libera, en tiempo de compilación. Si el código podría tener un bug de memoria, no compila.

¿Por qué println! lleva !?

Porque es una macro, no una función normal. Las macros se expanden en código en tiempo de compilación; el ! las distingue.

¿Las variables en Rust se pueden cambiar?

No por defecto: let x = 5; es inmutable. Hay que declararlas con let mut para poder mutarlas. La inmutabilidad por defecto previene bugs.

Ejercicios

  1. Instalá Rust con rustup y verificá rustc --version y cargo --version.
  2. Creá un proyecto con cargo new y corrélo con cargo run.
  3. Cambiá el mensaje del println! por tu nombre.
  4. Probá declarar let x = 5; e intentar reasignarlo (x = 6;); mirá el error e arreglalo con mut.
  5. Corré cargo build --release y buscá el binario optimizado en target/release/.
