🕊️ Plataforma de Denuncia Anónima Cifrada

🌍 El problema: denunciar corrupción, abuso o violencia puede costar el trabajo, la libertad o la vida. El miedo a ser identificado silencia a testigos y víctimas. A quién ayuda: periodistas y sus fuentes, víctimas de violencia, denunciantes internos (whistleblowers) y organizaciones de derechos humanos — un canal donde la identidad esté técnicamente protegida, no solo prometida.
🎯 Objetivo: una plataforma donde alguien pueda enviar una denuncia (texto + archivos) de forma anónima y cifrada extremo a extremo: solo el destinatario autorizado puede leerla, y ni siquiera el servidor sabe quién la envió ni qué dice. Vas a aplicar criptografía real y, sobre todo, a pensar como un atacante para proteger al usuario.
⚠️ La seguridad real es difícil y los errores tienen consecuencias humanas. Este es un proyecto de aprendizaje: para uso real con personas en riesgo, se necesitan auditorías profesionales y herramientas probadas (SecureDrop, GlobaLeaks). El valor acá es entender el modelo de amenazas y por qué cada decisión importa.
🔗 Conexión con el campus: M29 Criptografía (cifrado asimétrico, E2E), M31 Seguridad de Apps (modelo de amenazas, metadatos), M30 Redes (anonimato, Tor) y el P19 Gestor Cifrado.

Cómo funciona — cifrado de clave pública

Qué vas a aprender

  • Cifrado asimétrico (clave pública/privada) y extremo a extremo (M29).
  • Modelo de amenazas: ¿de quién protegés al usuario? ¿qué puede ver el atacante? (M31)
  • El peligro de los metadatos: el contenido cifrado no basta si la IP/hora te delata.
  • Anonimato de red (Tor / hidden services) (M30).
  • Minimización de datos: no guardar lo que no necesitás (no podés filtrar lo que no tenés).
  • Pensar como atacante para defender — y la humildad de saber que la cripto casera es riesgosa.

Stack

Backend (Python/Node) · librería cripto seria (libsodium/NaCl — nunca cripto a mano) · cifrado del lado del cliente (el servidor recibe ya cifrado) · acceso vía Tor (hidden service) · sin logs de IP. Inspirate en SecureDrop/GlobaLeaks.

Código clave (cifrado del lado del cliente)

// El navegador del denunciante cifra ANTES de enviar (libsodium / NaCl)
// El servidor solo ve el ciphertext: cifrado extremo a extremo (M29)
const mensajeCifrado = sodium.crypto_box_seal(
  sodium.from_string(denuncia),     // texto en claro (nunca sale del navegador)
  clavePublicaDelPeriodista          // solo su clave privada podrá abrirlo
);

await fetch("/enviar", {             // se envía vía Tor → sin IP real (M30)
  method: "POST",
  body: mensajeCifrado,              // ruido para todos menos el destinatario
});
// El servidor NO puede descifrar: no tiene la clave privada.
// No guarda IP, no guarda timestamps precisos → menos metadatos (M31)
🔗 Tres capas de M29/M30/M31 trabajando juntas: cifrado E2E (el contenido), anonimato de red (quién envió) y minimización de metadatos (cuándo y desde dónde). Cifrar el mensaje no sirve si la IP o la hora delatan a la fuente — proteger a una persona es proteger toda la cadena, no solo el texto.

Fases

Fase 1: escribí el modelo de amenazas: a quién protegés, de quién, y qué pasa si falla cada parte. (Es la fase más importante.)
Fase 2: cifrado de clave pública: cifrar del lado del cliente, descifrar solo con la privada del destinatario.
Fase 3: servidor "buzón ciego" que guarda ciphertext sin poder leerlo ni saber quién envió.
Fase 4: reducir metadatos: sin logs de IP, timestamps difusos, acceso vía Tor.
Fase 5: bandeja del destinatario que descifra localmente + canal de respuesta anónimo.
✅ Terminado cuando:
  • El servidor, aunque sea comprometido, solo expone ruido cifrado.
  • El contenido se cifra en el cliente y solo el destinatario lo descifra.
  • No se guardan IPs ni metadatos que identifiquen a la fuente.
  • Escribiste y defendiste el modelo de amenazas (qué cubre y qué NO).
  • Documentás honestamente los límites y por qué usarías una herramienta auditada en producción.

Variantes

  1. Respuesta bidireccional anónima (código de seguimiento sin identidad).
  2. Borrado de metadatos de archivos adjuntos (EXIF de fotos, etc.).
  3. Verificación de integridad y firma para que la fuente confíe en el destinatario.
  4. Despliegue como hidden service de Tor real (con cuidado).
  5. Auditoría: invitá a alguien a intentar romper tu anonimato y documentá.
