⌨️ Macropad / Teclado Custom

🎯 Objetivo: construir tu propio teclado —desde un macropad de 4 teclas hasta uno completo— que la computadora reconoce como un teclado real (USB HID), con cada tecla programable. Vas a entender por dentro algo que usás todos los días: cómo unos cuantos cables y un microcontrolador se convierten en un periférico que el sistema operativo entiende solo.
🔗 Conexión con el campus: E02 Electrónica Digital (matriz, GPIO, lógica), E03 Microcontrolador (firmware, USB), M14 Sistemas Operativos (drivers, HID) y Linux (cómo el SO ve el dispositivo).

Cómo funciona — la matriz y el escaneo

Qué vas a aprender

  • Matriz de teclas: por qué N×M teclas usan solo N+M pines (E02).
  • Escaneo fila por fila y detección de cruces (incluido el "ghosting" y los diodos).
  • Debounce: filtrar el rebote del contacto mecánico (señal real vs ruido).
  • USB HID: el estándar que hace que cualquier teclado funcione sin drivers (M14).
  • Firmware con QMK (o propio): capas, macros, teclas reprogramables.
  • Soldadura básica y armado de un periférico real.

Componentes

Microcontrolador con USB nativo (RP2040 / Pro Micro / ESP32-S3) · switches mecánicos (o pulsadores para empezar) · diodos 1N4148 (anti-ghosting) · cables. Firmware: QMK/KMK (open source) o uno propio. Empezá con un macropad de 4 teclas en protoboard.

Código clave (escaneo + debounce + HID)

// Escanear la matriz: activar una columna, leer las filas (E02/E03)
for (int c = 0; c < COLS; c++) {
  digitalWrite(colPin[c], LOW);            // activar columna c
  for (int f = 0; f < FILAS; f++) {
    bool pressed = (digitalRead(filaPin[f]) == LOW);
    // Debounce: solo aceptar si el estado se mantiene N lecturas (no rebote)
    if (estable(f, c, pressed) && pressed && !antes[f][c]) {
      Keyboard.press(mapa[f][c]);          // envía por USB HID → el SO lo ve
    }
    antes[f][c] = pressed;
  }
  digitalWrite(colPin[c], HIGH);
}
🔗 El debounce es procesamiento de señal aplicado: el contacto mecánico "rebota" milisegundos y generaría decenas de pulsaciones falsas; filtrarlo es la misma idea de limpiar una señal ruidosa de E07. Y la matriz es lógica digital pura (E02): activás una columna, leés las filas, y el cruce te dice qué tecla. Los diodos evitan el "ghosting" (teclas fantasma) cuando apretás varias a la vez.

Fases

Fase 1: 1 tecla → enviar una letra por USB HID. Que el SO la reciba como teclado real.
Fase 2: matriz de 2×2 con escaneo. Detectá qué tecla se apretó.
Fase 3: debounce robusto + diodos anti-ghosting (apretá varias juntas).
Fase 4: firmware con capas/macros: una tecla que escribe un texto, otra que abre una app.
Fase 5: armado físico: switches, soldadura, una carcasa (impresa 3D o cartón). Tu teclado de verdad.
✅ Terminado cuando:
  • La compu lo reconoce como teclado sin instalar drivers.
  • Cada tecla hace lo que programaste; no hay pulsaciones fantasma ni dobles (debounce ok).
  • Funciona apretando varias teclas a la vez (anti-ghosting).
  • Tenés al menos una macro/capa útil para tu flujo de trabajo.
  • Entendés por qué la matriz ahorra pines y cómo el SO lo ve.

Variantes

  1. Teclado completo (60%) con QMK + keymap propio.
  2. Encoder rotativo (volumen) + pantalla OLED de estado.
  3. RGB por tecla (WS2812) — conecta con el Vúmetro (P12).
  4. Bluetooth (ZMK) en vez de USB — inalámbrico.
  5. Macropad de stream/edición con iconos en pantalla (tipo Stream Deck).
