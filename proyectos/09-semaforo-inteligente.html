Proyecto 09 ⚡ Puente HW+SW ⏱ ~1 semana ESP32/Arduino + C

🚦 Semáforo Inteligente

🎯 Objetivo: construir un semáforo real (3 LEDs) controlado por un microcontrolador, con botón peatonal y temporización. Es el proyecto perfecto para ver una máquina de estados finitos (FSM) hecha hardware — el mismo concepto que estudiaste en teoría, ahora con luces que parpadean de verdad.
🔗 El concepto que une todo: una FSM aparece TRES veces en el campus — M01 (autómatas, teoría), track-senior (state machines en software), y E02 (FSM en silicio). Este proyecto las junta: vas a escribir la FSM en C y verla controlar voltajes reales.

Cómo funciona — la máquina de estados (FSM)

Qué vas a aprender

  • Implementar una FSM en C (estados + transiciones).
  • Controlar GPIO de salida (encender LEDs).
  • Leer GPIO de entrada (botón) con pull-up/pull-down.
  • Manejar tiempo sin bloquear (millis() en vez de delay()).
  • Debounce de un botón físico (rebote mecánico).
  • Diseñar el circuito: resistencias para los LEDs (Ley de Ohm).

Componentes

ESP32 o Arduino · 3 LEDs (rojo, amarillo, verde) · 3 resistencias 220-470Ω · 1 pulsador · 1 resistencia 10kΩ (pull-down) · protoboard · cables. Todo simulable en Wokwi sin comprar nada.

El circuito (Ley de Ohm en acción)

Cada LED necesita su resistencia en serie:
  R = (Vcc - V_led) / I = (3.3V - 2V) / 0.01A ≈ 130Ω → usar 220Ω (seguro)

ESP32 ──[GPIO 25]──[220Ω]──►|──┐ (LED rojo)
       ──[GPIO 26]──[220Ω]──►|──┤ (LED amarillo)    todos a GND
       ──[GPIO 27]──[220Ω]──►|──┘ (LED verde)
       ──[GPIO 14]──── botón ──── 3.3V (con pull-down 10kΩ a GND)

La FSM

Estados:  ROJO → VERDE → AMARILLO → ROJO ...
                                    ↑
          botón peatonal: si está en VERDE, acelera el cambio a AMARILLO

Código (C / Arduino)

enum Estado { ROJO, VERDE, AMARILLO };
Estado estado = ROJO;
unsigned long ultimoCambio = 0;
bool peatonPidio = false;

const int LED_R = 25, LED_A = 26, LED_V = 27, BOTON = 14;

// Duración de cada estado en ms
unsigned long duracion(Estado e) {
  switch (e) {
    case ROJO:     return 5000;
    case VERDE:    return peatonPidio ? 1500 : 5000;  // acelera si hay peatón
    case AMARILLO: return 1500;
  }
  return 5000;
}

void setEstado(Estado e) {
  digitalWrite(LED_R, e == ROJO);
  digitalWrite(LED_A, e == AMARILLO);
  digitalWrite(LED_V, e == VERDE);
  estado = e;
  ultimoCambio = millis();
}

void setup() {
  pinMode(LED_R, OUTPUT); pinMode(LED_A, OUTPUT); pinMode(LED_V, OUTPUT);
  pinMode(BOTON, INPUT);          // con pull-down externo
  setEstado(ROJO);
}

void loop() {
  // Leer botón (sin bloquear)
  if (digitalRead(BOTON) == HIGH && estado == VERDE) {
    peatonPidio = true;
  }

  // Transición por tiempo (sin delay — usa millis)
  if (millis() - ultimoCambio >= duracion(estado)) {
    switch (estado) {
      case ROJO:     setEstado(VERDE); break;
      case VERDE:    setEstado(AMARILLO); break;
      case AMARILLO: setEstado(ROJO); peatonPidio = false; break;
    }
  }
}
🔗 Por qué millis() y no delay(): delay(5000) congela el chip 5 segundos — no podría leer el botón mientras tanto. Usar millis() es el patrón "non-blocking" que en software conocés como no bloquear el event loop (M06) o el scheduler cooperativo (M14). Mismo principio, otro dominio.

Fases

Fase 1: armá el circuito en Wokwi. 3 LEDs que prenden de a uno en secuencia con delay() (versión simple).
Fase 2: convertí a FSM con millis() (non-blocking).
Fase 3: agregá el botón peatonal con debounce.
Fase 4: sumá un segundo semáforo (cruce) que esté sincronizado al revés.
✅ Terminado cuando:
  • El semáforo cicla rojo→verde→amarillo→rojo con tiempos correctos.
  • El botón peatonal funciona y acelera el cambio (sin congelar el sistema).
  • El código usa una FSM clara (enum + switch), no spaghetti de delays.
  • Cada LED tiene su resistencia calculada con Ley de Ohm.

Variantes

  1. Cruce completo: 2 semáforos peatonales + 2 vehiculares sincronizados.
  2. Modo nocturno: amarillo titilante después de cierta hora (RTC).
  3. Sensor de tráfico: un sensor que detecta autos y ajusta los tiempos.
  4. Control remoto vía WiFi/MQTT (conecta con la estación meteo y M37 IoT).
  5. Display con cuenta regresiva (pantalla de 7 segmentos o OLED).
