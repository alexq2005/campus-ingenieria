Proyecto 21 Avanzado ⏱ ~1-2 semanas Docker + Compose

🐳 Stack Docker Multi-servicio

🎯 Objetivo: empaquetar una aplicación real completa —frontend, API, base de datos y un reverse proxy— en contenedores que arrancan con un solo comando. Vas a resolver de raíz el "en mi máquina funciona": el stack corre igual en tu laptop, en la de un compañero y en un servidor.
🔗 Conexión con el campus: M27 DevOps (contenedores, orquestación), Linux redes (puertos, networking), Linux procesos (aislamiento) y M38 Cloud (deploy).

Cómo funciona — un stack, una red interna

Qué vas a aprender

  • Diferencia entre imagen y contenedor, y por qué aíslan procesos (Linux).
  • Escribir un Dockerfile eficiente (capas, multi-stage build).
  • Orquestar varios servicios con docker-compose.
  • Redes entre contenedores y qué exponer al exterior (seguridad).
  • Volúmenes: persistir datos fuera del ciclo de vida del contenedor.
  • Variables de entorno y secretos (no hardcodear credenciales).

Stack

Docker + docker-compose · una API (FastAPI/Express) · frontend (React build servido por nginx) · PostgreSQL · nginx como reverse proxy. Todo en Linux (nativo o WSL2).

Código clave (docker-compose.yml)

services:
  proxy:
    image: nginx:alpine
    ports: ["80:80"]              # ÚNICO puerto expuesto al exterior
    depends_on: [api, web]
    volumes: ["./nginx.conf:/etc/nginx/nginx.conf:ro"]

  web:
    build: ./frontend            # tu React
    expose: ["3000"]             # solo visible en la red interna

  api:
    build: ./backend
    expose: ["8000"]
    environment:
      DATABASE_URL: postgres://app:${DB_PASS}@db:5432/app
    depends_on: [db]

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: ${DB_PASS}
    volumes: ["pgdata:/var/lib/postgresql/data"]   # datos persistentes

volumes:
  pgdata:
🔗 Fijate que api conecta a db por su nombre de servicio (db:5432), no por IP — Docker resuelve eso con DNS interno (M15 Redes). Y expose vs ports: ports abre al mundo, expose solo a la red interna. Esa distinción es seguridad (M30): minimizás la superficie expuesta.

Fases

Fase 1: dockerizá UN servicio (la API). Escribí su Dockerfile y corré docker build/run.
Fase 2: sumá PostgreSQL como segundo servicio en compose. La API se conecta a la base.
Fase 3: agregá el frontend y nginx como reverse proxy. Una sola URL para todo.
Fase 4: volúmenes para persistir la base, variables de entorno para secretos, healthchecks.
Fase 5: optimizá imágenes (multi-stage, alpine) y documentá el up/down.
✅ Terminado cuando:
  • docker compose up levanta toda la app y funciona end-to-end.
  • Solo el proxy está expuesto; la base NO es accesible desde afuera.
  • Los datos sobreviven a docker compose down && up (volumen).
  • No hay credenciales hardcodeadas (usás variables de entorno).
  • Otra persona clona el repo y levanta todo sin instalar dependencias a mano.

Variantes

  1. Agregá Redis como caché (conecta con P24).
  2. HTTPS con certificados (Let's Encrypt / Caddy) — cripto en tránsito (M29).
  3. Healthchecks y reinicio automático de servicios caídos.
  4. Pipeline CI/CD que construye y publica las imágenes (P22).
  5. Deploy en un VPS real o en Kubernetes (M38 Cloud).
