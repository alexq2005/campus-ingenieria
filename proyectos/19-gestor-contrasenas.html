🔐 Gestor de Contraseñas Cifrado

🎯 Objetivo: una bóveda donde guardás tus contraseñas cifradas con AES-256, protegida por una sola clave maestra. El archivo en disco es ruido ilegible sin la clave. Vas a aplicar criptografía de verdad — derivación de claves, cifrado autenticado, salt — y entender por qué cada pieza importa.
⚠️ Proyecto educativo. Para tus contraseñas reales usá un gestor auditado (Bitwarden, KeePass). El valor acá es entender cómo funcionan por dentro, no reemplazarlos. La cripto casera en producción es peligrosa.
🔗 Conexión con el campus: M29 Criptografía (AES, KDF, hashing), M31 Seguridad de Apps (manejo de secretos), Python (I/O binario) y errores (fallar seguro).

Cómo funciona — de la clave maestra al cifrado

Qué vas a aprender

  • Diferencia entre hashing (contraseñas) y cifrado (datos recuperables) (M29).
  • KDF (Argon2/PBKDF2): por qué derivar la clave debe ser lento a propósito.
  • AES-GCM: cifrado autenticado — detecta si tocaron el archivo.
  • El rol del salt y del nonce, y por qué nunca se reutilizan.
  • Manejo de secretos en memoria y por qué no loguear la clave.
  • Generador de contraseñas fuertes con entropía real.

Stack

Python · librería cryptography (no implementes AES vos mismo) · argon2-cffi para el KDF · CLI con argparse o un frontend simple. Nunca: md5, DES, ni ECB.

Código clave (derivar y cifrar)

import os
from argon2.low_level import hash_secret_raw, Type
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

def derivar_clave(maestra: str, salt: bytes) -> bytes:
    # KDF LENTO a propósito: frena la fuerza bruta (M29)
    return hash_secret_raw(maestra.encode(), salt,
        time_cost=3, memory_cost=64*1024, parallelism=4,
        hash_len=32, type=Type.ID)

def cifrar(maestra, datos: bytes):
    salt  = os.urandom(16)
    nonce = os.urandom(12)              # único por cifrado, NUNCA se repite
    clave = derivar_clave(maestra, salt)
    ct = AESGCM(clave).encrypt(nonce, datos, None)   # cifra + autentica
    return salt + nonce + ct           # todo junto en disco
🔗 Tres detalles de M29 que separan lo seguro de lo roto: el KDF lento (Argon2 tarda a propósito), el nonce único (reutilizarlo rompe GCM) y el tag de autenticación (si alguien edita el archivo, el descifrado falla en vez de dar basura). Por eso nunca se hace cripto a mano.

Fases

Fase 1: generador de contraseñas fuertes (longitud, símbolos) usando secrets, no random.
Fase 2: cifrá y descifrá un texto con AES-GCM y una clave derivada. Verificá el round-trip.
Fase 3: bóveda: guardá pares (servicio, usuario, contraseña) cifrados en un archivo.
Fase 4: CLI: add, get, list, delete. Pide la clave maestra y la mantiene solo en memoria.
Fase 5: manejá errores: clave incorrecta, archivo corrupto (el tag GCM lo detecta), y fallá seguro.
✅ Terminado cuando:
  • El archivo de la bóveda es ilegible sin la clave maestra (abrílo y comprobá que es ruido).
  • Una clave maestra incorrecta NO descifra (falla limpio, no devuelve basura).
  • Si editás un byte del archivo, el descifrado falla (autenticación GCM).
  • Usás Argon2/PBKDF2 con costo alto, salt y nonce aleatorios únicos.
  • La clave maestra nunca se escribe a disco ni a logs.

Variantes

  1. Autocompletado en el navegador (extensión) — cuidado con la superficie de ataque.
  2. Sincronización cifrada extremo a extremo entre dispositivos.
  3. 2FA / TOTP: generá códigos de un solo uso (más cripto).
  4. Auditoría de contraseñas: detectá las débiles o repetidas (sin exponerlas).
  5. Chequeo contra filtraciones con k-anonymity (HaveIBeenPwned API).
