💬 Chatbot con RAG

🎯 Objetivo: un chatbot que responde preguntas sobre tus propios documentos (apuntes, manuales, un PDF) sin inventar. La técnica es RAG (Retrieval-Augmented Generation): buscás los fragmentos relevantes y se los das al LLM como contexto, para que responda con datos reales en vez de alucinar.
🔗 Conexión con el campus: M41 NLP (embeddings, tokenización), M43 Data Engineering (pipeline de ingesta), M21 NoSQL (base vectorial) y Python (leer/parsear documentos).

Cómo funciona — el pipeline RAG

Qué vas a aprender

  • Qué es un embedding: convertir texto en un vector que captura significado (M41).
  • Chunking: cómo partir documentos para que la búsqueda funcione bien.
  • Búsqueda por similitud de coseno en una base vectorial.
  • Prompt engineering: armar el contexto para que el LLM no alucine.
  • Por qué RAG reduce alucinaciones y permite citar fuentes.
  • Medir calidad: ¿responde bien? ¿cita el fragmento correcto?

Stack

Python · librería de embeddings (sentence-transformers, local y gratis, o la API de OpenAI) · vector DB: ChromaDB o FAISS (locales) · un LLM (Ollama local con Llama/Mistral, o una API). Frontend opcional con Streamlit o React.

Código clave (recuperar + generar)

from sentence_transformers import SentenceTransformer
import chromadb

embed = SentenceTransformer("all-MiniLM-L6-v2")
db = chromadb.Client().create_collection("docs")

# INGESTA: indexar chunks
for i, chunk in enumerate(chunks):
    db.add(ids=[str(i)], embeddings=[embed.encode(chunk).tolist()],
           documents=[chunk])

# CONSULTA
def responder(pregunta):
    q_vec = embed.encode(pregunta).tolist()
    hits = db.query(query_embeddings=[q_vec], n_results=3)
    contexto = "\n".join(hits["documents"][0])     # trozos relevantes
    prompt = f"""Respondé SOLO con este contexto. Si no está, decí "no sé".
Contexto:\n{contexto}\n\nPregunta: {pregunta}"""
    return llm(prompt)                              # llamar al LLM
🔗 El embed.encode() convierte texto en un punto en un espacio de cientos de dimensiones donde "cercano = parecido en significado" (M41). Buscar es geometría: el vecino más cercano al vector de la pregunta. La instrucción "si no está, decí no sé" es lo que frena la alucinación.

Fases

Fase 1: tomá un texto (un PDF, tus apuntes), partilo en chunks, generá embeddings y guardalos.
Fase 2: dada una pregunta, recuperá los 3 chunks más similares. Verificá que sean relevantes.
Fase 3: conectá un LLM (Ollama local es gratis). Armá el prompt con el contexto y obtené respuestas.
Fase 4: citá fuentes: mostrá de qué fragmento salió la respuesta. Manejá "no sé".
Fase 5: interfaz de chat con historial y un set de preguntas de prueba para medir calidad.
✅ Terminado cuando:
  • Responde correctamente preguntas cuya respuesta está en tus documentos.
  • Dice "no sé" cuando la respuesta NO está (no inventa).
  • Cita el fragmento de origen de cada respuesta.
  • Funciona con un LLM local (no dependés de una API paga).
  • Entendés por qué el chunking y el tamaño del contexto afectan la calidad.

Variantes

  1. RAG sobre el propio campus: que responda dudas de los lectures.
  2. Re-ranking de los resultados para mejorar la precisión.
  3. Memoria de conversación (preguntas de seguimiento).
  4. Evaluación automática con un set de QA y métricas (groundedness).
  5. Deploy como API (conecta con P23) + frontend React.
