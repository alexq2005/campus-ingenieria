❤️ Monitor de Signos Vitales de Bajo Costo

🌍 El problema: un oxímetro de pulso —que mide oxígeno en sangre (SpO₂) y ritmo cardíaco— es vital para detectar problemas respiratorios y cardíacos, pero su costo y disponibilidad son una barrera en muchos lugares (lo vimos crudamente en la pandemia). A quién ayuda: centros de salud con pocos recursos, escuelas, hogares de cuidado y campañas de salud comunitaria que necesitan medir signos vitales de muchas personas.
🎯 Objetivo: construir un monitor que mida ritmo cardíaco y SpO₂ con un sensor óptico de pocos dólares, aplicando procesamiento de señal (E07) para extraer el pulso de una señal ruidosa. Vas a entender cómo funciona la fotopletismografía — la misma tecnología de tu smartwatch.
⚠️ Proyecto educativo, no dispositivo médico certificado. Sirve para aprender y para tendencias, no para decisiones clínicas. Los equipos médicos reales pasan validación estricta. El valor acá es entender la fisiología y el DSP detrás.
🔗 Conexión con el campus: E07 DSP (filtrado, detección de picos, FFT), E06 Señales (frecuencia del pulso), E05 (sensor óptico) y E03 (ADC).

Cómo funciona — el latido en la luz

Qué vas a aprender

  • Fotopletismografía (PPG): cómo la luz mide el flujo sanguíneo (E05).
  • Filtrar una señal biológica ruidosa: pasa-banda para aislar el pulso (E07).
  • Detección de picos y cálculo de frecuencia cardíaca (BPM).
  • El principio del SpO₂: ratio de absorción luz roja/infrarroja.
  • Manejo de artefactos de movimiento (el gran enemigo de los wearables).
  • Mostrar tendencias y alertar fuera de rango (con los disclaimers correctos).

Componentes

ESP32/Arduino + sensor MAX30102 (pulso + SpO₂, ~3 USD) · pantalla OLED · batería. El MAX30102 ya trae los LEDs rojo/IR y el fotodiodo; vos hacés el DSP.

Código clave (pulso por detección de picos)

// 1) Filtrar la señal PPG cruda (pasa-banda ~0.5-4 Hz = 30-240 bpm) (E07)
float filtrada = pasaBanda(muestraCruda);

// 2) Detectar picos: un latido = cruce ascendente sobre un umbral adaptativo
if (filtrada > umbral && !enPico) {
  enPico = true;
  unsigned long ahora = millis();
  long intervalo = ahora - ultimoLatido;     // tiempo entre latidos
  ultimoLatido = ahora;
  if (intervalo > 300 && intervalo < 2000)   // descartar ruido (E06: 30-200 bpm)
    bpm = 60000.0 / intervalo;               // frecuencia → pulsaciones/min
} else if (filtrada < umbral) {
  enPico = false;
}
🔗 El pasa-banda de E07 es lo que hace funcionar todo: la señal cruda está llena de ruido de luz ambiente y movimiento; filtrar a la banda del pulso (0.5–4 Hz, E06) la limpia. El intervalo entre picos es el período; su inverso, la frecuencia. Pura teoría de señales aplicada a tu corazón.

Fases

Fase 1: leé el sensor y graficá la señal PPG cruda por serial. Verás los latidos a simple vista.
Fase 2: filtrá (pasa-banda) y detectá picos. Calculá BPM y comparalo con tu pulso real.
Fase 3: estimá SpO₂ con la relación rojo/IR. Compará con un oxímetro comercial.
Fase 4: rechazo de movimiento: detectá cuando la lectura no es confiable y avisá.
Fase 5: pantalla con BPM/SpO₂ en vivo, tendencia, y alerta fuera de rango (con disclaimer).
✅ Terminado cuando:
  • El BPM coincide con tu pulso real (contado a mano) dentro de ±3.
  • El SpO₂ se acerca a un oxímetro comercial en reposo.
  • Detecta y descarta lecturas con movimiento en vez de mostrar valores falsos.
  • Explicás el rol del filtro y por qué la señal cruda no sirve directa.
  • La interfaz deja claro que es educativo, no clínico.

Variantes

  1. Integralo con el Detector de Caídas (un wearable de salud completo).
  2. Variabilidad de la frecuencia cardíaca (HRV) como indicador de estrés.
  3. Registro a la nube para seguimiento de un paciente crónico (con privacidad).
  4. Detección de arritmias simples a partir de los intervalos.
  5. Versión con cámara de celular (rPPG): pulso sin contacto.
