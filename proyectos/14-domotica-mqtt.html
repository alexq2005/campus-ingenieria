🏠 Domótica con MQTT

🎯 Objetivo: controlar y monitorear tu casa desde el navegador. Sensores físicos (temperatura, movimiento, luz) y actuadores (relés, luces) publican y reciben mensajes a través de un broker MQTT, y un dashboard web muestra todo en tiempo real. Es el patrón publish/subscribe que mueve el IoT del mundo real.
🔗 Conexión con el campus: integra E03/E04 (ESP32, WiFi), E05 (sensores y relés), M15 Redes (TCP, protocolos), M37 IoT y React (dashboard).

Cómo funciona — el patrón publish/subscribe

Qué vas a aprender

  • El protocolo MQTT: topics, QoS, retained messages, last will.
  • Conectar un ESP32 a WiFi y publicar/suscribir (E03/E04).
  • Leer sensores y accionar relés de forma segura (E05).
  • Levantar un broker (Mosquitto local o un broker cloud).
  • Un dashboard web que se suscribe vía MQTT-over-WebSockets.
  • Diseño desacoplado: agregar dispositivos sin tocar el resto.

Stack

ESP32 + sensores (DHT22, PIR, LDR) + módulo relé · broker Mosquitto (Docker) o HiveMQ Cloud · librería PubSubClient (Arduino) · dashboard React + mqtt.js sobre WebSockets. Simulable en Wokwi + broker público de pruebas.

Código clave (el nodo ESP32)

#include <WiFi.h>
#include <PubSubClient.h>

WiFiClient wifi;
PubSubClient mqtt(wifi);

void callback(char* topic, byte* payload, unsigned int len) {
  // Llega un mensaje a un topic suscrito (ej: casa/luz = "ON")
  if ((char)payload[0] == 'O' && (char)payload[1] == 'N')
    digitalWrite(RELE, HIGH);          // accionar relé (E05)
  else
    digitalWrite(RELE, LOW);
}

void loop() {
  if (!mqtt.connected()) reconectar();
  mqtt.loop();

  float t = leerDHT22();               // sensor (E05)
  char msg[8];
  dtostrf(t, 4, 1, msg);
  mqtt.publish("casa/temp", msg);      // publicar lectura
  delay(2000);
}
🔗 El callback es el patrón observer (M24 Patrones de Diseño) sobre la red: el dispositivo "reacciona" a mensajes sin saber quién los envió. Y MQTT corre sobre TCP (M15 Redes), por eso garantiza orden y entrega.

Fases

Fase 1: ESP32 publica una lectura de sensor a un broker público de pruebas. Verificá con mosquitto_sub desde tu PC (Linux).
Fase 2: levantá tu propio broker Mosquitto en Docker. Asegurá con usuario/contraseña.
Fase 3: segundo ESP32 que se suscribe y acciona un relé/LED al recibir un comando.
Fase 4: dashboard React que muestra las lecturas en vivo y tiene botones para controlar los actuadores.
Fase 5: persistí el histórico en una base de datos y graficá tendencias (conecta con P23).
✅ Terminado cuando:
  • Un sensor físico publica y lo ves cambiar en el dashboard en <1 segundo.
  • Un botón del dashboard enciende/apaga un dispositivo real.
  • El broker exige autenticación (no está abierto al mundo).
  • Podés agregar un dispositivo nuevo sin tocar el código de los demás.
  • Usaste retained + last will para estado y detección de caídas.

Variantes

  1. Reglas de automatización ("si temp > 26 → encender ventilador") — conecta con E08 Control.
  2. Integración con Home Assistant o Google Home.
  3. App móvil en vez de web (M34 Mobile).
  4. Cifrado TLS en el broker (M29 Criptografía) — ver también P19.
  5. Modo offline: el nodo guarda lecturas y las sincroniza al reconectar.
