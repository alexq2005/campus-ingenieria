🔐 Control de Acceso RFID

🎯 Objetivo: una cerradura inteligente que abre solo a quien tiene una tarjeta autorizada. Acercás la tarjeta RFID, el sistema la valida contra una base de datos de permisos, abre (o no) la cerradura, y registra cada intento con quién y cuándo. Es un sistema completo: electrónica + datos + seguridad, lo mismo que controla la puerta de una oficina o un gimnasio.
🔗 Conexión con el campus: E05 Sensores/Actuadores (lector RFID, relé/cerradura), M19 SQL (usuarios, permisos, logs), M31 Seguridad (autenticación, qué se puede clonar) y el P23 API+SQL.

Cómo funciona — leer, validar, registrar

Qué vas a aprender

  • Leer una tarjeta RFID/NFC (MFRC522) y su UID (E05).
  • Accionar una cerradura eléctrica con relé de forma segura (E05/E00).
  • Modelar la base de datos: usuarios, tarjetas, permisos, logs (M19).
  • Auditoría: registrar cada acceso (autorizado y denegado).
  • Seguridad real: por qué el UID se puede clonar y qué hacer (M31).
  • Panel web para dar de alta/baja tarjetas y ver el historial.

Componentes

ESP32 + lector MFRC522 (RFID 13.56 MHz) + relé + cerradura/electroimán + fuente · base de datos (SQLite local o un backend, P23) · pantalla/LED de estado. ⚠️ La parte de potencia (cerradura) aislada y con su fuente.

Código clave (validar contra la base)

String uid = leerTarjeta();                 // UID de la tarjeta (E05)

// Validar contra la base — SIEMPRE parametrizado (sin inyección, M31)
bool ok = db.consultar(
  "SELECT 1 FROM permisos WHERE uid = ? AND activo = 1", uid);

registrarAcceso(uid, ok, ahora());          // log SIEMPRE (auditoría)

if (ok) abrirCerradura(3000);               // abre 3s (E05)
else    parpadearRojo();                     // denegado
🔗 Dos lecciones se cruzan: la query es parametrizada (el ?) para evitar inyección SQL (M31) —porque el UID viene "de afuera"—, y el log que se escribe siempre (autorizado o no) es el principio de auditoría de seguridad: no podés investigar lo que no registraste. Bonus honesto: el UID de una tarjeta común se puede clonar; para seguridad seria se usa autenticación criptográfica de la tarjeta (M29), no solo el UID.

Fases

Fase 1: leé el UID de una tarjeta y mostralo por serial.
Fase 2: lista de UIDs autorizados (en código). Encendé un LED verde/rojo según corresponda.
Fase 3: base de datos real: usuarios, tarjetas, permisos. Accioná el relé/cerradura.
Fase 4: log de cada acceso (quién, cuándo, resultado). Panel para verlo.
Fase 5: alta/baja de tarjetas desde una web + análisis de accesos (P18). Seguridad: discutí el clonado.
✅ Terminado cuando:
  • Solo las tarjetas autorizadas abren; las demás quedan registradas como denegadas.
  • Cada acceso (ok o no) queda en el log con hora.
  • Podés dar de alta/baja una tarjeta sin reprogramar el micro.
  • Las queries son parametrizadas (no inyectables).
  • Entendés y explicás el límite de seguridad (clonado del UID).

Variantes

  1. Doble factor: tarjeta + PIN en un teclado.
  2. Horarios: una tarjeta solo válida en ciertos días/horas.
  3. Sincronización a la nube y multi-puerta (varios lectores, un panel).
  4. Notificación al celular cuando alguien entra (P14 MQTT).
  5. Reemplazar RFID por huella o QR; o autenticación cripto de la tarjeta (M29).
