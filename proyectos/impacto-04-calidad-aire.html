🌫️ Estación de Calidad del Aire Colaborativa

🌍 El problema: la contaminación del aire causa ~7 millones de muertes prematuras al año (OMS), pero las estaciones oficiales son pocas y caras — barrios enteros no tienen datos. A quién ayuda: vecinos, escuelas y personas con asma que necesitan saber cuándo el aire está peligroso, y comunidades que quieren evidencia para exigir acción. Una red de sensores baratos democratiza ese dato.
🎯 Objetivo: construir una estación que mide partículas finas (PM2.5) y CO₂, calcula el índice de calidad del aire (AQI) y lo publica a un mapa abierto en tiempo real. Muchas estaciones baratas juntas dan una resolución que ninguna estación oficial cara puede igualar.
🔗 Conexión con el campus: E05 Sensores, E03/E04 (ESP32, WiFi), M37 IoT, React (mapa) y el Proyecto 18 (EDA) para analizar tendencias.

Cómo funciona — del barrio al mapa

Qué vas a aprender

  • Medir PM2.5/PM10 con un sensor láser y CO₂ (E05).
  • Calcular el AQI (índice estandarizado) a partir de las concentraciones.
  • Publicar datos georreferenciados a la nube (MQTT/HTTP, M37).
  • Construir un mapa de calor web con datos en vivo.
  • Calibración: por qué los sensores baratos derivan y cómo corregirlos.
  • Datos abiertos: ética de compartir y la potencia de lo colaborativo.

Componentes

ESP32 + sensor PMS5003 (PM2.5 láser) + MH-Z19 o SCD40 (CO₂) + sensor de temp/humedad (afectan la lectura) · caja ventilada para exterior. Backend simple + mapa con Leaflet o React.

Código clave (lectura + AQI + publicación)

// Leer PM2.5 del sensor láser (E05) y publicar con ubicación
float pm25 = leerPMS5003();
int aqi = calcularAQI(pm25);          // tabla estándar concentración → índice

String payload = "{\"lat\":" + String(LAT, 5) +
                 ",\"lon\":" + String(LON, 5) +
                 ",\"pm25\":" + String(pm25, 1) +
                 ",\"aqi\":" + String(aqi) + "}";

http.POST(payload);                   // → servidor → mapa (M37)
mostrarSemaforo(aqi);                 // LED verde/amarillo/rojo local
🔗 El dato crudo (μg/m³) no le dice nada a un vecino; el AQI lo traduce a "bueno/malo" con colores — eso es diseño de información. Y como los sensores baratos derivan, conviene cruzar tus datos con una estación oficial cercana y calibrar (P18 EDA): el análisis de datos arregla las limitaciones del hardware barato.

Fases

Fase 1: leé PM2.5 y CO₂ y mostralos por serial. Comparalos con apps oficiales de tu ciudad.
Fase 2: calculá el AQI y mostralo con un semáforo de LEDs local.
Fase 3: publicá las lecturas (con lat/lon) a un servidor o broker (M37).
Fase 4: mapa web con los puntos coloreados por AQI, actualizándose en vivo.
Fase 5: calibración contra una estación de referencia (P18) y caja para exterior.
✅ Terminado cuando:
  • Tus lecturas siguen la tendencia de una estación oficial cercana.
  • El AQI se muestra con colores entendibles para cualquier vecino.
  • Los datos llegan al mapa en tiempo real y son públicos.
  • Aplicaste una corrección de calibración documentada.
  • La caja resiste a la intemperie y el sensor respira bien.

Variantes

  1. Alerta a vecinos con asma cuando el AQI supera un umbral.
  2. Correlacionar contaminación con tráfico/hora/clima (P18 EDA).
  3. Sumar ruido ambiental (otra forma de contaminación urbana).
  4. Integrar con redes globales abiertas (Sensor.Community).
  5. Energía solar para autonomía total en la calle.
