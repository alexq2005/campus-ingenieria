Proyecto 26 ⚡ Puente HW+SW ⏱ ~2-3 semanas Game loop + pantalla

🎮 Consola Portátil Retro

🎯 Objetivo: armar una mini consola de mano —microcontrolador, una pantalla chica y unos botones— y programarle un juego (Snake, Pong, un plataformas). Es la forma más divertida de entender el game loop y de pelear con recursos limitados: pocos KB de RAM te obligan a programar con la cabeza, como en la era dorada de las consolas.
🔗 Conexión con el campus: E03 Microcontrolador (GPIO, SPI a la pantalla), M35 Game Development (game loop, física, colisiones), M36 Gráficos (sprites, framebuffer) y el loop sensar-decidir-actuar (P10) — es el mismo bucle.

Cómo funciona — el game loop

Qué vas a aprender

  • El game loop y por qué el delta time mantiene la velocidad constante (M35).
  • Manejar una pantalla por SPI/I2C (OLED o TFT) desde el micro (E03).
  • Framebuffer y dibujo de sprites pixel a pixel (M36).
  • Detección de colisiones simple (cajas).
  • Programar con recursos limitados (KB de RAM): el arte de la optimización.
  • Sonido simple (buzzer) y guardar el high-score (EEPROM).

Componentes

Microcontrolador (RP2040 / ESP32 / Arduino) · pantalla OLED 128×64 (SSD1306) o TFT pequeña · 2-4 botones · buzzer · batería. Empezá con Snake en la OLED — es el "hola mundo" de los juegos en micro.

Código clave (el loop a ritmo constante)

unsigned long anterior = 0;
const int MS_POR_FRAME = 33;          // ~30 FPS

void loop() {
  unsigned long ahora = millis();
  if (ahora - anterior < MS_POR_FRAME) return;   // mantener ritmo constante
  anterior = ahora;

  leerBotones();        // 1) INPUT (E03)
  actualizar();         // 2) UPDATE: mover, colisiones, reglas (M35)
  dibujar();            // 3) RENDER: framebuffer → pantalla (M36)
}

void actualizar() {
  serpiente.avanzar(direccion);
  if (serpiente.choca(manzana)) { crecer(); nuevaManzana(); puntos++; }
  if (serpiente.chocaConsigoMisma()) gameOver();
}
🔗 Limitar el loop a MS_POR_FRAME es control de tiempo: sin eso, el juego correría a la velocidad del micro (distinta en cada placa) y sería injugable. Es la versión simple del delta time de M35. Y dibujar en un framebuffer antes de mandarlo a la pantalla evita el parpadeo — la misma idea del doble buffer de M36.

Fases

Fase 1: encendé la pantalla y dibujá un pixel/texto desde el micro.
Fase 2: game loop básico: un punto que se mueve con los botones a ritmo constante.
Fase 3: el juego completo (Snake/Pong): reglas, colisiones, puntaje, game over.
Fase 4: pulido: sonido (buzzer), high-score en EEPROM, pantalla de inicio.
Fase 5: armado portátil: batería, carcasa, botones cómodos. Tu consola de bolsillo.
✅ Terminado cuando:
  • El juego es jugable de principio a fin (inicio → jugar → game over → reiniciar).
  • Corre a velocidad constante (no más rápido en otra placa).
  • Guarda el récord aunque apagues la consola.
  • Funciona con batería, en la mano, sin la compu.
  • Entendés el game loop y por qué el delta time importa.

Variantes

  1. Más juegos en un menú (un "cartucho" de varios).
  2. Multijugador por cable o por radio entre dos consolas.
  3. Acelerómetro como control (inclinar para mover) — conecta con E05.
  4. Pantalla a color (TFT) + sprites más ricos (M36).
  5. Emular un juego clásico simple (Game Boy es otro nivel — proyecto avanzado).
