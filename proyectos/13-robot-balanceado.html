Proyecto 13 ⚡ Puente HW+SW ⏱ ~2-3 semanas ESP32 + IMU + PID

🛴 Robot Auto-balanceado

🎯 Objetivo: un robot de DOS ruedas que se mantiene parado solo, como un Segway en miniatura. Si lo empujás, se corrige. Es el PID de E08 hecho equilibrio físico — el proyecto de control por excelencia, porque sin control el robot simplemente se cae.
🔗 Conexión con el campus: es la aplicación canónica de E08 Control (PID, lazo cerrado, estabilidad), E05 (IMU + motores), E04 (loop a dt fijo con timer) y el cálculo de M03 (derivada e integral del error).

El problema: un péndulo invertido

El cerebro: el lazo de control PID

Qué vas a aprender

  • Leer un IMU (giroscopio + acelerómetro, ej MPU6050) por I2C (E03).
  • Fusión de sensores (filtro complementario o Kalman) para un ángulo estable.
  • Implementar y sintonizar un PID real (E08) — el corazón del proyecto.
  • Loop de control a dt fijo con timer (E04).
  • Control de motores con driver + PWM (E05, E01).
  • Entender estabilidad en carne propia: un PID mal sintonizado = robot en el piso.

Componentes

ESP32 · IMU MPU6050 · 2 motores DC con encoder (o steppers) · driver L298N/TB6612 · chasis de 2 ruedas · batería LiPo. La sintonización requiere el robot físico (la simulación no captura la dinámica real).

Código clave — el lazo de control

float kp = 25.0, ki = 0.5, kd = 1.2;   // ⚠️ estos valores se SINTONIZAN
float integral = 0, errorPrev = 0;
const float OBJETIVO = 0.0;            // queremos θ = 0° (vertical)

void loopControl(float dt) {           // llamado a dt fijo (timer, E04)
  float angulo = leerIMU();            // SENSAR — giroscopio (E05/E03)
  float error = OBJETIVO - angulo;

  // PID — derivada e integral = cálculo de M03
  float P = kp * error;
  integral += error * dt;
  integral = constrain(integral, -50, 50);   // anti-windup (E08)
  float I = ki * integral;
  float D = kd * (error - errorPrev) / dt;
  errorPrev = error;

  float salida = P + I + D;             // señal de control

  // ACTUAR — ambos motores aceleran hacia donde cae (E05)
  moverMotores(constrain(salida, -255, 255));
}
🔗 Mirá los conceptos de E08 en el código: integral += error*dt (integral numérica de M03), (error-errorPrev)/dt (derivada numérica), constrain(integral,...) (anti-windup). Y el dt fijo viene de un timer de E04 — si el loop no corre a intervalo constante, el PID calcula mal.

Fases

Fase 1: leé el IMU y mostrá el ángulo por serial. Aplicá filtro complementario para un valor estable (sin deriva ni ruido).
Fase 2: hacé andar los motores en ambos sentidos con PWM. Verificá el driver y la fuente.
Fase 3: implementá el PID. Empezá SOLO con P, sumá D, después I. Sintonizá una ganancia a la vez (regla de E08).
Fase 4: ajuste fino hasta que aguante empujones. Agregá control de posición/giro por Bluetooth (manejarlo como un Segway).
✅ Terminado cuando:
  • El robot se mantiene parado solo sobre 2 ruedas.
  • Si lo empujás suavemente, se corrige y vuelve a la vertical.
  • El PID está sintonizado (no oscila violentamente ni se cae).
  • El loop corre a dt fijo con timer.
  • Implementaste anti-windup en la integral.
  • Grabaste un video del robot balanceándose y resistiendo empujones.

Variantes (hacia robótica avanzada)

  1. Control remoto: manejarlo por Bluetooth/WiFi como un mini-Segway (M37 IoT).
  2. Telemetría: graficar el ángulo y la señal PID en vivo en un dashboard (Curso-React).
  3. Filtro de Kalman en vez del complementario (fusión de sensores avanzada, conecta con M04 Probabilidad).
  4. Auto-tuning: que el robot ajuste sus propias ganancias.
  5. RL en vez de PID: entrenar el balanceo con reinforcement learning (M39) — el "control aprendido" de E08.
🔗 El cierre del campus: la última variante —reemplazar el PID por reinforcement learning— es literalmente el espejo que E08 describe: control clásico (ingeniero ajusta ganancias) vs control aprendido (el agente las descubre). Hacer ambas versiones del MISMO robot es ver los dos mundos —ingeniería de control e IA— resolviendo el mismo problema. La complementariedad total.
