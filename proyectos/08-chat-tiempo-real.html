Proyecto 08 Avanzado ⏱ ~1-2 semanas WebSockets

💬 Chat en Tiempo Real

🎯 Objetivo: un chat con salas, mensajes que aparecen en vivo sin recargar, indicador de presencia ("Fulano está escribiendo…") e historial persistido. Es el proyecto que enseña real-time de verdad: el servidor te empuja los mensajes apenas pasan, en vez de que vos le preguntes todo el tiempo.
🔗 Conexión con el campus: React (estado en vivo, efectos), estado global, M15 Redes (TCP, protocolo WebSocket) y P23 API+SQL (persistir el historial).

Cómo funciona — por qué WebSockets y no HTTP

Qué vas a aprender

  • El protocolo WebSocket: handshake, canal persistente, bidireccional (M15).
  • Diferencia entre polling (preguntar) y push (que te empujen).
  • Broadcast a una sala: reenviar un mensaje a todos los conectados menos al que lo mandó.
  • Presencia y estado efímero: "está escribiendo…", quién está online.
  • Persistir historial en base de datos y cargarlo al entrar (P23).
  • Reconexión: qué pasa cuando se corta la red y vuelve (el problema real del real-time).

Stack

Backend: Node + Socket.IO (o ws), o Python con FastAPI WebSockets. Frontend: React. Persistencia: PostgreSQL/SQLite (P23). Empezá con un solo servidor; escalar a varios pide Redis pub/sub (P24).

Código clave (servidor que reenvía a la sala)

// Servidor (Socket.IO) — el corazón del real-time
io.on("connection", (socket) => {
  socket.on("entrar_sala", (sala) => {
    socket.join(sala);
    socket.to(sala).emit("presencia", "alguien entró");
  });

  socket.on("mensaje", async ({ sala, texto, autor }) => {
    await db.guardar(sala, autor, texto);          // persistir (P23)
    // reenviar a TODOS los de la sala, al instante (broadcast)
    io.to(sala).emit("mensaje", { autor, texto, hora: Date.now() });
  });

  socket.on("escribiendo", (sala) =>
    socket.to(sala).emit("escribiendo", socket.id) // estado efímero, no se guarda
  );
});
🔗 La clave es io.to(sala).emit(...): el servidor empuja el mensaje a todos los de la sala sin que nadie pregunte. Notá que el mensaje se persiste (P23) pero el "está escribiendo" NO — es estado efímero. Distinguir lo que se guarda de lo que es momentáneo es media batalla del diseño real-time.

Fases

Fase 1: conexión WebSocket básica: el cliente manda un texto, el servidor lo devuelve (eco). Verificá el canal abierto.
Fase 2: broadcast: un mensaje de un cliente llega a TODOS los conectados, en vivo.
Fase 3: salas: separar conversaciones. Solo recibís lo de tu sala.
Fase 4: persistencia (P23): guardar mensajes y cargar el historial al entrar a una sala.
Fase 5: presencia ("escribiendo…", online) + reconexión automática al cortarse la red.
✅ Terminado cuando:
  • Dos navegadores en la misma sala se ven los mensajes al instante.
  • Las salas están aisladas (no te llega lo de otra).
  • El historial persiste y se carga al entrar.
  • Funciona el "está escribiendo…" y se ve quién está online.
  • Si se corta la red, el cliente se reconecta solo y no pierde mensajes.

Variantes

  1. Autenticación: que cada usuario tenga su identidad (conecta con login/JWT).
  2. Escalado horizontal: varios servidores con Redis pub/sub (P24) para sincronizar salas.
  3. Mensajes con archivos/imágenes (subida + almacenamiento).
  4. Notificaciones push cuando no estás en la app.
  5. Cifrado extremo a extremo de los mensajes (conecta con M29 y P19).
