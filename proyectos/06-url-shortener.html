🔗 Acortador de URLs (Fullstack)

🎯 Objetivo: un servicio tipo bit.ly. El usuario pega una URL larga, recibe una corta (tusitio.com/aZ3k), y al visitarla redirige a la original. Con analytics de clicks. Es EL proyecto fullstack canónico: simple de explicar, rico en conceptos de backend.

▶ Probar la app REAL funcionando
Versión client-only del proyecto: acorta con base62 sobre ID incremental (el algoritmo real), resuelve códigos, cuenta clicks y muestra analytics. Sin backend — usa localStorage como "base de datos".

Cómo funciona — crear y redirigir

Por qué este proyecto enseña tanto

Parece trivial pero toca: diseño de API REST, base de datos, generación de IDs únicos, redirects HTTP, rate limiting, caching, y analytics. Es pequeño en alcance pero profundo en conceptos de sistemas.

Qué vas a aprender

  • Diseñar una API REST (endpoints, métodos, status codes).
  • Modelar y consultar una base de datos (SQL).
  • Generar códigos cortos únicos (base62, colisiones).
  • Redirects HTTP (301 vs 302) y por qué importa.
  • Rate limiting e idempotencia (anti-abuso).
  • Frontend que consume tu propia API.

Stack

Backend: Next.js API routes (o Express/FastAPI). DB: Postgres (Neon) + Drizzle/Prisma. Frontend: React. Deploy: Vercel.

Arquitectura

[Frontend React] ──POST /api/shorten──► [Backend] ──► [Postgres]
                                            │            id | code | url_larga | clicks
   visitar tusitio.com/aZ3k ──GET /aZ3k──► [Backend] ──► busca code, +1 click, redirige (302)

Fases

Fase 1 — Schema + endpoint de creación. Tabla links. Endpoint POST /api/shorten que recibe una URL, genera un code, lo guarda y lo devuelve.
// Generar code corto base62 (a-z A-Z 0-9)
function generarCode(len = 6) {
  const chars = 'abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789';
  return Array.from({ length: len }, () =>
    chars[Math.floor(Math.random() * chars.length)]
  ).join('');
}

// POST /api/shorten
export async function POST(req) {
  const { url } = await req.json();
  if (!esUrlValida(url)) return Response.json({ error: 'URL inválida' }, { status: 400 });

  let code;
  do { code = generarCode(); } while (await existeCode(code)); // evitar colisión
  await db.insert(links).values({ code, urlLarga: url, clicks: 0 });

  return Response.json({ code, short: `${BASE}/${code}` });
}
Fase 2 — Redirect. Endpoint GET /:code que busca el code, incrementa el contador de clicks y redirige a la URL original.
// GET /[code]
export async function GET(req, { params }) {
  const link = await db.query.links.findFirst({
    where: eq(links.code, params.code),
  });
  if (!link) return new Response('No encontrado', { status: 404 });

  await db.update(links).set({ clicks: link.clicks + 1 }).where(eq(links.code, params.code));

  return Response.redirect(link.urlLarga, 302);  // temporal: permite contar clicks
}
302 (temporal) vs 301 (permanente): con 301 el browser cachea el redirect y deja de pegar a tu server → NO contás clicks. Por eso para analytics usás 302.
Fase 3 — Rate limiting + validación. Limitar cuántas URLs puede crear una IP por minuto (anti-spam). Validar que la URL sea real y no apunte a tu propio dominio (loop).
Fase 4 — Frontend + analytics. Página para crear links, listar los tuyos, copiar al portapapeles, y ver clicks por link en un gráfico.
🔗 Conexión con el campus: este proyecto materializa M19 SQL (schema, queries), M15 Redes (HTTP, status codes, redirects), M31 Seguridad (rate limiting, validación, SSRF), M33 Fullstack y el Curso de React para el frontend.
✅ Terminado cuando:
  • Creás una URL corta desde el frontend.
  • Al visitarla, redirige a la original.
  • El contador de clicks sube en cada visita.
  • Hay rate limiting y validación de URL.
  • Ves analytics (clicks por link) en un gráfico.
  • Está deployado con DB real y URL pública.

Variantes

  1. Códigos personalizados (tusitio.com/mi-promo).
  2. Expiración: links que mueren tras N días o N clicks.
  3. QR code automático para cada link.
  4. Auth: cada usuario ve solo sus links (se conecta con M31 auth).
  5. Analytics avanzado: país, dispositivo, referer de cada click.
  6. Cache con Redis para los redirects más usados (M21 NoSQL).
