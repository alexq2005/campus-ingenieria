Proyecto 10 ⚡ Puente HW+SW ⏱ ~2 semanas ESP32 + sensores + motores

🤖 Robot Evita-Obstáculos

🎯 Objetivo: un robot que se mueve solo y esquiva obstáculos. Mide la distancia con un sensor ultrasónico, decide hacia dónde ir, y controla dos motores. Es el ciclo sensar → decidir → actuar — la esencia de la robótica y de todo sistema autónomo.
🔗 El loop sensar-decidir-actuar: es el mismo de la IA (percepción → modelo → acción de M39), del game loop (M35: input → update → render), y del control (E08). Acá lo ves físico: el robot literalmente percibe el mundo y reacciona.

Cómo funciona — el loop sensar → decidir → actuar

Qué vas a aprender

  • Leer un sensor ultrasónico (HC-SR04): medir distancia por tiempo de eco.
  • Controlar motores DC con un driver (L298N / L9110) — los pines del MCU NO pueden alimentar motores directo.
  • PWM para controlar la velocidad de los motores.
  • Lógica de decisión (la "inteligencia" del robot).
  • Manejo de energía: batería, consumo, por qué los motores necesitan fuente aparte.
  • Introducción al control: reaccionar proporcionalmente a la distancia.

Componentes

ESP32 · sensor ultrasónico HC-SR04 · 2 motores DC + ruedas · driver de motor L298N · chasis · porta-pilas (4×AA o batería LiPo) · protoboard · cables. Simulable en Wokwi (con limitaciones de motores).

🔗 Lección de E00 que SALVA tu chip: un pin del ESP32 da ~20mA; un motor DC pide cientos de mA. Conectar el motor directo al pin lo quema. Por eso va un driver (L298N) que usa una fuente aparte para los motores y solo recibe la señal de control del MCU. Esto es exactamente por qué E00 (potencia, corriente) importa antes de tocar actuadores.

El sensor ultrasónico (cómo mide distancia)

Emite un pulso de ultrasonido → rebota en el obstáculo → mide el tiempo del eco.
distancia = (tiempo_eco × velocidad_sonido) / 2
         = (tiempo_µs × 0.0343 cm/µs) / 2

// En código:
long medirDistancia() {
  digitalWrite(TRIG, HIGH); delayMicroseconds(10); digitalWrite(TRIG, LOW);
  long us = pulseIn(ECHO, HIGH);     // mide el tiempo del eco
  return us * 0.0343 / 2;            // cm
}
🔗 Esto es un ADC temporal: convertir un fenómeno físico (distancia) en un número usando tiempo, como el ADC de E03 convierte voltaje en número. Todo sensor hace lo mismo: traduce el mundo analógico a un número que tu código puede procesar.

La lógica de decisión

void loop() {
  long dist = medirDistancia();   // SENSAR

  if (dist > 30) {                // DECIDIR
    avanzar();                    // camino libre
  } else {
    detener();
    retroceder(300);              // alejarse un poco
    girarDerecha(400);            // buscar otra dirección
  }
}

// ACTUAR — controlar los motores vía el driver
void avanzar() {
  digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);   // motor izq adelante
  digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW);   // motor der adelante
  analogWrite(ENA, 200); analogWrite(ENB, 200);      // PWM velocidad
}

Fases

Fase 1: hacé andar los motores solos (adelante, atrás, girar). Verificá la fuente de poder separada.
Fase 2: leé el sensor ultrasónico e imprimí la distancia por serial.
Fase 3: uní ambos: el robot avanza y frena al detectar obstáculo cercano.
Fase 4: lógica de esquive (retroceder + girar) y ajuste de velocidad según distancia (control proporcional simple).
✅ Terminado cuando:
  • El robot avanza solo en línea recta.
  • Detecta obstáculos a <30cm y los esquiva sin chocar.
  • Los motores andan desde una fuente separada (no quemaste el ESP32).
  • El código tiene el ciclo claro sensar→decidir→actuar.
  • Grabaste un video del robot andando (va al portfolio).

Variantes (hacia robótica seria)

  1. Control PID: en vez de "frenar/girar", ajustá velocidad proporcionalmente a la distancia (suaviza el movimiento). Conecta con E08 Control.
  2. Seguidor de línea: sensores infrarrojos que siguen una línea negra en el piso.
  3. Control remoto: manejarlo desde el celular vía WiFi/Bluetooth (M37 IoT).
  4. Mapeo: que recuerde por dónde anduvo y arme un mapa simple.
  5. Visión: agregar una ESP32-CAM y que siga objetos por color (conecta con M42 Visión).
  6. ML en el edge: clasificar obstáculos con un modelo TinyML en el chip (M39+M40).
🔗 Este es el capstone de la complementariedad: empezás con electrónica pura (motores, sensor, energía), agregás lógica de software (decisión), y las variantes te llevan a control (E08), visión (M42), IoT (M37) y ML (M39).
