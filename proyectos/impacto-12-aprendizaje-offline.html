📚 Plataforma de Aprendizaje Offline

🌍 El problema: ~2.600 millones de personas siguen sin acceso a internet, y muchas más solo tienen conexión cara, lenta o intermitente. La educación digital asume una conexión que gran parte del mundo no tiene. A quién ayuda: estudiantes y docentes en zonas rurales, escuelas con poca conectividad y comunidades donde el dato móvil es un lujo — contenido que funciona sin internet y se actualiza cuando hay señal.
🎯 Objetivo: una PWA (Progressive Web App) que descarga lecciones, videos y ejercicios una vez y luego funciona 100% offline: se puede leer, resolver ejercicios y guardar el progreso sin conexión, sincronizando cuando vuelve la señal. De hecho, este mismo campus ya aplica el principio: funciona abriendo archivos sin servidor.
🔗 Conexión con el campus: React / Data fetching, estado global, M33 Fullstack (Service Workers, sync) y M21 (almacenamiento local).

Cómo funciona — offline-first

Qué vas a aprender

  • PWA y Service Workers: interceptar pedidos y servir desde caché (M33).
  • Almacenamiento local: IndexedDB / Cache API para contenido y progreso (M21).
  • Estrategia offline-first y resolución de conflictos al sincronizar.
  • Optimizar para dispositivos modestos y poca batería/datos.
  • Empaquetar contenido (videos comprimidos, imágenes livianas) para descargar una vez.
  • Accesibilidad e i18n: distintos idiomas y baja alfabetización digital.

Stack

React/PWA + Service Worker (Workbox) + IndexedDB · backend simple para contenido y sync · contenido educativo abierto (Khan Academy, Wikipedia ZIM/Kiwix como referencia). Probar en modo avión es parte del testeo.

Código clave (servir desde caché, sync diferida)

// Service Worker: si no hay red, servir desde caché (offline-first) (M33)
self.addEventListener("fetch", (e) => {
  e.respondWith(
    caches.match(e.request).then((cacheado) =>
      cacheado || fetch(e.request)   // caché primero; red solo si hace falta
        .catch(() => caches.match("/offline.html"))
    )
  );
});

// El progreso se guarda local y se encola para sincronizar cuando haya señal
async function guardarProgreso(leccion, estado) {
  await idb.put("progreso", { leccion, estado, synced: false });
  if (navigator.onLine) sincronizarPendientes();   // si hay red, subir
}
🔗 El Service Worker es un proxy que vive en el navegador (M33): intercepta cada pedido y decide servir de caché o de red. Es la misma idea de caché del P24 (Redis), pero del lado del cliente. Guardar el progreso con synced:false y subirlo después es una cola de sincronización — manejar conflictos es el problema interesante.

Fases

Fase 1: PWA básica que se instala y abre sin conexión (Service Worker + manifest).
Fase 2: precargar lecciones en caché. Probá en modo avión: debe funcionar completo.
Fase 3: guardar progreso/respuestas en IndexedDB sin conexión.
Fase 4: sincronización diferida cuando vuelve la red, resolviendo conflictos.
Fase 5: optimizar peso (videos/imágenes), multi-idioma y prueba en un dispositivo modesto.
✅ Terminado cuando:
  • La app funciona completa en modo avión tras la primera descarga.
  • El progreso se guarda offline y se sincroniza solo al recuperar señal.
  • Maneja conflictos de sincronización sin perder datos del estudiante.
  • Es liviana y usable en un teléfono modesto con poca batería/datos.
  • Soporta al menos dos idiomas y es accesible.

Variantes

  1. Compartir contenido por Bluetooth/WiFi local entre dispositivos (sin internet del todo).
  2. Servidor local en una Raspberry Pi para una escuela entera (intranet).
  3. Tutor con un LLM pequeño que corre en el dispositivo (TinyML/edge).
  4. Panel para el docente con el progreso de la clase (sincroniza cuando puede).
  5. Contenido generado/curado por la comunidad local en su idioma.
