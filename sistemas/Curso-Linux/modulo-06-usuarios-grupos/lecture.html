Módulo 06 — Usuarios y Grupos

Modelo

Linux es multiusuario. Cada usuario tiene:

  • Username y UID (User ID)
  • Uno o más grupos (cada uno con GID)
  • Un home y un shell asignados
  • Una contraseña hasheada

Convención de UIDs:

RangoUso
0root
1-999Usuarios de sistema (servicios, daemons)
1000+Usuarios humanos

Archivos clave

/etc/passwd

Una línea por usuario. Lectura pública (no contiene contraseñas reales):

ana:x:1000:1000:Ana Pérez,,,:/home/ana:/bin/bash
│   │ │    │    │           │         │
│   │ │    │    │           │         shell
│   │ │    │    │           home
│   │ │    │    GECOS (info)
│   │ │    GID primario
│   │ UID
│   x = ver /etc/shadow
username

/etc/shadow

Contraseñas hasheadas. Solo root puede leer:

ana:$6$abc...:19000:0:99999:7:::
│   │         │     │ │     │
│   hash      │     │ │     warn antes de expirar
│   (formato $algo$salt$hash)
│             │     │ vida máxima
│             │     min antes de poder cambiar
│             días desde 1970 del último cambio
username

Algoritmos de hash ($id$):

  • $1$ MD5 (inseguro)
  • $5$ SHA-256
  • $6$ SHA-512 (default moderno)
  • $y$ yescrypt (más nuevo)

/etc/group

devs:x:1001:ana,luis,eva
│    │ │    │
│    │ │    miembros (separados por coma)
│    │ GID
│    x (no usado típicamente)
nombre del grupo

/etc/gshadow

Contraseñas de grupos (raras de usar).

Crear y eliminar usuarios

sudo useradd ana                          # mínimo (no crea home)
sudo useradd -m ana                       # con home
sudo useradd -m -s /bin/bash ana          # especificar shell
sudo useradd -m -G devs,docker ana        # con grupos suplementarios
sudo passwd ana                           # asignar contraseña

sudo adduser ana                          # ⭐ wrapper interactivo (Debian/Ubuntu)

adduser es más amigable: pregunta nombre, contraseña, etc. y crea home con skeleton (/etc/skel).

Eliminar

sudo userdel ana                          # eliminar usuario
sudo userdel -r ana                       # también borrar home y mail
sudo deluser --remove-home ana            # Debian/Ubuntu

Modificar usuarios

sudo usermod -aG docker ana               # AGREGAR a grupo (cuidado con -a)
sudo usermod -G devs,docker ana           # ⚠️ REEMPLAZA grupos suplementarios
sudo usermod -L ana                       # bloquear contraseña
sudo usermod -U ana                       # desbloquear
sudo usermod -s /bin/zsh ana              # cambiar shell
sudo usermod -d /nuevo/home -m ana        # mover home
sudo usermod -e 2025-12-31 ana            # fecha de expiración
sudo chage -l ana                         # ver info de aging
Trampa típica: usermod -G grupo ana sin -a te BORRA todos los grupos suplementarios anteriores. Usá siempre -aG cuando agregás.

Cambiar contraseña

passwd                                     # tu propia (interactivo)
sudo passwd ana                            # de otro usuario
sudo passwd -l ana                         # bloquear
sudo passwd -u ana                         # desbloquear
sudo passwd -e ana                         # forzar cambio en próximo login

Grupos

sudo groupadd devs
sudo groupadd -g 1500 devs                # con GID específico
sudo groupdel devs
sudo groupmod -n nuevos viejos            # renombrar

groups                                     # tus grupos
groups ana                                 # los de ana
id                                         # tu UID, GID y grupos
id ana                                     # los de ana

Cambiar grupo de archivos

sudo chgrp devs archivo
newgrp devs                                # cambiar GID activo en la sesión

El comando su — Switch User

su                                         # convertirse en root (pide contraseña)
su -                                       # como root con su entorno completo
su ana                                     # convertirse en ana
su - ana                                   # ana con su entorno
exit                                       # volver

El comando sudo

Permite ejecutar comandos como otro usuario (usualmente root) sin compartir contraseña.

sudo comando
sudo -i                                    # shell interactivo de root
sudo -u ana comando                        # como ana
sudo -l                                    # qué puedo hacer con sudo
sudo !!                                    # repetir el último con sudo

Configuración — /etc/sudoers

Editar SIEMPRE con visudo (valida sintaxis antes de guardar):

sudo visudo

Sintaxis:

# usuario   host=(usuarios)   comandos
root        ALL=(ALL:ALL) ALL
%sudo       ALL=(ALL:ALL) ALL              # %grupo
ana         ALL=(ALL) NOPASSWD: /usr/bin/systemctl

Archivos modulares en /etc/sudoers.d/:

sudo visudo -f /etc/sudoers.d/ana-deploys
El archivo debe terminar sin extensión y permisos 0440.

Logs de sudo

Cada sudo se loguea en /var/log/auth.log (Debian) o /var/log/secure (RHEL).

Sesiones activas — who y w

who                                        # quiénes están logueados
w                                          # más detalle (carga, idle, comando)
last                                       # historial de logins
last -F | head                             # con fechas completas
lastb                                      # logins fallidos (root)
finger ana                                 # info detallada (instalable)
whoami                                     # tu username
logname                                    # username del login original

Skeleton de home — /etc/skel

Cuando se crea un usuario con useradd -m, se copia el contenido de /etc/skel/ a su home. Es el lugar para configurar defaults globales (.bashrc, .profile, etc.).

Cuotas de disco

# Habilitar en /etc/fstab: añadir usrquota,grpquota
sudo quotacheck -avug
sudo quotaon -av
sudo edquota -u ana                        # editar cuotas
quota -u ana                               # ver

Buenas prácticas

  1. Nunca compartir cuentas. Cada humano = un usuario
  2. Deshabilitar root login por SSH: PermitRootLogin no en /etc/ssh/sshd_config
  3. Usar sudo, no su -, para auditoría
  4. Política de contraseñas: instalar libpam-pwquality y configurar /etc/security/pwquality.conf
  5. Bloquear cuentas inactivas: chage -E para expiración

Errores típicos administrando usuarios

1. Borrar un usuario y dejarle los archivos. userdel ana sin -r deja su home y todo lo que tuviera repartido por el sistema con el UID huérfano. El próximo usuario que crees va a reusar ese UID… y hereda automáticamente todos esos archivos, incluidas sus claves SSH.
# ❌ mal — el home queda, y el UID 1001 queda libre para el que venga
sudo userdel ana

# ✅ bien — respaldá primero y después borrá también sus datos
sudo tar -czf /respaldos/ana-$(date +%F).tar.gz /home/ana
sudo userdel -r ana

# Buscá lo que haya quedado suelto por el resto del sistema:
sudo find / -xdev -nouser 2>/dev/null
2. Agregarte a un grupo y esperar que funcione en la misma terminal. Los grupos se leen al iniciar sesión: tu shell actual sigue con la lista vieja. El caso clásico es sumarse a docker y que docker ps siga tirando permission denied.
sudo usermod -aG docker ana
groups                        # ❌ docker todavía NO aparece

# ✅ cerrá sesión y volvé a entrar; o, para la terminal actual:
newgrp docker
id -nG                        # ahora sí
3. Regalar NOPASSWD: ALL "para no andar poniendo la contraseña". Eso es root permanente y sin fricción para esa cuenta: quien le robe la sesión, se queda con el equipo. Y ojo, tampoco alcanza con acotar el comando si ese comando puede abrir una shell: vi, find, less o awk con sudo son root disfrazado.
# ❌ mal — root sin contraseña, para siempre
# ana ALL=(ALL) NOPASSWD: ALL

# ❌ también mal — desde vi se abre una shell root con :!bash
# ana ALL=(root) NOPASSWD: /usr/bin/vi

# ✅ bien — un comando concreto, con ruta absoluta y argumentos fijos
# ana ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx
sudo visudo -f /etc/sudoers.d/ana-nginx
sudo -l                       # verificá qué quedó realmente habilitado
4. Editar /etc/passwd o /etc/shadow a mano con un editor común. Si otro proceso (un useradd, un passwd) escribe al mismo tiempo, se pisan y el archivo queda inconsistente: nadie puede loguearse. vipw y vipw -s toman el lock y validan al salir.
# ❌ mal
sudo nano /etc/passwd

# ✅ bien — con lock y validación
sudo vipw          # /etc/passwd
sudo vipw -s       # /etc/shadow
sudo vigr          # /etc/group

# Chequeo de consistencia después de tocar algo:
sudo pwck -r
sudo grpck -r

Checkpoint — ¿lo tenés claro?

¿Por qué sudo te pide TU contraseña y no la de root?

Porque sudo no te convierte en root pidiéndote el secreto de root: verifica que vos sos vos y después consulta en /etc/sudoers qué te dejaron hacer. Eso trae tres ventajas sobre su -: la contraseña de root no la conoce nadie (en muchas distros la cuenta viene directamente bloqueada), cada usuario puede tener permisos distintos, y todo queda auditado a tu nombre en /var/log/auth.log. Con un su - compartido, el log solo dice "alguien fue root" y no sabés quién.

¿Qué diferencia hay entre su ana y su - ana?

El guion pide una login shell. Sin él cambiás de usuario pero te quedás con el entorno anterior: seguís parado en el mismo directorio y con el PATH, el HOME y las variables del usuario de antes, así que un script puede escribir en el home equivocado o no encontrar un binario de /sbin. Con su - ana el entorno se arma de cero como en un login real: se leen los .profile/.bashrc de ana y quedás en su home. La misma diferencia hay entre sudo -s y sudo -i.

¿Por qué muchos usuarios de /etc/passwd tienen /usr/sbin/nologin como shell?

Porque son usuarios de sistema (UID por debajo de 1000): existen para que un servicio corra con identidad propia y permisos acotados — www-data para el servidor web, postgres para la base — no para que alguien se loguee con ellos. Poner nologin (o /bin/false) hace que cualquier intento de abrir una sesión con esa cuenta se rechace. Es contención de daño: si mañana alguien explota el servidor web, se encuentra parado en una cuenta sin shell, sin home útil y sin sudo, en vez de en root.

🧠 Autoevaluación rápida

Respondé sin mirar arriba. Cada pregunta te explica el porqué.

1. ¿En qué archivo están las contraseñas hasheadas de los usuarios?

/etc/passwd es de lectura pública y lleva una x en el campo de contraseña justamente porque el hash real vive en /etc/shadow. /etc/group guarda grupos y sus miembros.

2. ¿Cuál es la trampa de correr sudo usermod -G devs ana?

Sin -a, la lista de grupos suplementarios se reemplaza entera. Para agregar sin perder nada, usá siempre usermod -aG devs ana.

3. ¿Con qué hay que editar /etc/sudoers?

Un error de sintaxis en sudoers te puede dejar sin sudo en el sistema. visudo valida antes de escribir; para archivos modulares, sudo visudo -f /etc/sudoers.d/nombre.
