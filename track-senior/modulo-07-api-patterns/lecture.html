Tres decisiones de diseño de API. Respondé sin volver arriba — cada opción te explica el porqué.

1. Los assets con hash en el nombre van con max-age=31536000, immutable, pero el HTML va con no-cache. ¿Por qué la asimetría?

La regla es: si el contenido cambia, cambia la URL → cacheá para siempre; si la URL es estable, revalidá. El HTML es el índice mutable que referencia a main-abc123.js. Si lo cacheás, tus usuarios siguen pidiendo el bundle viejo aunque hayas deployado hace horas.

2. El módulo marca como contra de GraphQL que «el caché HTTP no funciona». ¿Por qué?

El caché de HTTP indexa por método más URL. Con POST /graphql todas las queries comparten dirección y ninguna es cacheable por la infraestructura. Se compensa moviendo el caché al cliente (Apollo, urql y Relay normalizan por entidad) o con persisted queries vía GET — pero es trabajo extra que en REST venía gratis.

3. ¿Qué problema resuelve un circuit breaker que el retry con backoff exponencial no?

El backoff espacia los reintentos de un cliente; con miles de clientes, el servicio caído igual recibe una tormenta que le impide levantarse. El breaker abre el circuito y falla rápido durante una ventana, y recién después prueba de nuevo (half-open). Es la diferencia entre un microservicio degradado y una caída en cascada.
