use-local-storage.jsx — Custom hook reusable

Un custom hook useLocalStorage(key, defaultValue) que se comporta como useState pero persiste a localStorage. Reusado en 3 componentes distintos.

¿Qué demuestra?

  • Custom hook: una función con prefijo use que usa otros hooks adentro.
  • Misma firma que useState: const [v, setV] = useLocalStorage(...).
  • Lazy init: lectura de localStorage SOLO al montar.
  • Sync con useEffect: cada cambio en valor → escribe a localStorage.
  • Error handling: try/catch en getItem y setItem (quota exceeded, JSON parse error).
  • 3 componentes reusan el mismo hook con tipos distintos (string, number, object).

Cómo ejecutarlo

npm run dev
# Reemplazá src/App.jsx
# Cambiá valores, recargá la página (F5), persisten

El hook (lo importante)

⬇ Descargar .jsx 🔗 Ver crudo 
import { useState, useEffect } from 'react';

// Devuelve [valor, setter] como useState, pero persiste en localStorage.
function useLocalStorage(key, defaultValue) {
  const [value, setValue] = useState(() => {
    // Lazy init: solo se ejecuta al montar
    try {
      const stored = localStorage.getItem(key);
      return stored !== null ? JSON.parse(stored) : defaultValue;
    } catch {
      return defaultValue;
    }
  });

  // Sync a localStorage cada vez que cambia value
  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch (err) {
      console.error('Error guardando en localStorage:', err);
    }
  }, [key, value]);

  return [value, setValue];
}

// ─── 3 usos del mismo hook ───

function ThemeToggle() {
  const [theme, setTheme] = useLocalStorage('theme', 'dark');
  return (
    <button onClick={() => setTheme(t => t === 'dark' ? 'light' : 'dark')}>
      {theme === 'dark' ? '🌙 Dark' : '☀️ Light'}
    </button>
  );
}

function Counter() {
  const [count, setCount] = useLocalStorage('counter', 0);
  return (
    <>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
    </>
  );
}

function UserProfile() {
  const [user, setUser] = useLocalStorage('user', { nombre: '', email: '' });
  return (
    <>
      <input
        value={user.nombre}
        onChange={(e) => setUser({ ...user, nombre: e.target.value })}
      />
      <input
        value={user.email}
        onChange={(e) => setUser({ ...user, email: e.target.value })}
      />
    </>
  );
}

Lecciones clave

  • Misma firma que useState: facilita reemplazar uno por otro sin cambiar el sitio que lo usa.
  • NO comparte estado entre componentes: cada useLocalStorage('x') es independiente. Comparten la LÓGICA, no los datos. Si dos componentes usan la MISMA key, hay sync vía localStorage pero no instantáneo (se actualizan al re-renderizar).
  • El nombre TIENE que empezar con use: sin esto, ESLint no aplica las reglas de hooks.
  • Lazy init: useState(() => readFromStorage()) evita leer localStorage en cada render.
  • Try/catch: localStorage puede tirar (quota exceeded, JSON malformado, modo privado de Safari).

Otros custom hooks útiles para implementar

  1. useDebounce(value, delay) — diferir un valor.
  2. useToggle(initial) — boolean + función toggle.
  3. useFetch(url) — { data, loading, error }.
  4. usePrevious(value) — recordar valor anterior.
  5. useWindowSize() — viewport reactivo.
  6. useCopyToClipboard() — { copy, copied } con flash visual.
  7. useHover(ref) — boolean true si el mouse está encima.
  8. useOnScreen(ref) — boolean si el elemento es visible (IntersectionObserver).
