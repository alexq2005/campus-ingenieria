Proyecto Puente — Estación Meteorológica IoT

El proyecto que no podés terminar sabiendo solo software o solo electrónica. Atraviesa medio campus: del sensor físico al dashboard web con predicción ML. Esta es la complementariedad hecha proyecto.
🌉 Por qué es "puente": cada fase usa un módulo distinto del campus, alternando entre electrónica e informática. Si te falta cualquiera de los dos mundos, te trabás. Eso es exactamente el punto — te obliga a integrar.

Qué construís

Una estación que mide temperatura, humedad y presión, los manda por WiFi a un servidor, los guarda, los muestra en un dashboard web en vivo, y predice la temperatura de la próxima hora con un modelo simple.

El flujo completo — y qué módulo usa cada parte

Fase por fase

Fase 1-2 — El hardware (Electrónica)

Conectá el sensor BME280 al ESP32 por I2C (4 cables: VCC, GND, SDA, SCL). Verificá con multímetro que el sensor recibe 3.3V. En el simulador Wokwi podés hacerlo sin hardware físico.
#include <Wire.h>
#include <Adafruit_BME280.h>

Adafruit_BME280 bme;

void setup() {
  Serial.begin(115200);
  Wire.begin();              // inicia I2C (E03)
  if (!bme.begin(0x76)) {
    Serial.println("Sensor no encontrado!");
  }
}

Fase 3-4 — Firmware + WiFi (Informática en el chip)

#include <WiFi.h>
#include <PubSubClient.h>   // MQTT

WiFiClient espClient;
PubSubClient mqtt(espClient);

void loop() {
  float temp = bme.readTemperature();   // ADC + I2C (E03)
  float hum  = bme.readHumidity();

  char payload[64];
  snprintf(payload, sizeof(payload),
           "{\"temp\":%.1f,\"hum\":%.1f}", temp, hum);

  mqtt.publish("estacion/datos", payload);   // M15/M37
  delay(60000);  // cada minuto (mejor: deep sleep — Fase 9)
}
🔗 El snprintf y el manejo de buffers fijos vienen directo de M07. El protocolo MQTT, de M37.

Fase 5-7 — Backend, DB, Dashboard (Informática)

Un backend (Next.js de M33 o Python/FastAPI) se suscribe al MQTT, guarda en Postgres con TIMESTAMPTZ (M19), y un dashboard React (Curso-React) con Recharts muestra los datos en vivo vía TanStack Query.

Fase 8 — Predicción ML (Informática)

Con el histórico, entrená una regresión simple (M39) que prediga la temperatura de la próxima hora. Empezá con regresión lineal sobre las últimas N lecturas.

Fase 9 — Optimización de energía (Electrónica)

Acá volvés al hardware: usar deep sleep del ESP32 entre lecturas baja el consumo de ~80mA a ~10µA. La diferencia entre "dura 1 día" y "dura 6 meses con la misma batería". Calculás la autonomía con la Ley de Ohm y la capacidad de la batería (E00).
🔗 El bucle se cierra: empezaste en electrónica (sensor), pasaste todo por software, y volvés a electrónica (energía). Esa ida y vuelta es la complementariedad en acción — optimizar el sistema completo requiere pensar en watts Y en algoritmos a la vez.

Criterios de "terminado"

  • ☐ El sensor lee datos reales (o simulados en Wokwi).
  • ☐ Los datos llegan al backend por WiFi/MQTT.
  • ☐ Se guardan en una base de datos.
  • ☐ El dashboard los muestra en vivo (se actualiza solo).
  • ☐ Hay al menos una predicción simple funcionando.
  • ☐ Documentaste el consumo de energía y una optimización.
  • ☐ README con diagrama, fotos/screenshots y el flujo completo.
