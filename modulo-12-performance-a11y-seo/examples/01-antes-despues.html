Optimización de una página real

Para cada técnica: código malo vs bueno, y por qué.

1. Imágenes

MaloBueno
<img src="hero.jpg"> <img src="hero.avif" alt="..." width="1600" height="900" loading="lazy">

✓ Formato moderno (AVIF/WebP), lazy load, dimensiones explícitas (sin CLS), alt text.

2. Fuentes

/* MAL: FOIT, bloquea el render */
@font-face { font-family: 'X'; src: url(X.woff2); }

/* BIEN: muestra fallback mientras carga */
@font-face {
  font-family: 'X';
  src: url(X.woff2) format('woff2');
  font-display: swap;
}

Y en el HTML:

<link rel="preload" href="/fonts/X.woff2" as="font" type="font/woff2" crossorigin>

3. Scripts

PatrónComportamiento
<script src="...">Bloquea el parser del HTML
<script defer src="...">Descarga paralelo, ejecuta después del HTML
<script async src="...">Descarga paralelo, ejecuta en cuanto termina (sin orden garantizado)
<script type="module">Equivale a defer, scope propio

4. Animaciones

/* MAL: dispara re-layout en cada frame */
.caja:hover { width: 300px; }

/* BIEN: solo composite (GPU) */
.caja:hover { transform: scale(1.2); }

5. Estabilidad visual (CLS)

✗ Un botón aparece tarde y todo el texto baja → "salto" que frustra al usuario.

✓ Reservá espacio con min-height, aspect-ratio, y width/height en imágenes.

/* Reservar espacio para un banner que carga async */
.banner { min-height: 120px; }

/* Aspect ratio moderno — reserva espacio en video/iframe */
.video { aspect-ratio: 16 / 9; }

7. Medir antes de optimizar

  1. Abrí DevTools → pestaña Lighthouse.
  2. Corré un audit en modo "Mobile" (más exigente).
  3. Mirá Performance score + Web Vitals.
  4. Cada recomendación tiene un link a la doc.
