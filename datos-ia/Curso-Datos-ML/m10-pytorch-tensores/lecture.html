Módulo 10 — PyTorch: Tensores & Autograd

Hasta acá usaste scikit-learn, que te entrena modelos clásicos con un .fit(). Para deep learning (redes neuronales) necesitás algo de más bajo nivel y más potente: PyTorch. Y todo PyTorch empieza por una sola estructura, el Tensor. Si entendés el Tensor, entendés PyTorch.

¿Qué es un Tensor?

💡 Un Tensor es un array de NumPy con dos superpoderes: (1) puede correr en la GPU (cientos de veces más rápido para matrices grandes), y (2) calcula gradientes automáticamente — el famoso autograd. Todo lo demás (forma, operaciones, indexado) es prácticamente igual a NumPy.

"Tensor" es solo el nombre matemático de un array de N dimensiones: un número es un tensor de 0 dimensiones (un escalar), un vector es de 1, una matriz de 2, una imagen RGB de 3, un lote de imágenes de 4. PyTorch los maneja todos con la misma clase: torch.Tensor.

Crear tensores

import torch

# desde una lista de Python
t = torch.tensor([[1, 2, 3],
                  [4, 5, 6]])

# llenos de 0 o de 1, dándole la forma
ceros = torch.zeros(2, 3)        # matriz 2x3 de ceros
unos  = torch.ones(3)            # vector de 3 unos

# números aleatorios (distribución normal)
r = torch.randn(2, 2)            # 2x2 con media 0, std 1

print(t.shape)   # torch.Size([2, 3])  -> filas, columnas
print(t.dtype)   # torch.int64         -> tipo de dato
.shape te dice las dimensiones (igual que en NumPy) y .dtype el tipo de dato. Ojo: si pasás enteros, el dtype es int64; si querés decimales y gradientes, usá floats: torch.tensor([1.0, 2.0]) o torch.randn(...).

Operaciones — igual que NumPy

Las operaciones se escriben exactamente como en NumPy: +, * son elemento a elemento, y @ es el producto matricial.

a = torch.tensor([1.0, 2.0, 3.0])
b = torch.tensor([10.0, 20.0, 30.0])

a + b          # tensor([11., 22., 33.])   suma elemento a elemento
a * b          # tensor([10., 40., 90.])   producto elemento a elemento
a * 2          # tensor([2., 4., 6.])      broadcasting con un escalar

M = torch.randn(2, 3)
N = torch.randn(3, 4)
M @ N          # producto matricial -> forma (2, 4)

El puente con NumPy

Vas a tener datos en NumPy (vienen de pandas) y necesitás convertirlos a tensores, y al revés para graficar o reportar. El puente es directo:

import numpy as np

arr = np.array([1.0, 2.0, 3.0])

# NumPy  ->  Tensor
t = torch.from_numpy(arr)

# Tensor  ->  NumPy
arr2 = t.numpy()
🔍 Si sabés NumPy (M01), ya sabés operar tensores. El 90% de lo que aprendiste sobre arrays —forma, indexado, slicing, broadcasting, sum/mean— se traslada tal cual. PyTorch solo le agrega GPU y gradientes encima.
from_numpy y .numpy() comparten memoria (no copian): si modificás uno, cambia el otro. Es eficiente, pero si querés una copia independiente usá torch.tensor(arr) o t.clone().

Correr en la GPU

Una GPU hace miles de multiplicaciones en paralelo, ideal para las matrices de una red neuronal. Mover un tensor a la GPU es .to('cuda'). Pero no todas las máquinas tienen GPU, así que se detecta el dispositivo de forma portable:

# elige GPU si hay, sino CPU — funciona en cualquier máquina
device = 'cuda' if torch.cuda.is_available() else 'cpu'

t = torch.randn(1000, 1000)
t = t.to(device)        # mueve el tensor al device elegido
print(t.device)         # cuda:0   ó   cpu
📌 Regla de oro del device: todos los tensores que participan de una misma operación deben estar en el mismo dispositivo. No podés sumar un tensor de CPU con uno de GPU. En M11 vas a mover los datos y el modelo al mismo device antes de entrenar.

Autograd — el corazón de PyTorch

Acá está la magia. Para entrenar una red hay que calcular, en cada paso, cuánto influye cada parámetro en el error (el gradiente). PyTorch lo hace solo: si marcás un tensor con requires_grad=True, registra cada operación que hacés con él, y cuando llamás a .backward() calcula todos los gradientes de una.

El flujo de autograd es siempre el mismo:
  1. Marcás los tensores que querés derivar con requires_grad=True.
  2. Hacés operaciones con ellos (forward pass). PyTorch arma un grafo por detrás.
  3. Llamás loss.backward() sobre el resultado escalar final.
  4. Leés los gradientes en .grad de cada tensor.

Ejemplo: verificá el gradiente vos mismo

Tomemos la función y = x² + 3x en x = 2. La derivada a mano es dy/dx = 2x + 3, que en x = 2 da 2·2 + 3 = 7. Veamos que PyTorch llega al mismo número solo:

import torch

# 1. tensor que queremos derivar
x = torch.tensor(2.0, requires_grad=True)

# 2. forward pass: una operación simple
y = x**2 + 3*x          # y = 2² + 3·2 = 10

# 3. backward: calcula dy/dx automáticamente
y.backward()

# 4. leemos el gradiente
print(x.grad)           # tensor(7.)   <- coincide con 2x+3 = 7 ✓
💡 Lo que escribiste a mano, PyTorch lo derivó solo. No le dijiste cuál era la derivada de x² ni de 3x: registró las operaciones y aplicó la regla de la cadena por vos. Con miles de parámetros (una red real) es exactamente la misma llamada: loss.backward().

Esto reemplaza el backprop a mano del proyecto P30

En el proyecto P30 — Red Neuronal desde cero derivás el gradiente vos: escribís a mano la regla de la cadena, capa por capa, para ajustar los pesos. Es el ejercicio perfecto para entender qué pasa por dentro. PyTorch hace exactamente eso, pero automático: cada derivada que ahí calculás a mano, autograd la deduce sola con .backward(). Hacer P30 primero y luego ver esto es el orden ideal: primero entendés el motor, después usás la herramienta.
📌 Por qué importa: una red real tiene millones de parámetros. Derivar la regla de la cadena a mano para todos sería imposible. Autograd te deja definir cualquier arquitectura y obtener todos los gradientes con una sola línea. Eso es lo que hace viable el deep learning moderno.

Errores típicos

Olvidar requires_grad=True. Si el tensor no está marcado, PyTorch no registra sus operaciones y .grad queda en None. Después .backward() no tiene nada que calcular.
Mezclar tensores con ndarray sin convertir. No podés hacer tensor + np.array(...) directo en cualquier caso; convertí primero con torch.from_numpy(arr) (o el array a tensor) para que ambos sean del mismo tipo.
Olvidar mover datos y modelo al mismo device. Si el modelo está en cuda y los datos en cpu (o viceversa), PyTorch tira RuntimeError: Expected all tensors to be on the same device. Mové ambos con .to(device).
Llamar .backward() sobre un tensor que no es escalar sin pasarle un gradiente. backward() espera un único número (típicamente el loss). Si tu resultado es un vector, primero reducilo con .sum() o .mean().

Checkpoint — ¿lo tenés claro?

¿Qué dos superpoderes tiene un Tensor sobre un array de NumPy?

(1) Puede correr en GPU para acelerar operaciones con matrices grandes, y (2) calcula gradientes automáticamente (autograd) cuando lo marcás con requires_grad=True. Por lo demás, opera casi idéntico a NumPy.

¿Qué hace exactamente loss.backward()?

Recorre hacia atrás el grafo de operaciones que PyTorch fue registrando en el forward pass y, aplicando la regla de la cadena, calcula el gradiente de loss respecto a cada tensor marcado con requires_grad=True. Esos gradientes quedan disponibles en el atributo .grad de cada tensor.

¿Por qué autograd reemplaza el backpropagation a mano del proyecto P30?

En P30 derivás la regla de la cadena vos mismo, capa por capa, para conseguir los gradientes. Autograd hace eso automáticamente: registra las operaciones y deduce todas las derivadas solo. Con millones de parámetros, hacerlo a mano sería inviable; autograd lo resuelve con una sola línea.

  3. Partí de un np.array([1.0, 2.0, 3.0]), convertilo a tensor con torch.from_numpy, sumale 10, y volvé a NumPy con .numpy().
  4. Definí device con la línea portable ('cuda' if torch.cuda.is_available() else 'cpu'), mové un tensor con .to(device) e imprimí .device.
  5. Repetí el ejemplo de autograd con y = x**3 en x = 2. Calculá la derivada a mano (3x² = 12) y verificá que x.grad coincide tras y.backward().

🧠 Autoevaluación

1. ¿Qué dos cosas hace un Tensor que un array de NumPy no hace por sí solo?

Esos son los dos superpoderes del Tensor: aceleración por GPU y autograd. El resto de las operaciones son prácticamente idénticas a NumPy.

2. Definiste x = torch.tensor(2.0, requires_grad=True) y y = x**2 + 3*x. Tras y.backward(), ¿qué vale x.grad?

La derivada de x²+3x es 2x+3. En x=2: 2·2+3 = 7. Autograd llega a ese 7 solo, sin que le digas la fórmula de la derivada.

3. Tu modelo está en la GPU (cuda) pero tus datos quedaron en CPU. ¿Qué pasa al operarlos juntos?

PyTorch exige que todos los tensores de una operación estén en el mismo dispositivo. Hay que mover datos y modelo al mismo device con .to(device).
