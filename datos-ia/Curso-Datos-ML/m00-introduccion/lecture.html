Módulo 00 — Introducción & Setup

Bienvenido a la ciencia de datos. En este curso vas a recorrer el camino completo: de un archivo .csv crudo a un modelo que predice. Empezamos entendiendo el flujo y dejando el entorno listo para trabajar.

¿Qué es la ciencia de datos (y el ML)?

💡 Programación clásica: vos escribís las reglas, la computadora las aplica. Machine Learning: le das ejemplos (datos) y la computadora descubre las reglas sola. En vez de programar "si el email tiene la palabra X es spam", le mostrás miles de emails etiquetados y el modelo aprende el patrón.

La ciencia de datos es la disciplina que rodea a ese modelo: conseguir los datos, limpiarlos, entenderlos, visualizarlos, modelar y evaluar si el modelo sirve.

Tu primer análisis — en 5 líneas

Así se ve "mirar" un dataset con pandas. No te preocupes por entender cada método ahora — lo vemos en M02:

import pandas as pd

df = pd.read_csv("datos.csv")   # cargar un CSV en un DataFrame
df.head()                        # ver las primeras 5 filas
df.shape                         # (filas, columnas)
df.describe()                    # estadísticas: media, min, max, std...
df["edad"].mean()               # promedio de una columna
🔍 Un DataFrame es una planilla de Excel en código: filas, columnas con nombre, y métodos para filtrar, agrupar y calcular — pero programable, reproducible y capaz de manejar millones de filas.

La regla de oro: train / test

Nunca evalúes un modelo con los mismos datos con los que lo entrenaste. Separás los datos en train (para que aprenda) y test (para ver si generaliza a datos nuevos). Mirar el test set antes de tiempo es "hacer trampa" — el modelo parecería bueno y fallaría en producción. Lo formalizamos en M06.

Errores típicos al arrancar

Instalar las librerías global en vez de en un venv del proyecto. Termina en conflictos de versiones entre proyectos.
Saltarse la limpieza y el EDA y correr directo a modelar. Garbage in, garbage out: un modelo sobre datos sucios da resultados sucios.
Evaluar con los datos de entrenamiento (o espiar el test set). Da una falsa sensación de que el modelo es bueno.

Checkpoint — ¿lo tenés claro?

¿Cuál es la diferencia entre programación clásica y machine learning?

En la clásica vos escribís las reglas. En ML le das ejemplos (datos) y el modelo descubre las reglas solo. Programás el "aprendizaje", no las reglas finales.

¿Por qué NumPy es el pre-requisito de todo?

Porque pandas, scikit-learn y PyTorch están construidos sobre arrays de NumPy. Entender vectorización y arrays (M14 de Python) es la base.

¿Para qué sirve un notebook?

Para ejecutar código en celdas, ver resultados al instante y mezclar texto, código y gráficos. Ideal para explorar datos de forma iterativa.

🧠 Autoevaluación

1. ¿Cuál es el orden correcto del pipeline de datos?

Primero conseguís y limpiás los datos, los explorás, recién después modelás y evaluás. Modelar sobre datos sucios no sirve.

2. ¿Qué librería se usa para datos tabulares (filas y columnas, como Excel)?

pandas y su DataFrame son la estructura central de los datos tabulares. matplotlib es para gráficos; PyTorch para deep learning.

3. ¿Por qué se separan los datos en train y test?

El test mide si el modelo generaliza a datos nuevos. Evaluar con los datos de entrenamiento da una falsa sensación de éxito.
