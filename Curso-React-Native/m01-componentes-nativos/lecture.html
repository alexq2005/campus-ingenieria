Módulo 01 — Componentes Nativos

En la web tenías <div>, <p>, <img>, <button>… un montón de tags listos para usar. En React Native pasa lo mismo, pero con otro juego de piezas. Estos componentes core son los ladrillos con los que vas a construir absolutamente todas tus pantallas. En este módulo los conocés uno por uno, con su razón de ser y sus trampas.

💡 Los "componentes core" son los componentes que React Native trae de fábrica. Los importás desde 'react-native' y cada uno se traduce a un elemento nativo de verdad en el celular. No son HTML: un <View> es un UIView en iOS y un android.view.View en Android. Con apenas seis de ellos ya armás el 90% de cualquier app.

<View> — el contenedor

El <View> es el equivalente directo del <div>: una caja que no muestra nada por sí misma. Su trabajo es contener y organizar otros componentes. Y lo organiza todo con flexbox (lo mismo que ya conocés de CSS, con una diferencia clave).

import { View } from 'react-native';

export default function App() {
  return (
    <View style={{ flex: 1, padding: 20 }}>
      <View style={{ backgroundColor: '#a78bfa', height: 80 }} />
      <View style={{ backgroundColor: '#34d399', height: 80 }} />
    </View>
  );
}
En RN, flexbox es el default y la dirección es column, no row. En la web los hijos de un flex se acomodan en fila; acá se apilan de arriba hacia abajo. Tiene sentido: las pantallas de celular son altas y angostas. Si querés que vayan en fila, ponés flexDirection: 'row' explícito.
📌 flex: 1 es tu mejor amigo. Significa "ocupá todo el espacio disponible". El <View> raíz casi siempre lleva flex: 1 para llenar la pantalla completa.

<Text> — todo el texto vive acá

En la web cualquier elemento puede tener texto adentro. En RN NO: todo string visible tiene que estar dentro de un <Text>. Es la regla que más cuesta a quien viene de HTML.

import { Text, View } from 'react-native';

export default function App() {
  return (
    <View>
      <Text style={{ fontSize: 24, fontWeight: 'bold' }}>Título</Text>
      <Text>
        Un párrafo normal. Y el <Text style={{ fontWeight: 'bold' }}>Text se anida</Text> para
        dar formato a un pedazo del texto, igual que un <span> en la web.
      </Text>
    </View>
  );
}

El <Text> tiene dos props muy útiles que conviene memorizar desde ya:

PropPara qué sirve
numberOfLines={2}Corta el texto a N líneas y agrega … al final (ideal para títulos largos).
onPress={fn}Sí, un <Text> puede recibir toques. Útil para enlaces tipo "Leer más".
 
<Text numberOfLines={1}>Este título larguísimo se corta con puntos suspensivos</Text>
<Text style={{ color: '#a78bfa' }} onPress={() => alert('¡tocado!')}>Leer más</Text>
📌 Anidación heredada: el estilo de un <Text> padre se hereda a los <Text> hijos (color, tamaño de fuente). Esto NO pasa entre <View>s — el estilo de un View nunca se hereda.

<Image> — imágenes locales y remotas

El <Image> muestra imágenes, y tiene una particularidad que confunde al principio: casi siempre necesita que le digas su tamaño. Hay dos formas de darle una imagen:

import { Image } from 'react-native';

// 1) LOCAL — un archivo que está en tu proyecto. Se usa require():
<Image source={require('./assets/logo.png')} style={{ width: 100, height: 100 }} />

// 2) REMOTA — una URL de internet. Se pasa un objeto { uri }:
<Image
  source={{ uri: 'https://reactnative.dev/img/tiny_logo.png' }}
  style={{ width: 100, height: 100 }}
/>
⚠️ Las imágenes remotas obligan a poner width y height. RN no conoce las dimensiones de una imagen de internet hasta que termina de bajarla, así que si no le das un tamaño, no reserva espacio y no se ve nada. Las locales con require sí conocen su tamaño, pero igual conviene fijarlo para controlar el layout.

Para controlar cómo se acomoda la imagen dentro de la caja que le diste, usás resizeMode:

resizeModeQué hace
'cover' (default)Llena toda la caja, recortando lo que sobre. Sin deformar.
'contain'Muestra la imagen entera dentro de la caja, dejando espacio si hace falta.
'stretch'Estira la imagen para llenar la caja (puede deformarla — usar con cuidado).
 
<Image
  source={{ uri: 'https://reactnative.dev/img/tiny_logo.png' }}
  style={{ width: 120, height: 80 }}
  resizeMode="contain"
/>

<ScrollView> — contenido que se scrollea

Un <View> no scrollea: si su contenido es más alto que la pantalla, lo que sobra simplemente no se ve (no hay barra de scroll como en el navegador). Para contenido scrolleable usás <ScrollView>.

import { ScrollView, Text, View } from 'react-native';

export default function App() {
  return (
    <ScrollView style={{ flex: 1 }} contentContainerStyle={{ padding: 16 }}>
      <Text style={{ fontSize: 20 }}>Sección 1</Text>
      <View style={{ height: 300, backgroundColor: '#a78bfa' }} />
      <Text style={{ fontSize: 20 }}>Sección 2</Text>
      <View style={{ height: 300, backgroundColor: '#34d399' }} />
      <Text style={{ fontSize: 20 }}>Sección 3 (acá ya hiciste scroll)</Text>
    </ScrollView>
  );
}
style vs contentContainerStyle: el style es la caja del scroll (cuánto espacio ocupa en pantalla); el contentContainerStyle es el estilo del contenido de adentro (donde ponés el padding y el gap). Es la confusión #1 con ScrollView.
🚫 El <ScrollView> renderiza TODOS sus hijos de una sola vez, estén o no a la vista. Para 5–20 ítems está perfecto. Pero para una lista de miles (un feed, un chat, un catálogo), monta miles de componentes en memoria y la app se traba. Para eso existe <FlatList>, que solo renderiza lo que entra en pantalla. Lo vemos en el M03 — por ahora, recordá: ScrollView para poco, FlatList para mucho.

<SafeAreaView> — respetar el notch y las barras

Los celulares modernos tienen notch (la muesca de la cámara), esquinas redondeadas y barras del sistema arriba y abajo. Si dibujás tu contenido a pantalla completa sin cuidado, el título puede quedar tapado por el notch o el botón pegado al borde inferior. El <SafeAreaView> agrega automáticamente el relleno necesario para mantener tu contenido en la "zona segura".

import { SafeAreaView, Text } from 'react-native';

export default function App() {
  return (
    <SafeAreaView style={{ flex: 1 }}>
      <Text>Este texto nunca queda tapado por el notch.</Text>
    </SafeAreaView>
  );
}
✅ Patrón habitual: el <SafeAreaView> suele ser el contenedor más externo de la pantalla (con flex: 1), y adentro va el resto: tu <ScrollView>, tus <View>, etc. En proyectos reales se usa la versión del paquete react-native-safe-area-context, que funciona mejor en Android; el de 'react-native' alcanza para aprender.

<Pressable> — los toques

En móvil no hay "click": hay toques. El <Pressable> es el componente moderno para detectar toques en cualquier cosa. Reemplaza al <button> + onClick de la web por onPress.

import { Pressable, Text } from 'react-native';

<Pressable onPress={() => console.log('me tocaron')}>
  <Text>Tocame</Text>
</Pressable>

Lo poderoso del <Pressable> es que sabe cuándo lo estás presionando. En vez de pasarle un objeto de estilo fijo, le podés pasar una función que recibe { pressed } y devuelve el estilo según el estado:

<Pressable
  onPress={() => alert('¡Hola!')}
  style={({ pressed }) => ({
    backgroundColor: pressed ? '#7c3aed' : '#a78bfa',
    padding: 14,
    borderRadius: 10,
    opacity: pressed ? 0.85 : 1,
  })}
>
  <Text style={{ color: 'white', fontWeight: 'bold', textAlign: 'center' }}>
    Tocá para confirmar
  </Text>
</Pressable>
📌 El <Pressable> no muestra texto solo: es una caja invisible que detecta toques. El contenido visible (un <Text>, un <Image>) va adentro, como hijo. Igual que envolverías algo con un <button> en HTML.

Errores típicos con los componentes core

Texto suelto fuera de un <Text>. Escribir <View>Hola</View> tira el error "Text strings must be rendered within a <Text> component". Siempre: <View><Text>Hola</Text></View>.
Usar <ScrollView> para una lista de miles de ítems. Monta todo en memoria y la app se pone lenta o se cuelga. Para listas largas va <FlatList> (M03), que recicla las filas a medida que scrolleás.
Olvidar el tamaño de una <Image> remota. Sin width/height la imagen ocupa 0×0 y parece que "no carga". No es la URL: es que no le diste espacio.
Esperar que el estilo de un <View> se herede. Solo el texto hereda (de <Text> padre a <Text> hijo). Un color puesto en un <View> no afecta a sus hijos.

Ejemplo integrador — tarjeta de perfil

Juntemos casi todo en una pieza realista: una tarjeta de perfil que combina <SafeAreaView> + <View> + <Image> + <Text> + <Pressable>, con sus estilos en un StyleSheet.

import { SafeAreaView, View, Image, Text, Pressable, StyleSheet } from 'react-native';

export default function App() {
  return (
    <SafeAreaView style={styles.pantalla}>
      <View style={styles.tarjeta}>
        <Image
          source={{ uri: 'https://reactnative.dev/img/tiny_logo.png' }}
          style={styles.avatar}
          resizeMode="cover"
        />
        <Text style={styles.nombre}>Alex Quiñones</Text>
        <Text style={styles.bio} numberOfLines={2}>
          Desarrollador frontend aprendiendo React Native. Le gusta el mate y el código limpio.
        </Text>

        <Pressable
          onPress={() => alert('¡Ahora me seguís!')}
          style={({ pressed }) => [styles.boton, pressed && styles.botonPress]}
        >
          <Text style={styles.botonTexto}>Seguir</Text>
        </Pressable>
      </View>
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  pantalla: { flex: 1, justifyContent: 'center', alignItems: 'center', padding: 20 },
  tarjeta: {
    backgroundColor: 'white',
    borderRadius: 16,
    padding: 24,
    alignItems: 'center',
    width: '100%',
    maxWidth: 320,
    gap: 10,
    // sombra (iOS) + elevación (Android)
    shadowColor: '#000',
    shadowOpacity: 0.1,
    shadowRadius: 8,
    elevation: 4,
  },
  avatar: { width: 96, height: 96, borderRadius: 48, backgroundColor: '#eee' },
  nombre: { fontSize: 20, fontWeight: 'bold' },
  bio: { fontSize: 14, color: '#666', textAlign: 'center' },
  boton: { backgroundColor: '#a78bfa', paddingVertical: 10, paddingHorizontal: 28, borderRadius: 999, marginTop: 6 },
  botonPress: { backgroundColor: '#7c3aed' },
  botonTexto: { color: 'white', fontWeight: 'bold' },
});
✅ Fijate en dos detalles pro: el style del Pressable usa un array [base, pressed && extra] — RN combina varios objetos de estilo y descarta los false. Y un borderRadius igual a la mitad del lado convierte el avatar cuadrado en un círculo perfecto.

Checkpoint — ¿lo tenés claro?

¿Por qué <View>Hola</View> rompe la app?

Porque en React Native todo texto visible tiene que estar dentro de un <Text>. Un <View> es solo un contenedor (como un <div> vacío); no sabe dibujar texto. Lo correcto es <View><Text>Hola</Text></View>.

Una imagen remota no aparece. ¿Cuál es la causa más probable?

Que le falte width y height en el style. RN no conoce las dimensiones de una imagen de internet hasta bajarla, así que sin un tamaño explícito no reserva espacio y la imagen ocupa 0×0. No suele ser la URL.

¿Cuándo usar <ScrollView> y cuándo <FlatList>?

<ScrollView> para contenido acotado (5–20 ítems, una pantalla de detalle), porque renderiza todo de una. <FlatList> para listas largas (feeds, chats, catálogos), porque solo renderiza lo que entra en pantalla y recicla las filas. Lo vemos en el M03.

Ejercicios

  1. Armá una pantalla con un <SafeAreaView> que contenga un <Text> de título y verificá que el título no queda tapado por el notch.
  2. Poné dos <View> de colores uno al lado del otro (no apilados) usando flexDirection: 'row'.
  3. Mostrá una imagen remota con { uri } dándole width y height; después probá resizeMode="contain" y "cover" y observá la diferencia.
  4. Envolvé una larga columna de <Text> (10+ párrafos) en un <ScrollView> y confirmá que podés scrollear.
  5. Recreá la tarjeta de perfil del ejemplo cambiando el avatar, el nombre y haciendo que el botón cambie de color al presionarlo con { pressed }.

El <View> es el contenedor de RN: no muestra nada por sí mismo y organiza a sus hijos con flexbox.

Las imágenes remotas no traen dimensiones hasta bajarse; sin un tamaño explícito ocupan 0×0 y parece que no cargan.
