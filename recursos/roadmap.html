🎯 Niveles de dominio

Junior

0–1 año
0 de 6 completos
  • HTML/CSS/JS nativo fluido
  • React + hooks
  • TypeScript básico
  • Git + GitHub
  • 2–3 proyectos en portfolio
  • Lighthouse ≥ 85 en tu proyecto

Semi-Senior

1–3 años
0 de 8 completos
  • TypeScript avanzado (generics, utility types, mapped types)
  • Next.js / Remix / SSR
  • Testing robusto (unit + integration + E2E)
  • Performance profundo (profiler, flame graphs, budget)
  • Accesibilidad avanzada (ARIA, lectores de pantalla)
  • Diseño (saber hablar con diseñadores, Figma)
  • Contribuir a open source
  • Tech blog propio

Senior

3+ años
0 de 6 completos
  • Arquitectura de aplicaciones grandes
  • Design systems
  • Mentoría
  • Decisiones de stack con trade-offs claros
  • Performance budgets + monitoreo en producción
  • Security frontend (CSP, SRI, XSS, CSRF) + colaboración cross-team

💼 Conseguir trabajo

📦 Portfolio mínimo

  • 3 proyectos reales (no clones de tutoriales)
  • READMEs profesionales con screenshots
  • Deployados (Vercel / Netlify)
  • Lighthouse ≥ 85

📄 CV efectivo

  • 1 página, sin foto
  • Stack claro arriba
  • 3 proyectos con link y descripción breve
  • Métricas en lugar de "implementé features"
    ("reduje bundle 40%")

🎤 Interview prep

  • JS fundamentals (closures, event loop, this)
  • React patrones + hooks
  • CSS: specificity, box model, flex/grid
  • Algoritmos básicos (LeetCode Easy/Medium)
  • System design frontend

🌐 Dónde aplicar

  • LinkedIn — bulk OK
  • Wellfound — startups
  • GetOnBoard — LatAm
  • Turing / Toptal — remote premium

🔄 Mantenerse vigente

Hábitos diarios

  • Construí algo cada mes (aunque sea chico)
  • Leé 1 post técnico por día
  • Seguí 10 expertos en Twitter / Bluesky

Hábitos anuales

  • State of JS / State of CSS
  • Aprendé 1 framework nuevo (aunque no lo uses en prod)
  • Escribí 4 blog posts técnicos

⚠️ Errores comunes a evitar

1Saltear fundamentos por querer React desde el día 1
2Copiar y pegar sin entender
3No leer la documentación (MDN es oro)
4Obsesionarse con el "framework correcto" en vez de construir
5Tutorial hell: 100 cursos sin construir nada
6Ignorar accesibilidad hasta que un cliente la exija
7No hacer commits frecuentes
8"Tests cuando haya tiempo" (nunca hay tiempo)
9Optimizar antes de medir
10Pelearte con Git por no entender las bases (1 tarde lo arregla)

"Lo que distingue a un dev senior no es saber más cosas — es saber qué NO hacer y por qué."
