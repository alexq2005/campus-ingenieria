# Roadmap de aprendizaje — qué viene después

## ⏰ Línea del tiempo sugerida

```
  Mes 1 ─── Módulos 0–4 (Web, HTML, CSS)
  Mes 2 ─── Módulos 5–8 (JS vanilla completo)
  Mes 3 ─── Módulos 9–11 (tooling, React, TypeScript)
  Mes 4 ─── Módulo 12 + Proyecto final
  Mes 5 ─── Deploy, pulir portfolio, empezar a aplicar
```

No es obligatorio ir rápido. **Dominio > velocidad**.

---

## 🎯 Niveles de dominio

### Junior (0–1 año)
- [x] HTML/CSS/JS nativo fluido.
- [x] React + hooks.
- [x] TypeScript básico.
- [x] Git + GitHub.
- [x] 2–3 proyectos en portfolio.
- [x] Lighthouse ≥ 85 en tu proyecto.

### Semi-Senior (1–3 años)
- [ ] TypeScript avanzado (generics, utility types, mapped types).
- [ ] Next.js / Remix / SSR.
- [ ] Testing robusto (unit + integration + E2E).
- [ ] Performance profundo (profiler, flame graphs, budget).
- [ ] Accesibilidad avanzada (ARIA, lectores de pantalla).
- [ ] Diseño (saber hablar con diseñadores, Figma).
- [ ] Contribuir a open source.
- [ ] Tech blog propio.

### Senior (3+ años)
- [ ] Arquitectura de aplicaciones grandes.
- [ ] Design systems.
- [ ] Mentoría.
- [ ] Decisiones de stack con trade-offs claros.
- [ ] Performance budgets + monitoreo en producción.
- [ ] Security frontend (CSP, SRI, XSS, CSRF).
- [ ] Colaboración cross-team (backend, product, design).

## 💼 Conseguir trabajo

### Portfolio mínimo
- 3 proyectos reales (no clones).
- README profesionales.
- Deployados.
- Lighthouse pasable.

### CV
- 1 página.
- Stack claro arriba.
- 3 proyectos con link y descripción breve.
- Experiencia (si hay) con métricas (no "implementé features" sino "reduje bundle 40%").

### Interview prep
- JavaScript fundamentals (closures, event loop, this).
- React patrones + hooks.
- CSS: specificity, box model, flex/grid.
- Algoritmos básicos (LeetCode Easy/Medium si la empresa lo exige).
- System design frontend (scalable SPA, caché, estado).

### Libros para interview
- **Cracking the Coding Interview** — Gayle McDowell.
- **Frontend Interview Handbook** · https://www.frontendinterviewhandbook.com.

### Dónde aplicar
- **LinkedIn** — OK para bulk.
- **Lever / Greenhouse** — postulaciones directas a empresas.
- **Wellfound** (ex AngelList) — startups.
- **Turing, Toptal, Arc** — remote premium.
- **Cobuild, Laboral Kutxa, InclusionJS** (España) / **GetOnBoard** (LatAm).

## 🔥 Cómo mantenerte vigente en frontend

1. **Construí algo todos los meses**, aunque sea chiquito.
2. **Leé 1 post técnico por día** (newsletters ayudan).
3. **Mirá los State of JS/CSS anuales**.
4. **Seguí a 10 expertos en Twitter/X o BlueSky**.
5. **Aprendé 1 framework nuevo por año** (aunque no lo uses en prod).
6. **Escribí**: blog posts o documentación.

## 🎓 Certificaciones (opcional)

- **Google UX Design Certificate** (Coursera) — útil si querés entender diseño.
- **Google Mobile Web Specialist** (discontinuado pero su material es oro).
- **AWS / Azure / GCP** — cloud básico nunca sobra.

La realidad: **en frontend, el portfolio importa más que cualquier cert**.

---

## ⚠️ Errores comunes a evitar

1. **Saltear fundamentos** por querer React desde el día 1.
2. **Copiar + pegar** sin entender.
3. **No leer la documentación** (MDN es oro).
4. **Obsesionarse con el framework "correcto"** en vez de construir.
5. **Tutorial hell**: mirar 100 cursos sin construir nada.
6. **Ignorar accesibilidad** hasta que te lo exija un cliente.
7. **No hacer commits frecuentes**.
8. **No escribir tests** hasta "cuando haya tiempo" (nunca hay tiempo).
9. **Optimizar antes de medir**.
10. **Pelearte con Git por no entender las bases** (invertí 1 tarde en aprenderlo bien).
