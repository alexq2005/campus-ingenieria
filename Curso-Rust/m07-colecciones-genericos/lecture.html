Módulo 07 — Colecciones & Genéricos

Hasta acá manejaste valores sueltos. Ahora vas a guardar muchos datos juntos con las colecciones del standard library: Vec (listas), String (texto) y HashMap (mapas clave-valor). Y descubrís cómo escribir código que funciona para cualquier tipo con genéricos, la herramienta que hace que Vec<T> sirva tanto para enteros como para textos.

Vec<T>: el arreglo dinámico

💡 Un Vec es una lista que crece y se achica. A diferencia de un arreglo fijo ([i32; 3]), un Vec<T> vive en el heap y puede cambiar de tamaño en runtime. El <T> es el tipo de los elementos: Vec<i32> guarda enteros, Vec<String> guarda textos. Todos los elementos deben ser del mismo tipo.

La forma más cómoda de crearlo es con la macro vec!. Después agregás elementos con .push():

let mut numeros = vec![1, 2, 3];
numeros.push(4);
numeros.push(5);
// numeros ahora es [1, 2, 3, 4, 5]
📌 Para usar .push() el Vec debe ser mut. Modificar la colección es mutarla, y en Rust mutar exige let mut (igual que cualquier variable).

Dos formas de leer un elemento

Indexar directo con v[i] es rápido, pero entra en pánico (crashea el programa) si el índice no existe. La alternativa segura es .get(i), que devuelve un Option (lo viste en M04):

let v = vec![10, 20, 30];

let a = v[0];          // 10  — pánico si el índice no existe
let b = v.get(1);      // Some(&20)  — nunca crashea
let c = v.get(99);     // None      — fuera de rango, seguro

match v.get(99) {
    Some(valor) => println!("hay: {}", valor),
    None        => println!("no existe ese índice"),
}

Para recorrer todos los elementos, usás for:

let v = vec![10, 20, 30];
for n in &v {
    println!("{}", n);
}
¿Por qué &v y no v? Iterar sobre &v presta el vector (lo lee sin consumirlo), así que después del for seguís pudiendo usar v. Iterar sobre v directo lo mueve y lo consume (ownership, M03).

String vs &str: dos formas de texto

Rust tiene dos tipos de texto y al principio confunde. La distinción es la misma idea de ownership: uno es dueño, el otro presta.

TipoQué esDueño del datoCrece/cambia
StringTexto UTF-8 en el heapSí (owned)Sí, es mutable
&strUna "vista" (slice) a un textoNo (prestado)No, solo lectura
🔗 Analogía: String es tu libro — lo tenés, podés escribir en él, agregar páginas. &str es una foto de una página de ese libro — la podés leer, pero no es tuya y no la podés modificar. Los literales que escribís entre comillas ("hola") son &str. 
let saludo: &str = "hola";          // literal → &str
let mut nombre: String = String::from("Ada");  // owned, mutable

nombre.push_str(" Lovelace");      // String puede crecer
// nombre ahora es "Ada Lovelace"

// Conversiones entre los dos:
let s: String = "texto".to_string();   // &str → String
let r: &str = &nombre;                 // String → &str (lo presta)
✅ Regla práctica: en los parámetros de una función pedí &str (acepta ambos y no te apropiás del dato); cuando necesitás guardar o construir texto, usá String.

HashMap<K, V>: clave → valor

💡 Un HashMap<K, V> asocia claves con valores. Como un diccionario de Python o un objeto de JS: buscás por la clave (K) y obtenés el valor (V). Las búsquedas son rapidísimas (tiempo constante promedio) sin importar cuántos elementos haya.

No viene en el prelude, así que hay que importarlo. Agregás pares con .insert() y leés con .get():

use std::collections::HashMap;

let mut edades: HashMap<String, i32> = HashMap::new();
edades.insert(String::from("Ada"), 36);
edades.insert(String::from("Alan"), 41);

// .get(&k) devuelve Option<&V>: Some si existe la clave, None si no
let e = edades.get("Ada");        // Some(&36)
let x = edades.get("Grace");      // None

match edades.get("Ada") {
    Some(edad) => println!("Ada tiene {}", edad),
    None        => println!("no está en el mapa"),
}
📌 .get(&k) siempre devuelve Option<&V>. El Option te obliga a manejar el caso "la clave no existe" — no podés ignorar que una búsqueda puede fallar. El &V significa que te presta una referencia al valor, no te lo entrega.

Genéricos: código para cualquier tipo

¿Notaste el <T> en Vec<T>? Eso es un genérico: un "hueco" para un tipo que se decide más tarde. Gracias a los genéricos, los autores de la stdlib escribieron Vec una sola vez y vos lo usás con cualquier tipo.

Vos también podés escribir funciones genéricas. Imaginá querer "el mayor de dos valores" para enteros, decimales, textos… sin repetir la función:

fn mayor<T: PartialOrd>(a: T, b: T) -> T {
    if a > b { a } else { b }
}

fn main() {
    println!("{}", mayor(3, 7));          // funciona con i32 → 7
    println!("{}", mayor(2.5, 1.1));      // funciona con f64 → 2.5
    println!("{}", mayor("abc", "xyz"));  // funciona con &str → xyz
}
Leelo así: fn mayor<T: PartialOrd>(a: T, b: T) -> T dice "para algún tipo T que se pueda ordenar, recibí dos T y devolveme un T". El <T> después del nombre declara el tipo genérico.

Structs genéricos

Los struct (M05) también aceptan genéricos. Un Par<T> guarda dos valores del mismo tipo, sea cual sea:

struct Par<T> {
    a: T,
    b: T,
}

fn main() {
    let enteros = Par { a: 1, b: 2 };           // Par<i32>
    let textos  = Par { a: "hola", b: "chau" }; // Par<&str>
    println!("{} {}", enteros.a, textos.b);
}

Trait bounds: poner condiciones al genérico

💡 Un trait bound restringe qué tipos se permiten. En <T: PartialOrd>, el : PartialOrd exige que T sea un tipo comparable con > y <. Sin ese bound, Rust no te deja escribir a > b: no todos los tipos saben compararse. El bound es una promesa que el compilador verifica.

Vas a ver bounds comunes como Clone (se puede copiar), Debug (se puede imprimir con {:?}) o PartialOrd (se puede ordenar). Los traits se profundizan en el M08 — por ahora alcanza con saber que un bound dice "este genérico tiene que saber hacer X".

⚠️ El bound no es opcional cuando usás la capacidad. Si dentro de la función comparás (>), sumás (+) o clonás (.clone()) un valor genérico T, tenés que declarar el bound correspondiente — si no, el código no compila.

Iteradores: recorrer con estilo

Los iteradores son la forma idiomática de transformar colecciones en Rust. En vez de un for con índices, encadenás operaciones declarativas:

let numeros = vec![1, 2, 3, 4, 5, 6];

let pares_x10: Vec<i32> = numeros
    .iter()                       // recorre prestando cada elemento
    .filter(|n| *n % 2 == 0)      // quedate solo con los pares
    .map(|n| n * 10)              // multiplicá cada uno por 10
    .collect();                   // junta el resultado en un Vec

// pares_x10 == [20, 40, 60]
Lazy de verdad: los iteradores no hacen nada hasta que algo los consume. .filter() y .map() solo describen el plan; recién .collect() (o un for) lo ejecuta. Eso los hace eficientes: no se crean listas intermedias innecesarias.
MétodoQué hace
.iter()Crea un iterador que presta cada elemento
.map(|x| ...)Transforma cada elemento
.filter(|x| ...)Deja pasar solo los que cumplen la condición
.collect()Junta el resultado en una colección (Vec, String, etc.)

Errores típicos al empezar

Indexar un Vec fuera de rango. v[99] en un vector de 3 elementos hace que el programa entre en pánico y crashee. Si no estás seguro de que el índice existe, usá .get(99), que devuelve None en vez de explotar.
Olvidar el trait bound. Escribir fn mayor<T>(a: T, b: T) y dentro hacer a > b no compila: faltó <T: PartialOrd>. El compilador no asume que cualquier T sabe compararse.
Mezclar String y &str sin convertir. Pasar un String donde se espera &str (o viceversa) sin & o .to_string() da error de tipos. Recordá: &mi_string lo convierte a &str; "x".to_string() lo convierte a String.
🚨 El pánico por índice no se atrapa con Option. v[i] y v.get(i) son mundos distintos: el primero aborta, el segundo te da un Option para manejar a mano. En código robusto, preferí siempre .get() sobre la indexación cuando el índice viene de afuera (input del usuario, longitud variable, etc.).

Checkpoint — ¿lo tenés claro?

¿Cuál es la diferencia entre v[i] y v.get(i) en un Vec?

v[i] devuelve el valor directo pero entra en pánico (crashea) si el índice no existe. v.get(i) devuelve un Option: Some(&valor) si existe, None si está fuera de rango — nunca crashea.

¿Qué devuelve hashmap.get(&clave) y por qué?

Devuelve Option<&V>: Some(&valor) si la clave existe, None si no. Es un Option porque la clave podría no estar, y Rust te obliga a manejar ese caso en vez de asumir que siempre está.

En fn mayor<T: PartialOrd>(...), ¿para qué sirve : PartialOrd?

Es un trait bound: restringe T a tipos que se pueden ordenar (comparar con > y <). Sin ese bound, el compilador no permite hacer a > b porque no todos los tipos saben compararse.

Ejercicios

  1. Creá un let mut v = vec![1, 2, 3];, hacé v.push(4) e imprimí cada elemento con un for n in &v.
  2. Usá v.get(10) sobre ese vector y manejá el resultado con un match que imprima "no existe" en el caso None.
  3. Creá un HashMap<String, i32> con tres pares (nombre → puntaje). Buscá uno que exista y uno que no, e imprimí el resultado de cada .get().
  4. Escribí una función genérica fn menor<T: PartialOrd>(a: T, b: T) -> T que devuelva el menor de dos valores, y probala con enteros y con &str.
  5. Partiendo de vec![1, 2, 3, 4, 5], usá .iter().filter(...).map(...).collect() para obtener un Vec<i32> con los impares multiplicados por 100.
