Módulo 01 — NumPy para Datos

Antes de tocar pandas, sklearn o PyTorch necesitás dominar la pieza que los sostiene a todos: NumPy. Un DataFrame de pandas es, por dentro, arrays de NumPy. Un modelo de sklearn recibe arrays de NumPy. Un tensor de PyTorch es la versión "con GPU" de un array de NumPy. Este módulo es el puente: vemos NumPy desde la óptica de datos, con la mentalidad que vas a usar el resto del curso.

Si querés la referencia completa y exhaustiva de NumPy (todos los métodos, casos borde, etc.), está en el Módulo 14 del Curso de Python. Acá nos enfocamos en lo que realmente usás para analizar datos y entrenar modelos.

¿Por qué NumPy y no una lista?

Python ya tiene listas. ¿Por qué inventar otra cosa? Porque para datos numéricos las listas son lentas y verbosas. Mirá la diferencia:

# Sumar dos "vectores" con listas de Python
a = [1, 2, 3, 4]
b = [10, 20, 30, 40]
c = [a[i] + b[i] for i in range(len(a))]   # bucle a mano

# Lo mismo con NumPy
import numpy as np
a = np.array([1, 2, 3, 4])
b = np.array([10, 20, 30, 40])
c = a + b                                   # [11 22 33 44] — sin bucle
💡 Dos diferencias clave. Una lista de Python guarda punteros a objetos dispersos en memoria. Un array de NumPy guarda los números contiguos (uno al lado del otro, mismo tipo). Eso permite la vectorización: la operación a + b corre en C optimizado sobre todo el bloque de memoria, sin el bucle interpretado de Python. Resultado: 10–100× más rápido y mucho menos código.

📌 Pensar vectorizado. La regla mental de NumPy: si te encontrás escribiendo un for para recorrer un array número por número, casi siempre hay una forma de expresarlo como una operación sobre todo el array de una. Eso es "pensar vectorizado", y es la base de escribir código de datos rápido y legible.

Crear arrays

Hay varias formas de fabricar un array, según de dónde salgan los datos:

import numpy as np

np.array([1, 2, 3])            # desde una lista -> [1 2 3]
np.zeros(5)                    # [0. 0. 0. 0. 0.]  (cinco ceros, float)
np.ones((2, 3))               # matriz 2x3 de unos
np.arange(0, 10, 2)           # [0 2 4 6 8]  (como range, pero array)
np.linspace(0, 1, 5)          # [0. 0.25 0.5 0.75 1.] -> 5 puntos equiespaciados

Cada array tiene dos atributos que vas a mirar todo el tiempo:

x = np.array([[1, 2, 3],
              [4, 5, 6]])

x.dtype     # dtype('int64')  -> el tipo de los elementos
x.shape     # (2, 3)          -> 2 filas, 3 columnas
x.ndim      # 2               -> cantidad de dimensiones
El dtype importa para datos: int64, float64 y bool son los que más vas a ver. Las operaciones de ML casi siempre trabajan en float64 (o float32 en deep learning). Podés forzarlo: np.array([1, 2, 3], dtype=np.float64).

shape, reshape y el truco del -1

La forma (shape) es la estructura del array. reshape reorganiza los mismos datos en otra forma (sin copiarlos):

x = np.arange(12)        # [0 1 2 ... 11], shape (12,)
x.reshape(3, 4)          # matriz 3x4
x.reshape(2, 6)          # matriz 2x6 (mismos 12 datos)

# El truco -1: "calculá vos esta dimensión"
x.reshape(3, -1)         # 3 filas, NumPy deduce 4 columnas
x.reshape(-1, 2)         # 2 columnas, NumPy deduce 6 filas
💡 (n,) NO es lo mismo que (n,1). Un array de shape (5,) es un vector 1D (una fila sin estructura de columna). Un array (5, 1) es una matriz columna 2D. Muchos modelos de sklearn esperan una de las dos en concreto, y mezclarlas tira errores de dimensión. El -1 es tu amigo para convertir: x.reshape(-1, 1) pasa un vector a columna. 
v = np.array([1, 2, 3, 4, 5])
v.shape                  # (5,)    -> vector 1D
col = v.reshape(-1, 1)
col.shape                # (5, 1)  -> matriz columna (una feature)

Operaciones vectorizadas y broadcasting

Las operaciones aritméticas se aplican elemento a elemento, sin bucles:

x = np.array([1, 2, 3, 4])

x * 2          # [2 4 6 8]      -> escalar a todos
x ** 2         # [1 4 9 16]     -> al cuadrado
x + x          # [2 4 6 8]      -> elemento a elemento
np.sqrt(x)     # raíz de cada uno

El broadcasting es la regla que permite operar arrays de formas distintas: NumPy "estira" el más chico para que calce con el más grande, sin copiar memoria.

M = np.array([[1, 2, 3],
              [4, 5, 6]])      # shape (2, 3)

M + 100                        # suma 100 a TODOS (escalar sobre matriz)

fila = np.array([10, 20, 30])  # shape (3,)
M + fila                       # suma la fila a CADA fila de M
# [[11 22 33]
#  [14 25 36]]
🔍 Broadcasting es como repartir una promo. Si la tienda dice "10% off a todo", no escribís el descuento producto por producto: la regla se "transmite" (broadcast) a toda la lista de precios de una. NumPy hace lo mismo con el escalar 100 o la fila: la propaga sobre toda la matriz.

Indexado y máscaras booleanas — filtrar datos

Acá NumPy se vuelve una herramienta de datos de verdad. El indexado básico es como en listas, pero podés usar condiciones para filtrar:

x = np.array([-3, 5, -1, 8, 0, -7, 2])

# Una condición devuelve un array de booleanos (la "máscara")
x > 0          # [False True False True False False True]

# Usar la máscara para FILTRAR: te quedás solo con los que cumplen
x[x > 0]       # [5 8 2]

# Combinar condiciones con & (and) y | (or) -> paréntesis SIEMPRE
x[(x > 0) & (x < 6)]    # [5 2]

Truco frecuente: convertir una máscara booleana en 0/1 con astype(int) (clave para crear etiquetas o features binarias):

(x > 0).astype(int)    # [0 1 0 1 0 0 1]  -> 1 donde es positivo
📌 Con máscaras nunca usás un bucle para filtrar. En vez de recorrer fila por fila preguntando "¿es positivo?", construís la condición sobre todo el array y dejás que NumPy lo resuelva. Es el patrón que pandas hereda: df[df["edad"] > 18] es exactamente esta idea.

Reducciones con axis — resumir datos

Las reducciones colapsan muchos números en uno (o en una fila/columna): mean, sum, std, max, min. Lo importante para datos es el parámetro axis, que decide en qué dirección reducir.

M = np.array([[1, 2, 3],
              [4, 5, 6]])      # 2 filas, 3 columnas

M.sum()            # 21         -> todo el array
M.sum(axis=0)      # [5 7 9]    -> suma POR COLUMNA (colapsa filas)
M.sum(axis=1)      # [6 15]     -> suma POR FILA (colapsa columnas)

M.mean(axis=0)     # promedio de cada columna
M.std(axis=0)      # desvío de cada columna
M.max(axis=1)      # máximo de cada fila
💡 Regla del axis. axis=0 reduce a lo largo de las filas -> te queda un resultado por columna. axis=1 reduce a lo largo de las columnas -> un resultado por fila. En una tabla de datos donde las columnas son features y las filas son muestras, axis=0 es "estadística de cada feature" (lo que casi siempre querés).

El producto matricial @ — el corazón del ML

En ML, una predicción lineal se escribe como X @ W: la matriz de datos X por el vector de pesos W. El operador @ es el producto matricial (no confundir con *, que multiplica elemento a elemento).

X = np.array([[1, 2],
              [3, 4],
              [5, 6]])         # 3 muestras, 2 features -> shape (3, 2)
W = np.array([0.5, 2.0])       # un peso por feature   -> shape (2,)

X @ W          # [4.5 9.5 14.5]  -> una predicción por muestra (shape (3,))

# OJO: * NO es lo mismo
X * 2          # multiplica cada elemento por 2 (broadcasting), NO es producto matricial
Para que A @ B funcione, las dimensiones internas deben coincidir: (3, 2) @ (2,) -> (3,). La columna de A (2) tiene que igualar la fila de B (2). Si no calzan, NumPy tira ValueError: matmul: .... Verificar shapes antes de un @ te ahorra el 90% de esos errores.

Ejemplo completo: normalizar de forma vectorizada

Normalizar (o "estandarizar") es uno de los pasos más comunes antes de entrenar un modelo: a cada feature le restás su media y la dividís por su desvío, para que todas queden en la misma escala. Vectorizado, son dos líneas — y el broadcasting + el axis=0 hacen toda la magia:

import numpy as np

# 4 muestras, 2 features (columnas en escalas muy distintas)
X = np.array([[ 50, 0.5],
              [ 60, 0.7],
              [ 80, 0.2],
              [ 90, 0.6]])

mu    = X.mean(axis=0)   # media de cada columna   -> shape (2,)
sigma = X.std(axis=0)    # desvío de cada columna   -> shape (2,)

X_norm = (X - mu) / sigma   # broadcasting: (4,2) - (2,) / (2,)

# Verificación: cada columna queda con media ~0 y desvío ~1
X_norm.mean(axis=0)    # ~[0. 0.]
X_norm.std(axis=0)     # ~[1. 1.]
🔍 Por qué importa. Sin normalizar, una feature que va de 50 a 90 "pesa" muchísimo más que otra que va de 0.2 a 0.7, solo por su escala. El modelo se obsesiona con la grande. Normalizar pone a todas las features a competir en igualdad de condiciones.

Errores típicos

Escribir bucles de Python en vez de vectorizar. for i in range(len(x)): y[i] = x[i] * 2 es lento y verboso. Es y = x * 2. Si ves un for sobre un array, frená y pensá vectorizado.
Confundir (n,) con (n, 1). Un vector 1D y una matriz columna no son intercambiables: muchos modelos de sklearn esperan una forma específica y tiran error de dimensión. Usá reshape(-1, 1) para pasar de vector a columna.
Usar * cuando querías @. X * W multiplica elemento a elemento (con broadcasting); X @ W es el producto matricial. En ML casi siempre querés @. Confundirlos da resultados numéricos que "parecen" válidos pero están mal.

Checkpoint — ¿lo tenés claro?

¿Por qué un array de NumPy es más rápido que una lista para cálculo numérico?

Porque guarda los datos contiguos en memoria y de un solo tipo (dtype homogéneo), lo que permite vectorizar: la operación corre en C optimizado sobre todo el bloque, sin el bucle interpretado de Python.

¿Qué diferencia hay entre axis=0 y axis=1 en una reducción?

axis=0 reduce a lo largo de las filas y deja un resultado por columna (estadística de cada feature). axis=1 reduce a lo largo de las columnas y deja un resultado por fila (resumen de cada muestra).

¿Cuál es la diferencia entre X * W y X @ W?

* multiplica elemento a elemento (usando broadcasting si hace falta). @ es el producto matricial, que combina filas y columnas según el álgebra lineal. En ML, la predicción lineal X @ W usa @.
